| 维度 | v0.2 状态 | v0.3 状态 |
|---|---|---|
| **界域（Domain）** | 无此概念 | 新增。战场三层（上层界域 / 底层界域 / 现实基底）+ 六范式操作牌，见 §10 |
| **位格（Rank）** | §3 判定"序列 2 以上不搬" | **解禁**。位格成为独立核心数值，高阶能力有了非数值的落地方式，见 §11 |
| **战斗级规则改写** | §9 🔴 不立项 | **解禁**（界域的环境规则就是它的落地形态），改以"界域"而非"通用规则开关"实现，见 §9 |
| **性别（Gender）** | 无 | 新增。角色属性（战外养成决定、战斗内不可变），见 §12 |
| **吟唱（cast_time）** | 仅"免吟唱"状态存在 | 提升为**每张卡的显性字段**，低阶默认 0，见 §13 |

### 1.3 触发点（**取值域封闭，共 12 个**）

定义见 `../ddd/params/执行参数.md` §2.1：

`on_apply` / `on_remove` / `on_tick` / `on_turn_start` / `on_battle_start` / `on_spawn` / `on_death` / `on_kill` / `on_attack` / `on_take_damage` / `on_deal_damage` / `on_active_skill`

三条易错纪律：

- ⚠️ `on_spawn` 会在召唤物 / 增援登场时**重复 fire**，绝不能当"开局"用。凡"战斗开始时生效"一律用 `on_battle_start`。
- ⚠️ `on_kill` 与 `on_death` **接收方不同**：`on_kill` fire 给**击杀者**，`on_death` fire 给**持有该被动的单位**（并支持全局监听）。击杀触发用 `on_kill`，不要用 `on_deal_damage` 凑（见 §7 G2）。
- ⚠️ `on_attack` 与 `on_active_skill` 的分工：普攻只 fire `on_attack`；非攻击主动技能只 fire `on_active_skill`；**攻击类主动技能两者都 fire**。需要「任何主动行为」语义的订阅方要同时挂两者（见 §7 裁决变更）。

## 2. 数值经济（所有定价都先折成这个单位）

| 锚点 | 值 |
|---|---|
| 技能伤害基准 | 1.2 × 能量 |
| 标准单体技能 | 3 能量 → 5 伤害（火球术锚点） |
| 能量上限 / 恢复 | 50 / (0.2+0.2×智力) per tick |
| 生命上限 | 30 + 10×力量（力量3 = 60 血） |
| 单卡纪律 | 攻防 ±1~±2、护甲 5 一档、抗性 ±10~±20% |
| 一张卡预算 | ≈ 3 能量 ≈ 6 伤害 ≈ 10% 最大生命 |

> 规则：一张卡预算 ≈ 3 能量。伤害技能按"能量 × 1.2"折算；位移/控制/资源类技能要压低直伤，因为位移在「双路各 4 格 + 坍缩 + 插队」的战场里本身就是硬资源。
> 拿不准的定价一律打 ⚠️ 并在「本稿遗留」里列出。

### 3.0 ⚠️ 关于"随机"的正确口径（务必先读）

**旧版 brief 写过"引擎确定性 → 禁止效果里写概率"，这个说法是错的，不要照它执行。**

引擎**确实支持概率**，且有完整治理（规则 R1–R6 见 `../ddd/contexts/随机性治理.md`）：

- 随机源可播种、可快照 / 恢复；治理规则 R1–R6 齐备。
- 可复现契约是 **结果 = f(初始状态, 输入序列, seed)** —— 是"**可播种、可复现**"，**不是"禁止随机"**。
- **R3 登记制**：引入概率的效果必须能被随机用量登记筛出，便于平衡审计一键定位。

**正确写法**——概率是 EffectRef 上的 **`condition`**，不是独立算子：

```ts
// ✅ 正确
{ ref: 'gain_energy_2', condition: { kind: 'chance', p: 0.3 } }

// ❌ 错误：不存在 Chance() 这个算子
`Chance(0.3)` → `modify_resource(energy, +2)`
```

**使用约束**：
- **R3 登记**：引入概率的效果必须可被筛出，便于单独评审。
- **R4 单次抽样**：随机源只在生效条件判定处读取一次，禁止在结算链内部二次抽样。
- **R5 用途限制**：概率只用于**非伤害维度**（是否附加状态、是否给能量这类"添头"），不要用来决定伤害数值本身。
- **目标选择禁止引入随机**（R1/R5）：候选池过滤与排序必须是确定性的。想表达"概率性落空/阻挡"一律改用 **charges 次数型状态**的确定性写法——2026-09-04 已按此裁决改写全稿，**R5 不开例外**（见 §7 裁决变更）。
- **命运/预知主题例外**：这类主题优先翻译成节奏（`gauge.current`）而非概率，因为"命运"的玩法体感是抢先出手，不是掷骰子。

## 3. 诡秘 → 卡牌 翻译规则（搬运前先定，否则会硬搬出"全知全能"）

| 原著能力类型 | 卡牌里的翻译 | 依据 |
|---|---|---|
| 信息/占卜/预知 | → 资源前置或节奏提前（energy / gauge.current） | 无隐藏信息，信息本身不值钱 |
| 命运/概率 | → `modify_resource(gauge.*)`（抢先/推后出手） | "命运"体感 = 谁先出手、多久出手一次。**不要用概率去表达"命运"**——命运主题应落在节奏上，而非掷骰子 |
| 欺骗/伪装/反占卜 | → `dispel` 或 `target_override` | 没对手心理可骗，只有状态和目标系统可操作 |
| 复活/历史/召唤 | → `heal` + `spawn` + 亡语 | 语义天然贴合，零新机制 |
| 位格碾压（序列 2 以上） | **v0.3 解禁** → 界域环境规则 / 规则改写 / 拉入·放逐·置换 | v0.2 判"不搬"是因为九原语里无处安放，只能退化成数值。v0.3 有了位格与界域：序列 2+ 的能力落到**改写全场规则**（神国雏形、非凡能力凋零）或**跨层操作**（拉入/放逐/置换），这才是原著里高序列的实质。见 §10、§11 |
| 跨层操作（拉入 / 放逐 / 置换 / 潜入） | → 界域六范式操作牌 | 原著里"场景切换"本就是战斗内行为，不是背景设定。见 §10.3 |
| 仪式 / 咒文 | → `cast_time` 吟唱字段（可被"免吟唱"免除、可被控制打断） | 原著中高序列能力与仪式魔法都需要吟唱，见 §13 |
| 治疗/净化/光明 | → `heal` / `dispel(buff on enemy)` / `mount_status(shield/fortify)` | 直接用现有原语 |
| 诅咒/痛苦/负面 | → `mount_status(vulnerable/poison/burn)` 或自定义 debuff 状态 | 优先复用已有状态，缺的才新增 |

## 4. 文档结构（严格对齐 `愚者途径_技能池_v0.2.md`）

1. **标题** `# <途径中文名>途径 · 技能池 v0.2`
2. **头部说明**：灵感源（ima 途径数据）、框架依据；加一行说明「文案」= 玩家视角效果描述，用于肉鸽派发展示。
3. **〇、肉鸽化前提**：照搬槽位/派发/共享/稀有度表；**定义本途径的 4 条构筑轴**（命名用炼金/元素符号 🜁🜂🜃🜄 或自创，配关键词 + 玩法）。每条途径的 4 轴要能覆盖它 10 个序列的能力谱系。
4. **一、技能池**：按稀有度分组（普通/精良/稀有/史诗/传说）。每个技能：
   - `#### 【主动/被动】<技能名> <轴符号>`
   - `- **文案** <玩家视角，1-2 句，有 flavor>`
   - `- **序列** <序列号 职业名> · **能量 X / cd Y / 吟唱 Z** · <reach/targetSpec>`（被动写 `hook`）
   - `- **效果** <原语表达>`
   - `- **推导/语义** <为什么这么映射、绑定了哪个数值锚点>`
   - **v0.3 新增的三个可选字段**（有则写，无则省略，不要为凑字段硬写）：
     - `- **吟唱** <Z tick>` —— **序列 7–5 的即时技能默认 0（瞬发），不标**；序列 4 以上或仪式类技能必须标。见 §13
     - `- **性别** <男 / 女 / 不限>` —— 只在本途径存在性别约束时标（默认不限）。见 §12
     - `- **界域标签** <标签>` —— 如 `镜像` `亡灵` `灵体系` `火焰` `光/净化`，用于界域交互。见 §10.5
   - 需要框架扩展处打 ⚠️ 并注明对应改动记录编号（A1/A2/C1…），**编号含义查本文档 §7**
   - 每条轴挑 1 个 ★ 旗舰技能
   - **总量约 24 个**（每个稀有度档都有，4 轴尽量均衡）
   - **v0.3 新增：本途径的 1–2 张主题界域牌**，占在上述总量内（不是额外加）。写法见 §10.4
5. **二、示例 Build**：4 个 Build（各 4 主动 + 4 被动），用本途径技能，体现 4 轴。
6. **三、跨途径共享**：列本途径哪些技能 `sharedAcross` 给哪些相邻途径（用源数据里的 `adjacent_pathways`），及理由。
7. **四、本稿遗留**：数值盲区、待标项。
8. **本途径框架改动（新增）**：**只列本途径特有的**新状态 / 新单位 / 新算子 / 新 move.op / 新 targetSpec。格式同改动记录（状态 🔴🟡🟢 + 说明 + 服务于哪个技能）。**不要重复**已登记的通用项 —— 通用项编号（A1–A4、B1–B7、C1–C8、D1–D5、E1–E4、F1–F63、G1–G15）的现落点**全部见本文档 §7**，直接引用，勿重立。

## 5. 质量红线

- 不写"全知全能""操纵因果于无形"这类无法落地的描述词进「效果」——那是 flavor，不是机制。
- 「文案」可以华丽，「效果」必须能映射到 1.1 的十一原语。
- 数值先换算成"能量/伤害/生命%"再写，别凭感觉。
- 每条新增状态必须说清：`damage_taken_mul` / `damage_mul` / `duration` / 触发事件 / 作用于谁。
- 用中文，简洁，有 flavor。

## 10. 界域系统（Domain）· v0.3 新增

> 依据：`docs/诡秘之主-界域系统-场景切换机制设计.md` v0.1 + `docs/诡秘之主-世界体系素材库.md` v0.1。
> 设计信条：**别自创机制**——原著已经把"战斗内切换场景"写成了六种范式，并附送了位格、时长、范围、次数、风险五套现成参数。我们的工作是把它们翻译成卡面。

### 10.1 战场三层结构

```
┌─ 上层界域（Active Domain）── 由卡牌打出，压制栈：后打出者压顶，仅栈顶生效，其余压制不删除
├─ 英雄域（Hero Domain）    ── 英雄被动开局挂载的常驻域，规则冲突优先级高于上层
├─ 底层界域（Base Domain）  ── 由塔层 / Boss 决定，战斗开始即确定，通常不可移除
└─ 现实基底                ── 永远存在（原著：灵界与现实"完全重叠"）
```

> ✅ 已落 ddd（2026-09-06）：三层 tier + 压制栈语义，见 `../ddd/contexts/战场上下文.md` §二/§六（INV-B9–B11）。

- **上层界域压制栈**：后打出者压顶，栈顶到期/被驱散后前者的剩余时长恢复生效——驱散界域因此有战术意义；任何时刻只有一套规则生效，无叠加爆炸，也符合"让目标周围区域改变"。
- **底层不可轻易移除**：保证塔层难度递进不被一张牌抹平。但**置换**类卡（范式④）可以把它和上层对换——这就是高阶卡的价值。
- **叠加而非替换**：因为现实基底恒在，切换界域**不会清空战场**。已存在的单位、状态、Zone 全部保留，只是换了"规则环境"。这一点很重要——它让界域切换是"环境改造"而非"重开一局"。

### 10.2 界域卡的三个字段

| 字段 | 作用 | 写法要求 |
|---|---|---|
| **环境规则** | 被动，对全场单位持续生效 | **必须双向**：既强化一方也削弱一方（或双方同受影响）。单向增益的界域会变成无脑起手牌 |
| **交互规则** | 只影响带特定**标签**的卡（深度来源） | 标在本途径技能的「界域标签」字段上，见 10.5 |
| **持续** | 回合数 / 直到被覆盖 / 直到满足某条件 | 建议 2–4 回合 |

**双向性示例**（照抄界域文档的原设计，别改）：
- 「黑夜」：我方暗影/睡眠 +50%，**我方光/火 -25%**
- 「幻境」：敌方无法查看我方手牌，但**我方攻击 20% 落空**（因为是幻象）
- 「深渊化」：全场每回合 2 点无视护甲腐蚀，**替身类能力失效**（原著明确克制）

### 10.3 六范式操作牌（原著已写好，直接归类）

| 范式 | 定义 | 原著出处 | 落到原语 |
|---|---|---|---|
| ① **降临** | 让场景覆盖当前区域 | 旅法师序列2、神之画卷 | `domain(op: overlay)` ✅ 已落 ddd |
| ② **拉入** | 把目标拖进另一个世界 | 不老魔女序列3、织梦人序列3、梦魇序列7 | `translocate(op: pull_into)`：目标 detached N 回合 ✅ 已落 ddd |
| ③ **放逐** | 丢进随机时空乱流，一段时间后回归 | 秘法师序列4（原著 20 秒） | `translocate(op: banish, returnPayload)`：detached + 回归时结算载荷 ✅ 已落 ddd |
| ④ **置换** | 当前区域与另一空间对换 | 旧日之盒第一层、末日魔女序列1 | `domain(op: swap)`：上下层界域对换 ✅ 已落 ddd |

**为什么这六种足够**：覆盖了"切换"的全部语义方向——改环境（①）、移走敌人（②③）、换掉战场（④）、造分身（⑤）、躲自己（⑥）。任何新卡都能归进其中一类，系统不会膨胀失控。

**选题原则**：从本途径的**权柄**出发，找原著里对应的"领域 / 世界 / 场景"类能力。几乎每条途径都有——例如：

| 刺客（痛苦魔女） | 镜像迷宫 | 序列5 |
| 罪犯（恶魔） | 深渊化 | 序列6「堕落」 |
| 不眠者（守夜人） | 黑夜领域 | 序列4 |
| 歌颂者（无暗者） | 无暗之域 | 序列4 |
| 愚者（魔术师） | 幻境 | 序列7「制造幻觉」 |

**写在技能池里的格式**（沿用原技能条目，多两个字段）：

```
#### 【主动】晨曦领域 🜁
- **文案** <玩家视角>
- **序列** 6 黎明骑士 · **能量 1 / cd - / 吟唱 0** · 全场

- **效果** <原语表达>
- **推导/语义** <绑定了哪个数值锚点>
```

**低序列就要有界域**：原著里领域类能力本就低（晨曦领域序列6、满月序列5、镜像迷宫序列5、深渊化序列6）。早介入才能让玩家从第一层就学会用场景。

### 10.6 迷失值（Lost）与锚（Anchor）——风险系统

界域切换很强，所以必须付租金。玩家的核心决策变成"我这局能切几次场"。

| 规则 | 效果 |
|---|---|
| 每打出 1 张界域牌（降临 / 置换） | 迷失 **+1** |
| 每打出 1 张拉入 / 放逐 / 投影 / 潜入牌 | 迷失 **+0.5**（向上取整累计） |
| 迷失 ≥ 3 | 每回合开始随机弃 1 张牌 |
| 迷失 ≥ 5 | 每回合开始 20% 概率「迷失」：本回合所有牌费用 +1 |
| 迷失 ≥ 8 | **失控**：本场战斗立即失败（或转为巨大惩罚，视难度） |
| 打出「现实世界」类回归牌 | 迷失清零，但本回合不能再次切换界域 |

**锚（Anchor）**：一类遗物/被动，提供锚点值抵消迷失积累（「锚 +2」= 迷失阈值提高 2 点）。原著依据：高位存在需要"锚"来保持自我。

> ⚠️ **归属说明**：迷失值是**战斗内**累积的资源（随 Combat 聚合生命周期），锚值来自**战外**遗物配置（作为 `CombatSetup` 的初始参数传入）。这张边界要守住，否则迷失会变成跨局累积的元进度，那就归 Progression 了。
>
> ✅ **内核落地（2026-09-06）**：迷失 = 每英雄 Pool（只增不减，清零靠回归牌 set 0），租金以显式 `modify_resource(lost, +N)` 段写在卡面；阈值档经 `thresholdTrigger` 挂 StatusDef 惩罚状态（见 `../ddd/params/编队参数.md` §2.5）。⚠️ 表中"弃牌 / 费用 +1"类惩罚在技能槽内核**无对应物**，落 catalog 时须转写为状态效果（如能量成本上升、行为受限）。

**反制牌必写**（没有反制的场景系统会变单向碾压）：回归现实（迷失清零）、镜扣（免疫切换的随机负面）、冰之护符（7 次切换不累积迷失）、乌拉摩丝之像（界域负面减半但持续 -1 回合）。

## 11. 位格（Rank）· v0.3 新增核心数值

> 原著依据："位格低于自身 → 强制生效且无察觉；位格高于或等于 → 取决于对方状态"。
> 原著几乎所有强制类能力都以位格为判定前提。把它从"角色等级"提升为**独立数值**，整套控制/拉入/放逐体系就有了统一约束，不必为每张卡单独写限制条件。

### 11.1 定义与取值

位格 = 序列基准 + 途径修正 + 遗物/界域临时修正

| 序列 | 位格基准 |
|---|---|
| 9 | 1 |
| 8 | 2 |
| 7 | 3 |
| 6 | 4 |
| 5 | 5 |
| 4 | 6 |
| 3 | 7 |
| 2 | 8 |
| 1 | 9 |
| 0 | 10 |

⚠️D 待定：途径修正表、遗物修正表（界域文档 §6 把这条列为"整个系统的地基，先定它"）。本轮技能稿**只写位格判定逻辑，不给具体修正值**。

### 11.2 判定规则（拉入 / 放逐 / 置换类卡统一走这条）

- `目标位格 < 施法者位格` → **必定生效**，且目标"不会有任何察觉"——不触发亡语、不触发反击、不触发敌方增益
- `目标位格 ≥ 施法者位格` → **成功率 = 基础值 + 状态修正**
  - 基础值 **40%**
  - 目标处于眩晕 / 冰冻 / 虚弱：**+35%**
  - 目标处于狂乱 / 失控：**+20%**
  - 目标为 Boss（位格 +2 以上）：**−20%**

> ⚠️ **与 §3.0 随机口径的冲突处理**：这条判定引入了概率（40% + 修正），看起来违反 R5"概率只用于非伤害维度"。但它判的是**控制是否生效**，不是伤害数值，符合 R5 的非伤害维度限制。
> 同时必须满足 **R3 登记制**（可被随机用量登记筛出）与 **R4 单次抽样**（只在判定处读一次随机源）。
> 另外**目标选择本身仍然禁止随机**（R1）——位格判定不改变"选谁"，只改变"选中的目标是否吃效果"。这条界线不能越。

**这条规则的价值**：把"为什么这张卡有时强有时废"用一个统一数值解释清楚，玩家能形成直觉，而不必记住每张卡的例外。

### 11.3 与稀有度的关系

界域持续回合数按稀有度分档（照抄原著时长数据换算）：

| 稀有度 | 界域持续 | 原著参照 |
|---|---|---|
| 普通 / 精良 | 2–3 回合 | 神降：序列5 仅 3 秒 |
| 稀有 | 3–4 回合 | 神降：圣者十几秒 |
| 史诗 | 4 回合 | 镜中世界 |
| 传说 | 2 回合（短而强） | 神国雏形；苍白世界 2 回合 |

## 12. 性别系统（Gender）· v0.3 新增

> 原著依据：魔女（刺客）途径是性别约束最突出的途径——**序列 7「女巫」**的能力原文即"**男性变女性**，容貌魅力极大提升"；序列 6 欢愉"更加美丽"；序列 0 魔女握"女性"权柄。
>
> v0.2 的【女巫之形】曾标注"『男性变女性』在卡牌里没有性别维度，本版不假装能落地"——**v0.3 就是这个维度的解锁**。

### 12.1 定位：战外养成决定的角色属性

性别是**角色属性**。「性别转换」发生在**战外养成事件**中——如晋升序列：刺客途径晋升序列 7「女巫」时，男性角色转为女性（对应原著"男性变女性"）。**战斗内没有转换入口**，开战时性别已是既定事实（2026-09-07 拍板，取代 v0.3 初稿的"战斗内转换能力"方案）。

| 字段 | 取值 | 说明 |
|---|---|---|
| `gender` | `male` / `female` | 战外养成确定，作为 `CombatSetup` 初始参数传入；战斗内不可变 |

### 12.2 性别对技能的影响（两条用法，按优先级）

1. **可得性约束**（最常见）：部分技能标注 `**性别** 女`，男性角色在构筑/获取阶段即不可获得。
   - 典型：刺客途径序列 4 及以上的高位技能限女性——男性角色想走这条谱系，需在晋升序列 7 的战外事件中接受转换。这是一个**构筑拐点**，戏剧性留在爬塔层。
2. **效果差异**：同一技能，不同性别效果不同（如男性施放衰减），条件面走 `gender_is` 谓词。
   - 只在原著有明确依据时使用，不要为了用性别而用。

### 12.3 写法纪律

- **默认不限**：本途径若无原著性别依据，技能条目**不写**性别字段（不要为凑字段硬写）。
- **只在有必要约束时标**：绝大多数技能是"- **性别** 不限"或干脆省略。
- **技能稿不写转换过程**：转换是战外养成事件的叙事，技能稿至多在小注里点一句"晋升本序列即完成转换"，不做成卡面效果。
- ⚠️ 性别是**内容层**设定，不要让它污染 DDD 的核心战斗逻辑——在 DDD 里它只是 `Unit` 上的一个可选属性字段（见 §14）。

## 13. 吟唱时间（cast_time）· v0.3 提升为显性字段

> DDD 基础：`BehaviorModifier.op` 已有 `cast_time_set`（聚合规则"取最小"）；「免吟唱」状态已定义为 `cast_time_set: 0`，`defaultDuration: 5`。
> 参见 `../ddd/params/执行参数.md` §一、`../ddd/params/编队参数.md` §2.2。

### 13.1 口径

- **单位：tick**（与 `gauge` 同一时间尺度，不是回合）。
- **序列 7–5 的即时技能：默认 0（瞬发），不标。**
- **序列 4 以上、或明确是仪式/咒文类的技能：必须标具体 tick 数。**
- 吟唱期间技能处于"待发"状态，**可被控制效果打断**（眩晕/沉默/冰冻等带 `interrupt` 标志的状态，见 `../ddd/params/编队参数.md` §1.1b），打断则技能失效。⚠️ 退还能量诉求与内核铁律「打断只作废效果，不退资源——提交即承诺」**冲突，维持不退**；若未来要退需先推翻该已定项（⚠️D 搁置）。

### 13.2 与原著、与数值经济的对齐

| 项 | 口径 |
|---|---|
| 原著依据 | 高序列能力与仪式魔法都需要吟唱咒文；"免吟唱"是其对立面 |
| 数值补偿 | **有吟唱的技能，效果或数值应高于同费瞬发技能**——吟唱是成本，不是白扣。具体换算 ⚠️D 待定，建议先按"吟唱 N tick ≈ 折扣 0.5×N 能量"试算 |
| 与 `gauge` 的关系 | 吟唱推进的是"技能待发进度"，与行动条 `gauge` 是两条独立时间线，不要混用 |

### 13.3 写法

在技能条目的「序列」行里带上：`**能量 X / cd Y / 吟唱 Z**`。
- 瞬发（Z=0）时写 `吟唱 0` 或直接省略，**不要留空**。
- 「免吟唱」状态（`cast_time_set: 0`）与打断吟唱的控制技能，应在「推导/语义」里点明与本途径哪些技能形成联动。

**已拍板的硬问题（2026-09-06）**：
- 第 4 项：**新增第 10/11 原语**（`domain` + `translocate`）。塞进 `move` / `mount_status` 会污染 Placement 坐标语义（INV-B6）与驱散边界（INV-P7）——translocate 离场单位不持有坐标，界域是战场级无宿主实体。
- 第 2 项：界域为 **Battle 聚合内的独立实体**（`DomainInstance`，三件套），非挂在战场上的特殊状态——有独立生命周期（压制栈）与覆盖规则。

- 位格判定：**复合模型**——低于施法者必定生效（确定性）；不低于走 `Chance(基础 40% + 状态修正)`，R3 登记 / R4 单次抽样 / 目标选择零随机。
