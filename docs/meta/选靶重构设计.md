# 选靶重构设计（Targeting Refactor）

> 触发：用户在差异化重构收官后指出——「目标范围还是只有单体和群体。敌方单体让手动和过滤排序都几乎没意义，只能是敌方同一路的排首。敌方的默认基准位置就是同路排首，这时范围变成基准位置一整路，这样才有可能有筛选/排序/手动选择的意义。」
> 本文先**逐条核对现有选靶机制（schema + DDD 内核 + 全库数据实测）**，再给出重构设计，并把"选靶"作为**途径风格**维度记录。
> 状态：设计稿（未落地 JSON）。落地见 §5 迁移方案。

---

## 0. 结论速览

- 机制层（schema + DDD）**早已支持完整的车道级选靶**：`laneRef`(扫描路线) + `anchor`(排首) + `filter` + `sort` + `selectionMode` + `scope` + `spread`(溅射)。流水线在 I 节点跑完。
- **数据层几乎没用**：全库 832 卡，`laneRef` 显式使用 **0** 处；`damage.spread` 仅 **6** 处（全 `splash_adjacent`）；`filter` 仅 14 处、`sort` 仅 2 处；**303 张「敌方单体」卡全部 `manual`+`fallbackSort` 但候选池塌缩成排首 1 个**。
- 根因：`scope:single` 在现有卡面被**实现成"直接锁 1 个单位（排首）"**，而非"从池里选 1 个"。池只有 1 个，手动/排序/过滤自然空转。
- 重构核心一句话：**把"敌方单体"的候选池从「1 个排首」扩为「基准位置那一整路（lane）」，选举在路内发生；`scope:single`=从路内选 1，`scope:all`=路内全部，`spread`=从已定目标沿路/跨路扩散。**

## 1. 现有选靶机制核对（已逐条核对）

### 1.1 字段全集（来源：`docs/meta/SCHEMA.md` §4 + `docs/ddd/params/共享内核参数.md` §一）

卡面 `target` 结构：`{ selectionMode, request:{faction, scope, anchor, sort, filter, laneRef, excludeSelf}, fallbackSort, mode, pickCount }`

| 字段 | 取值域 | 作用 |
|---|---|---|
| `faction` | enemy / ally / self / self_or_ally / any / none | 阵营（any=不限阵营有目标；none=无目标，配合 scope:none） |
| `laneRef` | same_lane / cross_lane / all_lanes / auto | **扫描路线**：决定候选池覆盖哪条/哪些路 |
| `anchor` | front_line / self / cross_same_index / first_empty / taunt_source / self_faction_hp_desc / spawned_unit / empty_ally_slot / last_dead_ally / index_asc_same_faction / …（16 值） | **基准位置**：路内站位锚点，`front_line`=站位序号最小可锁定者（排首） |
| `scope` | single / all / none（权威口径，2026-09-20 裁定） | 选几个：single=1、all=池内全部、none=无 |
| `sort` | none / hp_asc / hp_desc / atk_asc / atk_desc / index_asc / energy_desc / buff_count_desc / `status:<id>:asc\|desc` / … | 候选排序键（参数化状态键族已落地） |
| `filter` | unitType / tags / hasStatus / hasCategory / hpPercent / isSummon / adjacency / … | 候选池过滤器（9 维 + 项目扩展） |
| `spread` | none / lane_line / splash_adjacent / splash_behind / cross_same_index | **溅射**：I-2 收缩后从已定主目标向外扩散 |
| `selectionMode` | manual / auto | 谁拍板最终目标（候选数 ≤ pickCount 时不触发玩家选择） |
| `fallbackSort` | 同 sort 取值域 | manual 必填（INV-E6），用于 AI/状态触发/超时兜底 |
| `mode` | unit / area | 点目标/区域目标（与 selectionMode 正交） |
| `pickCount` | int | 选多目标数量（schema 已建模，2026-09-20 回补） |

### 1.2 解析流水线（I 节点，来源：执行参数 §二 + 共享内核 §一）

```
① laneRef 预处理（auto → same_lane|all_lanes；纯函数，保持流水线前置）
② 候选池形成：faction × laneRef 交出的路 → 路内全部可锁定单位
③ 候选池过滤：filter（隐匿/不可锁定者被跳过，不占排首）
④ 锚点/排序：anchor 定位基准；sort 决定次序
⑤ 选举：selectionMode=manual 玩家拍板 / auto 按 fallbackSort 取最高优先 → committed target(s)
   （scope:single → pickCount=1；scope:all → 池内全部）
⑥ I-2 收缩完成后 → spread 自 committed target 向外扩散（溅射目标不再进候选池、不二次排序/选择）
```

**target_override 层级（执行参数 §二.2.2）**：`target_override`（含嘲讽强制）> 行为显式 targetSpec > 缺省目标基准（同路排首）。反制开关 `target_override_immune`（H12 族）。

### 1.3 缺省目标基准（共享内核 §一 line 15）

> `faction:enemy + laneRef:auto + anchor:front_line + scope:single` → 普攻/未声明目标规格的近战伤害**缺省打「敌方同路最前排」**；同路无可锁定候选（空路/全隐匿）时按 `laneRef:auto` 细则跨路回退全场最前排。

`laneRef:auto` 细则（2026-10-01 拍板）：同路有可锁定候选 → `same_lane`；否则 `all_lanes`（全场取 front_line，跨路平局按 lane 升序破平）。

### 1.4 溅射机制（共享内核 §一 line 14）

`spread` 5 值，**应用时点 = I-2 收缩完成之后**：主目标已定，再自 `committedTargets` 向外扩散；溅射目标不进候选池、不触发二次排序/玩家选择。

| spread 值 | 含义 | 坐标基准 |
|---|---|---|
| `splash_adjacent` | 相邻单位 | 主目标所在路前后邻位 |
| `splash_behind` | 身后单位 | 主目标所在路后方 |
| `lane_line` | 整路 | 主目标所在路全部单位 |
| `cross_same_index` | 跨路同 index | 其他路同站位序号单位 |
| `none` | 不扩散 | — |

### 1.5 全库数据实测（2026-10-03，832 卡）

| 指标 | 实测值 |
|---|---|
| scope 分布 | single 497 / all 69 / none 5 / 未声明 261 |
| faction 分布 | enemy 361 / self 134 / ally 67 / any 3 / none 5 / 未声明 261 |
| **敌方单体（enemy+single）** | **303 张，全部 manual + fallbackSort** |
| **laneRef 显式使用** | **0 处** |
| filter 显式使用 | 14 处 |
| sort 显式使用 | 2 处 |
| damage.spread 使用 | 6 处（全 `splash_adjacent`） |

**结论**：303 张"敌方单体"卡声明了 manual 选择 + 排序键，但候选池塌缩为排首 1 个单位 → 手选无第二候选、排序无平局可破、过滤无多余候选可滤。这正是用户指出的"手动和过滤排序几乎没意义"。

## 2. 问题诊断

- **塌缩点**：`scope:single` 在现有卡面被实现为"直接锁 1 个单位（排首）"，池只有 1 个。
- **三件套空转**：
  - `manual`：候选数 ≤ pickCount(=1) 时不触发玩家选择 → 退化为"唯一点"，玩家无选择。
  - `sort`：池内只有 1 个，排序键（atk_desc/hp_desc…）无并列可破，纯装饰。
  - `filter`：池内只有 1 个，过滤无多余候选可筛。
- **排首 ≠ 全路**：用户洞察的本质——"同路排首"是**基准位置**，不是**候选范围**。把范围也锁死成排首，就剥夺了路内其余单位的被选资格。

## 3. 重构设计

### 3.1 核心原则（一句话）

> **基准位置（排首）≠ 候选池（整路）。** 选靶 = 先定基准位置（锚定 lane），再在"基准位置那一整路"内做 filter→sort→select，最后 scope/spread 决定取几个、扩多远。

### 3.2 新缺省契约（default contract 变更）

| 项 | 旧缺省 | 新缺省（重构后） |
|---|---|---|
| 敌方未声明 target | `faction:enemy + laneRef:auto + anchor:front_line + scope:single` → 锁排首 1 个 | `faction:enemy + laneRef:same_lane + anchor:front_line + scope:single` → **池=同路全部可锁定单位，auto 取排首** |
| "打排首"语义 | 唯一候选 | 不写 filter/sort/manual 时 → auto 取 front_line（行为向后兼容） |
| "打特定敌"语义 | 无法实现 | 写 `sort`(atk_asc/hp_desc…) 或 `filter`(unitType/tags) 或 `selectionMode:manual` → 在**路内**选举 |
| 跨路回退 | auto 细则 | 同路池空（空路/全隐匿）→ 保持 auto 跨路回退（细则不变） |

**向后兼容**：不写 `laneRef`/`filter`/`sort` 的普攻卡，新缺省下 auto 仍取排首，表现与旧版一致（只是现在"可以"扩池，而非"被锁死"）。

### 3.3 解析流水线重述（明确"池在锚之前"）

```
① laneRef 预处理（auto→same_lane|all_lanes）
② 候选池 = faction × laneRef 交出的路内全部可锁定单位      ← 新增明确：池=整路，非排首
③ filter 过滤（隐匿/不可锁定跳过）
④ anchor 仅作"默认基准位"（front_line=排首），sort 决定选举次序
⑤ selectionMode manual/auto → committed target(s)（scope:single→1，scope:all→池内全部，pickCount=N→路内取 N）
⑥ I-2 后 spread 自 committed 沿路/跨路扩散
```

### 3.4 scope 语义重定

- `single` = 从路内池选 1（pickCount=1）。
- `all` = 路内全部（即 `lane_line` 的语义来源；`scope:all` + `laneRef:same_lane` ≡ 整路命中）。
- `none` = 无目标（配合 faction:none，I 节点跳过）。
- **新增可选 `pickCount`**：从路内池选 N（如"点 2 个敌人"），`scope:single`+`pickCount:N`；候选不足则全部取。

### 3.5 溅射与选靶的统一

`spread` 沿用 lane 坐标，与重构后的"路内池"天然一致：

- `splash_adjacent` / `splash_behind`：主目标所在路的前后/身后邻位（路内）。
- `lane_line`：主目标所在路全部（= `scope:all` 沿路）。
- `cross_same_index`：其他路同 index 单位（跨路，需 `laneRef` 已含他路）。
- 溅射比 `splashRatio`：观众 `insight` 缩放（见 §4）按位格/洞察缩放溅射伤害，落点仍在 spread 次级目标。

### 3.6 选举维度补全（让 manual 真有意义）

- `selectionMode:manual` + 路内池 > 1 → 玩家在路内挑（前/中/后/特定类）。
- `fallbackSort` 在 manual 超时/AI 时按路内排序键兜底（INV-E6 仍满足）。
- 池空（路全隐匿/空路）→ `scope:none` 跳过或 auto 跨路回退（§3.2 细则）。

## 6. 风险与不变式

- **INV-E6**：manual 卡 `fallbackSort` 必填 → 补维时校验。
- **pickCount ≤ 池大小**：池空 → `scope:none` 跳过或 auto 跨路回退（§3.2）。
- **target_override 层级**：嘲讽强制 > laneRef 池（战士守护仍锁自己这路，不被跨路池覆盖）。
- **跨路回退 auto 细则**不变（同路空 → all_lanes 取 front_line，lane 升序破平）。
- **性能**：池扩大不增加复杂度（I 节点纯函数，池规模上限=路长）。
- **向后兼容**：不补维的普攻卡表现与旧版一致（仅"可扩池"不再"锁死"）。

## 7. 四决策（已按推荐锁定 · 2026-10-03 落地）

1. **全部 303 张敌方单体都改为 lane 池 ✅** —— 全部 enemy 卡（361）补 `request.laneRef`，候选池从「同路排首 1 个」扩为「同路全部可锁定单位」；向后兼容：不写 sort/filter/manual 的普攻卡 auto 仍按 `anchor:front_line` 取排首。仅对"有叙事特化"的卡显式补 sort/filter。
2. **`pickCount` 落库 ✅** —— 字段机制就绪（schema 已建模 `cardTarget.pickCount`）；本轮 0 张卡面显式「对 N 个」命中，未强填。
3. **`splashRatio` 落点 ✅** —— 走 `damage.splashRatio` 字段（现有字段，不新开乘区）；观众 `insight` 缩放溅射比已由其 `statusDef` 承载，本轮不重复补。
4. **跨路暗杀红线 ✅** —— 守序途径（lawyer/arbiter）禁 `cross_lane`，引擎强制 `laneRef:same_lane`；落地核验 lawyer/arbiter `cross_lane` 卡数 = 0。
