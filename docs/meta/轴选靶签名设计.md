## 1. 诊断：新几何能力零使用，88 轴在选靶层完全无区分

对全库 832 张卡实测（2026-10-03，§10 迁移落地后）：

| 维度 | 实测分布 | 结论 |
|---|---|---|
| `scope` | `whole_lane` **799 / 832（96%）**、`board` 28、`none` 5 | **`front_n` / `behind_n` / `cross_lane` / `diamond_n` / `point` 全部 0 使用** |
| `anchor` | 831 张走缺省（按 faction 推导），仅 1 张 `spawned_unit` | 7 值净化 anchor 实际上只有缺省在用 |
| `pickCount` | 763 无字段（默认 1）、69 个 `'all'` | 只有「1 个 / 全部」两档，中间档位没用 |
| `filter` | 811 张无 filter，仅 21 处有 | 过滤维度几乎空转 |
| `sort` | 493 无 sort；有值的集中在 atk_desc 101 / hp_desc 96 / hp_asc 45 | 排序有一定使用，但未与几何配合 |

**结论**：§10 建好的几何能力目前**一张卡都没用上**。88 个轴在选靶层完全同构（都是"敌方整路取 1"或"敌方整路取全部"），
轴的特色**只靠效果原语撑着**——这正是本次要补的缺口：把"这个能力在空间上如何表达"也做成轴的身份。

> 顺带修正一处口径：上表 `whole_lane` 799 是**含 schema 缺省**的统计（显式写 `scope` 的只有 76 张）。
> 统计页已按此口径修正（见 `site/js/views/stats.js` 的注释）。

## 2. 设计原则：原著内核 → 选靶维度

选靶六个维度各自回答一个问题，**每个维度都能承载原著意象**：

| 维度 | 回答 | 原著可承载的意象 |
|---|---|---|
| `faction` | 作用于**谁**（敌/我/自身/任意） | 献祭自身、号令友军、降厄于敌 |
| `anchor` | 从**哪个原点**量起 | 自身/敌方排首/己方排首/新召唤物/刚死去的同伴/固定格 |
| `scope` | **框多大一块几何** | 点名 / 前排交锋 / 四周蔓延 / 跨路 / 一整路 / 天命全场 |
| `sort` | 框内**先取谁** | 最残者（死兆）、最强者（审判）、即将行动者（预知） |
| `filter` | **谁有资格** | 亡灵、恶魔、召唤物、位格低于我者、被标记者 |
| `pickCount` | **取几个** | 1（点名）/ N（小队）/ all（普惠或灭世） |

### 2.1 几何词汇 ↔ 原著意象（本设计的核心映射）

| 几何 | 原著意象 | 典型归属 |
|---|---|---|
| `point` | **点名 / 契约 / 寄生 / 附身**——一对一的精准，不容第三者 | 公证、寄生、窥秘、物品附身 |
| `behind_1/2/3` | **正面交锋 / 前排冲击 / 战线推进**——从排首往后扫 | 战士武艺、律师蛮力、燃焚、格斗 |
| `front_n` | 从我方后排**向前覆盖**（我方锚点语义） | 我方增益链、后方推前线 |
| `diamond_1/2` | **疫病 / 污秽 / 阴影**——以一点为中心向四周**蔓延** | 刺客疫、罪犯污秽、秘祈人阴影 |
| `cross_lane` | **门 / 星桥 / 梦境穿梭**——跨越两路的非常规通道 | 学徒开门、观众梦境 |
| `whole_lane` | **辖区 / 领域 / 仪式**——一整路的权威覆盖 | 仲裁人辖区、罪犯领域、荒芜、秽堕 |
| `board` | **天命 / 神谕 / 规则**——超越战场的全局，稀有且昂贵 | 律令、月相、暗夜、奇迹、循环 |
| `chain_n`（新提案） | **传染 / 连锁闪电 / 诅咒链接**——沿关系跳跃，非静态半径 | 囚犯诅咒、水手风暴 |

### 2.2 优先级原则：能小不大

`whole_lane`（一路 4 格）优先于 `board`（全场 16 格）。**只有真正"超越战场"的概念才配用 `board`**——
律令、月相、暗夜、奇迹、命运循环。一路的权威（辖区、沼泽、荒芜）走 `whole_lane`。
否则全场几何会被滥用成"默认群体"，几何就重新失去区分度（这正是当前 96% 塌在 `whole_lane` 的教训）。

### 2.3 方向语义速查（易错，务必对齐）

- `front` = **朝中线**（战斗前线）；`behind` = **朝己方后排**（远离中线）。
- 对**敌方锚点**（敌 i=0 贴中线）：`behind_n` = **敌 i=0..n = 最靠前的 n 个敌人**（常用）；
  `front_n` 跨过中线进入我方半场，**敌 spell 下通常为空**。
- 对**我方锚点**：`behind_n` = 我 i=0..n = 最靠前的 n 个友军。
- 想打**敌方后排**（暗杀/狙击，敌 i=2/3）：`behind_3` + `sort:index_desc` + `pickCount:1`，
  或直接提案 B 的 `anchor:enemy_back`。

## 3. 新增枚举字段提案

> **状态：A–F 全部批准并已落地（2026-10-03）**——schema / glossary / check_glossary / SCHEMA.md §4 /
> 共享内核参数 §一 均已同步，四门禁全绿。落地结果与实测见 §6。

现有词汇不够表达下列原著意象，建议补充。**均为纯新增，不改动既有值域**，可安全先行落地 schema。

| # | 提案 | 落点 | 解决什么 | 优先级 |
|---|---|---|---|---|
| **A** | `anchor: ally_front`（己方同路排首） | `unitRequest.anchor` | **守护/替承/前排增益**无法指向"我方排首"——当前 ally spell 默认 `anchor:self`（施法者本人），保护不了挡在前面的队友。战士守护、歌颂者圣咏都要用 | **高**（缺失导致语义无法表达） |
| **B** | `anchor: enemy_back`（敌方同路最后排） | `unitRequest.anchor` | "**暗杀后排**"是刺客/猎人/偷盗者的核心幻想，现需 `behind_3`+`sort:index_desc` 绕；显式锚点更可读 | 中（可绕，但绕法隐晦） |
| **C** | `filter` 位格筛选：`rankBelowCaster` / `rankAboveCaster` / `rankMax` / `rankMin` | `unitRequest.filter` | **位格压制**是原著核心（高位格对低位格的绝对压制），且 §1.4 位格体系已建成。仲裁人「位格律令」、观众「位格前提」目前只能靠散文描述 | **高**（原著核心 + 体系已就绪） |
| **D** | `filter: gender` | `unitRequest.filter` | 性别机制（魔女/猎人系）已登记 v0.3 但零承载；`gender_is`/`gender_shift` 谓词也零使用 | 中 |
| **E** | `scope: chain_n`（n∈1..3，沿"相邻/链接"跳跃 n 次） | `unitRequest.scope` | **传染、连锁闪电、诅咒链接**是跳跃式的，不是静态半径——`diamond_n` 表达不了"从 A 跳到 B 再跳到 C"。囚犯诅咒网、水手连环闪电、刺客疫病传播都需要 | **高**（几何词汇真实缺口） |
| **F** | `scope: cross_lane_row`（另一路整半场 4 格） | `unitRequest.scope` | 现 `cross_lane` 只是"同 index 的另一路 1 格"；**跨路 AoE**（学徒门后的空间、水手雷暴横扫另一路）需要"另一路一整条" | 中 |

> 落 schema 时的纪律：新值先加进 `unitRequest` 的 `enum`/`pattern`，同步 `SCHEMA.md` §4 + `glossary.json`
> （anchor 补 `ally_front`/`enemy_back`；scope 补 `chain_*`/`cross_lane_row` 的 pattern；filter 补 4 个键）+
> `check_glossary.py` 的 `ENUM_TO_CAT`。**先落 schema 再改数据**，避免门禁红。
> 新增 `filter` 键是自由命名空间，但须进 glossary 的 `filter` 栏目（现有 14 条）。

## 5. 落地路径

### 5.1 顺序（硬性）

1. **先落 schema + 词典**（§3 提案 A–F 经拍板后）：`unitRequest` 加 anchor 值、scope pattern 补 `chain_*`/`cross_lane_row`、
   glossary 补词条、`check_glossary.py` 的 `ENUM_TO_CAT` 登记。
   ⚠️ **不要先改数据再改 schema**（教训见 `.workbuddy/memory/2026-10-03.md`：会导致门禁红）。
2. **写迁移脚本**：沿用 `docs/archive/tools/targeting_refit_v2.py` 的骨架（递归收集 unitRequest、幂等、`--dry`/`--list`、
   写回 + `conversionNotes` 留痕 + 出报告），新增按「途径 × 轴」写签名的配方表。
3. **分批执行**：按途径分批（建议每批 4–6 个途径），每批跑完即跑四门禁。
4. **统计页增维**：几何 scope 已有 bar + 途径×scope 热图（§10.10 已落地）；本轮后可补「途径 × anchor」「filter 键」两组，
   让新签名在网页端可见（否则 96% whole_lane 的旧观感不会变）。

### 5.2 分批建议

| 批 | 途径 | 理由 |
|---|---|---|
| 试点 1 | 战士（守护需 A）、囚犯（诅咒需 E） | 两个**最依赖新字段**的途径，先验证提案是否成立 |
| 试点 2 | 刺客（疫·菱形）、学徒（开门·跨路） | 验证**已存在但零使用**的几何能否自然承载 |
| 批次 1 | 收尸人、耕种者、药师、歌颂者 | filter/sort 主导型，风险低 |
| 批次 2 | 猎人、律师、仲裁人、通识者 | whole_lane/board 主导型 |
| 批次 3 | 占卜家、偷盗者、不眠者、观众、窥秘人 | 源堡/永暗/知识荒野系 |
| 批次 4 | 水手、罪犯、秘祈人、怪物、阅读者 | 剩余 |

### 5.3 验收口径

- **四门禁全绿**（validate / validate_schema / check_enum_sync / check_glossary）。
- **几何多样性**：`whole_lane` 占比从 96% 降到 **≤55%**；`point`/`behind_n`/`diamond_n`/`cross_lane`/`chain_n` 各有 ≥2 个途径承载。
- **原著可追溯**：每张改签名卡的 `conversionNotes` 写清"原著依据 → 几何选择"。
- **轴间差异化（观察性，非硬性验收）**：差异化本就分布在**不同维度**——有的轴靠阵营（faction）分，有的靠几何范围（scope）分，有的靠排序/过滤（sort/filter）分，还有的差异**本就在效果原语层**。因此**不要求**同一途径的 4 个轴在选靶层两两都不同；self 目标轴的选靶恒收敛为 `point`，更是常态。见 §6.2。

### 5.4 风险与红线

- **不要为了多样性而多样性**：几何是叙事的外化，`board` 滥用会让全局几何重新失去意义（原则 2.2）。
- **`anchor` 缺省推导不可破坏**：`faction:enemy → enemy_front`、`faction:ally/self → self`。本次只补 `ally_front`/`enemy_back`，
  不改推导规则。
- **数值不动**：本轮只改选靶层，**不碰任何数值**（沿用骨架手术轮的纪律）。
- effect 级 `target_override` / statusDef `behaviorModifiers` 的 anchor 是自由字符串，**不在本轮迁移范围**。

### 6.2 轴间差异化分布（观察性，非验收）

按「主导 faction / scope / anchor / sort / pick / filter」六维比较同途径内两两轴（共 132 对），结果作为**分布画像**而非验收门槛：

- **≥2 维不同：116 对（88%）**
- **<2 维不同：16 对（12%）**，其中 **完全同构 2 对**：`assassin.form vs mirror`、`warrior.guard vs hunt`。

**裁定（2026-10-04，用户拍板）：差异化在不同维度体现，不要求每个轴在选靶层都不同，不强制拆这 16 对。**

根因：那 16 对（含 2 对同构）多为**被 self 目标卡主导**的轴（自身变形 / 自身守护姿态），self 目标几何恒收敛为 `point`，
选靶本就不是它们的区分点——**区分本就在效果原语层**（`form` 是变形机制、`mirror` 是镜像替身机制，机制不同而非目标不同）。

**撤销原「深化轮待办」**：不再为指标去追加 sort/filter 硬凑差异，那会破坏原著贴合度。若日后某途径确实需要靠选靶区分两个 self 轴，再单独评估，而非批量工程。

### 6.3 两处脚本口径修正（写脚本时踩到）

1. **`faction:'any'` 不能按"精确相等"匹配**——首版把所有 `any` 轴的命中数打成 0（实际卡里几乎没有
   `faction:any`，它表达的是"该轴不挑阵营"）。修正为：`any` 轴对任意 faction 套用。修正后 272→408 张。
2. **self 目标卡的几何必须收敛为 `point`**——否则 self 卡会被套上 `board`/`behind_n` 成为纯噪声。
   但**轴签名本身就是 self 轴的要尊重轴设计**（如秘祈人阴影 `self + diamond_1` 是刻意的）。

### 6.4 四门禁

全绿：G1 832/0 · G2 22 文件/0 · G3 枚举一致 · G4 无缺词条。（`scope`/`filter` 因是 pattern 与开放结构，
不在 enum 正源内，G4 列为"无 schema 值域来源"，信息级。）
