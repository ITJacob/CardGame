## 〇、2.0 改了什么、为什么

1.0 的轴级判据只认**一种形状**（身份状态 → enabler 挂载 → payoff 读身份 → 读法多样），
且身份锚定硬要求「层数引擎」。实测 88 轴里产读闭环型仅 46，其余 42 是资源循环 / 触发器 /
形态轮转 / 召唤军团 / 纯放大器 / 自闭环 / 规则槽 / Pool；19 个轴靠 `payoffVacuumAccepted`
逃生舱拿保底分——**逃生舱的存在即模板不匹配的自证**。更关键的是：1.0 只认**直接引用**
（`statusId` 命中），看不见**间接作用**——不眠者「赶夜 `advance_clock` → 改全局时钟 → 相位入夜
→（跨四轴）点亮相位门控收益」这条链路经过「相位」这个**全局通道**，1.0 完全失明。结果：越按
分数优化越同质化，正是「差异化专项」要防的东西被评分体系自己制造出来。

2.0 的两条改动主线：
- **作用面**取代「身份状态」单点：评分认**状态面 + 全局通道面**两类产出，直接引用与**通道介导的
  间接作用**等价计分——多种轴型都能拿分，不再往一个形状上拧。
- **差异化权重大幅上调**（10→25），并把结构/落地/文本三个「全库已满分、无区分度」的维压到 5。

**2.1（同日追加）**：指纹向量从「原语四族」升级为**全链路八族**（加**状态身份 / 选靶 / 选靶 filter /
触发点**，见 §三·一），轴内多样性同步扩到全链路词表。动机：度量一度只认原语，导致**选靶维度
（全库 571 卡有 `target`、88 轴已逐一设计签名）与私有状态身份对差异化零贡献**——用常规原语做
主题化机制的途径（如战士）被结构性低估。

**2.2（2026-10-17）**：全链路指纹从八族扩到**十二族**（2.3 合并选靶两族后为十一族），并修三处口径缺口：
① `sref`（私有 statusId）→ `sshape`（状态形态）——statusId 是途径私有命名，跨途径几乎零重合，
   距离恒满，等于把"有没有私有状态"当设计差异；改为展开状态 def 的结构 flags / 修正名 /
   自带效果原语 / 时长形态，跨途径可比。
② `stat`（只取 `modify_stat` 的 `stat` 键）→ `param`（所有原语的枚举型参数键值），补
   `modify_resource.resource` / `spawn` 单位与位置 / `move`·`domain`·`translocate` 的 op /
   规则槽 field 等；仍不取数值（原则 4）。
③ 新增 `condarg`（条件谓词的枚举参数）、`reach`（射程）、`cost`（支付形态档）、
   `temporal`（吟唱 / 时长口径）。轴内多样性的"状态身份"同步改为"状态形态"。

**2.3（2026-10-17）**：权重收尾。实测 22 途径的「结构健康 / 机制落地 / 文本完备」全部满分，15 分

## 一、原则

1. **全部指标机器可验**：从 JSON AST 实算，不靠人工打分。
2. **每个失分项指向具体卡/轴**：计分卡附失分清单，可直接转为修改动作。
3. **闭环优先**：产出物被**消费**（直接读 / 通道下游 / def 内自闭环）权重最高。
4. **评分不治数值**：全库数值 ⚠️D 是基线状态，不计分；本体系评的是**结构与设计丰富度**。
5. **差异化可度量**：途径级「差异化」维（签名键 + 途径间指纹 + 构型多样 + 途径内去重）使同质化在分数上可见。
6. **承认间接作用（2.0 新增）**：产出物经**全局通道**（相位 / 量表 / 场地 / 召唤…）被他处消费的，
   与卡面直接读等价计分——间接因果链不再隐形。
7. **玩法轨隔离（2.4 新增）**：玩家侧指标（`playable_scan.py` 10 项）只作诊断与验收，**永不进 100 分**——
   进分即会在两轮内被优化成新的刷分面。
8. **指标生命周期（2.11 新增）**：新指标须先跑 ≥3 轮只读诊断方可进 100 分（玩法轨隔离的推广）；
   score.py 每轮输出各维全库方差（`analysis/variance.md`），方差 <1.0 的维标「候选降门禁/降权」，
   人工复核后走口径变更流程（先改本文件再改 score.py）。
   **准入门槛（2.15）**：进分前另须过 §〇 2.15 五条（单义可赋 / 增量信息 / 有效类数 / 声明可对账 / 进分位置先定）。

## 一·附 卡角色口径（2.12 立）

卡可声明 `role`（schema `$defs/card.role`，六值，**opt-in——未声明 = 计分面现状不变**）。
角色的意义：在设计阶段（玩法蓝图工序）就声明卡的定位，使「刻意平庸/教学/对策/赌博」不被
差异化/去重/密度指标误判为缺陷，也让承重件必须真的承重。`flagship` 保留独立 bool，不并入 role。

| 角色 | 作用 | 量化判据（机器可验） | 对计分的影响 |
|---|---|---|---|
| `core` | 轴循环承重件 | 命中 ≥1 项身份动作：挂锚点状态 / 读写锚点通道 / 签名键载体 / 被 axes.enablers\|payoffs 登记 / **写入本途径跨系枢纽**（2.13：卡面直接 `mount_status` 挂 `crossPathway:true` 且 owner=本途径的状态；间接写入不算）；否则注级「core 无身份动作」 | 全计分（指纹/密度/去重/实证全权重） |
| `starter` | 低序列教学卡 | 硬校验 `rarity=="common"`（validate.py）；原语种类 >2 属设计过 Complex，人工复核 | starter↔starter 近重复对豁免去重惩罚 |
| `bridge` | 跨轴/跨系连接 | 须读本途径他轴私有状态/facet，或读他途径枢纽/耦合通道，否则注级「bridge 无跨界读取」 | 无豁免；语义注级进失分清单 |
| `generic` | 泛用骨架 + 刻意补位 | 反向约束（硬校验/门禁）：不得被 axes 登记、不得携带签名键、不得 `flagship` | **不入途径间指纹向量**；generic↔generic 对豁免去重；被登记 →「角色冲突」注级且不计实证 |
| `trap` | **core 同族的赌博变体**（偏激进、有输面） | 须命中身份动作（同 core）**且**须带风险段（chance 条件 / 含失败分支的双分支条件 / 自伤），缺一即注级 | **与 core 同计分面**：照常入指纹、可登记 enabler/payoff 实证 |
| `tech` | 对策卡（驱散/反制/针对 filter） | 语义含 dispel/take_control/target_override 等对策原语或针对 filter（人工声明，机器不判） | 豁免收束实证要求；被登记进 enablers/payoffs →「角色冲突」注级且不计实证 |

**配比约束（两级）**：**core 是轴级硬约束**——每轴 ≥1 张（途径已有 role 声明后启用，蓝图 rubric 判）；
**其余五角色是途径级约束**——starter/bridge/generic/trap/tech 途径各 ≥1 张（蓝图 rubric 判，轴级不要求配全）。
**防刷收口**：generic ≤25%、trap ≤20%（对齐玩法轨「纯转移卡 ≤1/3」约束，蓝图 rubric 判）——
generic 豁免去重又不入指纹，无上限即可把同质化整组隐身。

**违规分两级**：硬结构（starter≠common、generic 被登记/带签名键/旗舰声明非 core/trap、轴缺 core）
→ validate.py 报错或蓝图 rubric 判（2.14 起结构门禁不再单设计角色合规分）；语义不当
（core 无身份动作、bridge 无跨界读、trap 无风险段）→ score.py 注级失分清单，不扣分。

**风格边界与全局通用玩法**：途径有基础风格，卡不应越界——score.py 只读诊断「风格越界」
（卡命中他途径主签名键、且该键非 ≥3 途径共享的事实通用分叉 → 注级列出，**不进 100 分**，
原则 8 首个实例）。全游戏通用玩法不被任何途径写死包揽：damage/heal/modify_stat/move 等
通用原语骨架与 §二·三 全局概念词表任何途径可用、不算越界；玩法蓝图的「风格边界」表须声明
途径主签名维度 + 使用的全局通用机制，使「占用 vs 通用」可审计。

**失分清单联动**：已声明豁免角色（generic/starter/tech）的卡出现在失分项时，fix 自动冠
「如属误判请改 role 而非改卡」——防止按通用建议把刻意设计改坏。

## 二·零 轴身份锚点体系（2026-10-19 立）

> 原则：**一个轴以「代表玩法 / 机制」为身份，状态只是可选载体**。不得为了评分给每个轴强造一个状态、
> 再让其他卡围绕它做产层/读层——那是 AI 设计模式的核心病灶。

轴可用 `axes.<axis>.anchor = { kind, id }` 声明锚点；`statusId` 是 `kind=status` 的兼容简写。
锚点必须满足两条：**可机器验证**（结构化操作存在）＋ **有闭环**（≥2 张卡操作、≥1 张卡读取或自身机制闭环）。

### 全四类锚点清单（登记版）

|---|---|---|---|

### 评分口径

- **最小实现集**：`status` / `resource` / `channel` / `equipment` / `primitive`（落在 score.py）。
- **（2.14）轴级计分改兑现口径**（§二表）：蓝图锚点 kind:id 与 axes 实录对账；产层/收束兑现的
  实证判据仍按锚点的「产出面」计算：
  - status → `status:<id>`；equipment → 该槽全部状态；channel → 通道键；resource → 资源读写；primitive → 原语使用。
- 未声明 anchor 且无 statusId 的轴：产出面回退旧逻辑（Pool 资源 / 本轴通道）。
- 不适合作锚点：单一元素/单张卡签名、纯数值维度、通用骨架原语（damage / mount_status）。

### 二·一 全局通道表（「间接作用」的载体）

通道 = 战场级共享变量，跨轴 / 跨途径可见。轴产出面 = 「状态面」∪「通道面」。

> 之后的通道——二者是库内结构性脚手架（写卡 41 / 117 张），纳入会让"有区域/有召唤"人人拿满耦合分；
> 它们仍计入轴的产出面供「收束」判定。

### 二·二 归一说明

跨轴耦合 / 跨系联动原始量为**重尾分布**（通道读者可达数十），2.0 用**封顶归一**（`15 × min(raw, CAP)/CAP`，
跨轴 CAP=8、跨系 CAP=16）而非「÷全库最大」，避免单点离群把其余途径压平。

### 二·三 机制条目（facet）：全局概念的主权边界

> 2026-10-19 拍板：武器 / 相位 / 资源 / 原语是**全局概念**，不是任何轴的身份。轴的身份是它在概念上
> 实现的**机制条目**；「占了武器」不等于武艺，「用过相位」不等于相位轴。

轴用 `anchor = {kind, id}` 声明自己占有的概念；score.py 从轴内卡面自动提取实际占用的 facet：

| 概念 | facet 词表 | 判定 |
|---|---|---|
| equipment | equip / durability_consume / durability_replenish / read_equipped / dump / steal | 装备槽状态挂载 / 耐久消耗（charges + on_attack）/ 补耐久（restoreCharges）/ 读已装备 / 一次打空 / 夺取或卸下 |
| channel | write / read / cycle | 写通道（§二·一）/ 读通道 / phases·cycleTicks·formGroup 轮转 |
| resource | produce / consume / threshold | 加资源 / 减资源 / thresholdTrigger·resource_compare 档位 |
| primitive | use | 使用该原语 |

规则：

- **只有轴锚点上的 facet 参与跨轴耦合**；轴没声明某概念为身份，就不占有它的机制条目（避免「用过相位即独霸相位」）。
- 跨轴卡与轴 facet **同概念同条目**才算耦合；不同条目（如武艺=装备/耐久，另一轴=抢夺武器）不算。
- 私有状态按「途径内占多数的轴」归属（排除 common 与 `classMechanics`）；武器不是状态，不参与私有状态归属。跨轴读该状态仍算耦合。
- 通道保留「写入→下游读取」的产出消费耦合（§二·一），与 facet 取并集、同卡同轴只计一次。

示例（战士）：武艺锚 `equipment:weapon`，facets = equip / durability_consume / durability_replenish / read_equipped。
猎魔「晨曦之剑」同占 equip + durability → 耦合；黄昏「神罚」读已装备武器 → 耦合；若另有轴只抢夺武器（steal）则不算。

示例（不眠者）：暗夜锚 `channel:phase`，facets = write / read；夜色 `nightfall` 是相位资源，不再冒充轴身份。
只受相位门控、不推进时钟的梦魇 / 安魂轴仍按状态锚点，读相位只作为对暗夜的耦合。

### 三·一 全链路指纹（2.1 新增；2.8 十二族，unit 2×）

> 动机：**机制的复杂性不单单是原语**——施法作用的整条链路（选靶 → 条件 → 效果 → 状态 → 时序）
> 都是设计语言。2.2 起状态不再用私有 statusId 当键（跨途径不可比），改为状态 def 的形态指纹。

指纹 = 若干**族**，每族独立 **L2 归一**后参与距离；`cos_dist` = **各族余弦距离的加权均值**
（默认 1×；`unit` 族 **2×**——召唤物自身的设定是召唤卡的主载荷）。
距离计分用**绝对阈值**（0.14–0.30 五档，见 §三），不再用全库分位——分位制会让「全库一起优化」排名不动、
单卡微改跨档套利。

> **效果空间** = `cards[].effects` + `cards[].triggers[].effects`（2.6）；`spawn` 引用 `unitDef` 的
> 元素 / tags / `triggers[].effects`（2.7，其 `triggers[].event` / `condition` 另计 `hook` / `cond`，
> 2.16）；**卡面挂载状态 def 的 `triggers[].effects`**（2.9）。
> 被动/触发载荷与主动效果同口径；只读 `effects` 会让带触发器的被动卡在指纹里退化成一个挂载节点。
> `hook` 仍是触发点本身，其余族取效果空间。

| 族 | 键 | 来源 |
|---|---|---|
| `prim` | 原语种类 | `card_effect_types`（每卡去重，含触发载荷） |
| `elem` | 元素 | 效果空间的 `element` |
| `cond` | 条件谓词 | 效果空间的 `_cond_kinds`（含 unitDef 触发器条件，2.16） |
| `condarg` | 条件谓词的枚举参数 | 效果空间 `kind:field=value`（cmp/side/key/stat/unitIdx/…；**私有 statusId 不取**） |
| `param` | 效果原语的枚举参数 | 效果空间 `field=value`（`modify_stat.stat` / `modify_resource.resource` / spawn 单位与位置 / `move`·`domain`·`translocate` 的 op / 规则槽 field 等；**数值不取**） |
| `reach` | 射程 | active 卡 `reach`（none/melee/spell/thrown） |
| `tgt` | 选靶（卡级坐标 + filter + 效果级作用对象） | `target.request`：`faction`/`scope`/`anchor`/`mode`/`selectionMode`；`request.filter` 键（前缀 `filter:`）；效果空间的 `target`（前缀 `eff:`） |
| `hook` | 触发点 | 卡级 `hook`/`triggers[].event` ＋挂载状态 def 的 `triggers[].event` ＋ unitDef 蓝本的 `triggers[].event`（2.16）；**排除 `on_apply`**（状态挂载载荷的固有生命周期事件，不体现触发点设计） |
| `sshape` | **状态形态** | 引用状态 def **及卡面挂载状态 def** 的结构 flags（triggers/charges/stack/threshold/form/phases/cycle/ramp/behavior/action_lock/immune/redirect…）+ 修正名 + 自带效果原语（`on_apply` 载荷）+ 时长形态；**不含私有 statusId** |
| `cost` | 消耗形态 | `energy` 档（zero/low/mid/high）+ `cooldown` 档（none/short/long）+ 血费（效果空间中的自伤 hp 支付） |
| `temporal` | 时序形态 | 吟唱有无（`castTime>0`）/ `durationUnit`（tick、self_turn）/ 吟唱转瞬发 |
| `unit` | **召唤物设定**（2× 权重） | 卡面 `spawn` 引用的 `unitDef`：`type:<unitType>` / `elem:<element>` / `tag:<tag>` / `reach:<reach>` / `hp:low·mid·high` / `atk:low·mid·high` / `trig:<event>:<原语>`（攻击/亡语载荷） |

> 不取数值：上述键只记录**形态/档位**，不含 amount、value、duration 等数值（SCORING 原则 4）。
> 消费通道 `consumption`、选靶几何形状（schema 无字段）等暂未入族；需扩展时加进 `score.py`
> 的 `FAMILIES` 并同步本表。
