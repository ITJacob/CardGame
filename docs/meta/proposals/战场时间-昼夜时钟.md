## 一、原著核查结论（先定边界）

### 1.1 22 途径内的时间设定只有三类

| 类别 | 原著出处 | 仓库现状 |
|---|---|---|
| **状态重启**（非时间倒流） | 水银之蛇 序列1「循环」权柄：保存 / 选择 / 重启 / 命运循环。原著对「重启」原文括注：**"重启区域内状态（非逆转时光）"** | ✅ 已落地 5 卡：保存、选择、重启、重启循环、命运循环 |
| **时间推进**（加速 / 剥夺） | 时之虫 序列1「窃取时间」「衰老」；战士 序列2 荣耀者「黄昏」权柄让目标老化至死；序列0 黄昏巨人「飞快衰老」 | ✅ 已落地：窃取时间、窃取锚、衰老、石制壁钟、壁钟之域；战士 `twilight` 轴 statusId = `aging` |
| **历史 / 循环** | 愚者 序列0「愚弄时间/历史」+ 历史权柄；古代学者借历史孔隙；星之匙 序列1「时空迷宫：时间即空间」 | ✅ 已落地：历史影像、借取力量、时空迷宫、封印 |

### 1.2 真正的反向时间不在本仓库范围内

反向时间只出现在**外神途径**（《宿命之环》新增，**不属于本仓库 22 途径**）：

- 病患途径（第二定律）序列2 **时光巨人**：混乱 / 加快 / 放慢 / 切割时间；序列1 **衰老之神**：时间加速衰败
- 舞蹈家途径（永劫者）序列2 **罪人**：回溯自身状态；序列4 **环中人**：过去和现在的循环

→ **只能作数值与手感参考，不能作落地依据。**

### 1.3 裁定

**战场时钟只进不退。**「回到过去」的语义全部交给已有的 保存 / 重启 / 命运循环 三卡（快照回滚），不新增时钟回拨算子。

依据除原著「非逆转时光」外，另有引擎侧硬约束：时钟回拨需连带回滚全部 `duration` / `gauge` 历史，与 **INV-S5**（行动周期是派生值，不可直改）及确定性回放契约（R6）冲突。

## 二、三层数据模型

| 层 | 字段 | 类型 | 语义 |
|---|---|---|---|
| L1 绝对时钟 | `board.clock` | `int[0,71]` | 每 tick +1，到 71 后归 0（跨日环绕）。**唯一可写源** |
| L2 派生光照度 | `board.luminance` | `int[0,10]` | 由 `clock` 查表派生，**只读** |
| L3 覆写层 | `board.lumOverride` | `{ value, duration, sourceId }` | 权柄卡写入，压栈顶，到期回落 L2 |

- **INV-C2（数值单点定义）**：`luminance` 只由 `clock` 派生，不双写；卡面不存光照度副本
- **派生相位** `board.phase`：`clock → phase` 查表派生，与 `luminance` 同为只读视图
- **覆写优先级**：L3 > L2；多个 L3 按打出序号压栈（复用 `DomainGrant.priority` 口径）

> ⚠️ **档位与相位不严格同构**：黎明前段（tick 12–15，04:00–05:00）光照度 ≤2，落在暗夜档——这符合「黎明前最暗」的物理事实，但会让黎明轴卡片在此窗口吃到暗夜档乘区。**需要精确判定的卡一律走 `phase_is` 谓词，不要只靠阈值。**

## 四、进入战斗的时间（按塔层定窗口 + 种子抖动）

| 塔层类型 | 基础窗口（clock） | 抖动 | 等价区间 |
|---|---|---|---|
| 常规层 | 24–47（白昼） | ±6 tick | 08:00–16:00 ±2 小时 |
| 夜战层 | 54–71 ∪ 0–11（夜/午夜） | ±6 tick | 18:00–04:00 ±2 小时 |
| 晨昏层 | 12–23 ∪ 48–59（黎明/黄昏） | ±3 tick | ±1 小时 |
| 首领层 | 48–59（黄昏） | ±3 tick | 16:00–20:00 ±1 小时 |

合规性：

- **R1 / R5**：时钟影响的是**状态挂载与乘区**，不是伤害数值、资源增减、目标选择 → 落在非伤害维度边界内
- **R3**：起始时间抽样必须显式登记，供平衡审计工具筛出单列
- **R4**：只在 CombatSetup 抽样**一次**，结算链内不二次抽样
- **R6**：`结果 = f(初始状态, 输入序列, seed)`，起始 clock 随 seed 固定 → 回放逐位一致

设计理由：纯随机会让夜行构筑在正午开局直接废掉，玩家无法预期；按塔层定窗口后「选路」本身成为构筑决策的一部分，符合肉鸽化方向。

## 五、消费接口

### 5.1 乘区挂钩（复用既有 dimHook）

`dimHook.dim` 枚举由 `secrecy / order / fate_value` 增补 **`luminance`**。之所以主量用**连续量**而非枚举 phase：schema 的 `dimHook.threshold` 是 number + comparator，枚举塞不进去；改用 0–10 连续刻度后只需加一个枚举值 + 一条阈值档，完全复用现有机制。

**官方阈值档（2 / 5 / 8，已登记进 `数值标定基准.md` §五.3）**

| 档 | 条件 | 语义 | 主要受益方 |
|---|---|---|---|
| 暗夜档 | `luminance ≤ 2` | 夜色庇佑 | 不眠者（夜幕轴）、秘祈人（阴影轴）、刺客（影形态） |
| 晨昏档 | `3 ≤ luminance ≤ 7` | 晨曦 / 暮光 | 战士（黎明轴 + 黄昏轴双峰） |
| 白昼档 | `luminance ≥ 8` | 日照 | 歌颂者（太阳光环 / 白昼） |

单卡乘区仍受 §五.1 约束（建议 0.8–1.5，超限需单列审批）；阈值口径一律复用本表，不得自造档位。

### 5.2 条件谓词（`共享内核参数.md` §三 增补）

沿用「带参谓词族」纪律，不为每种比较新开 ID，只加两个：

| 谓词 | 参数 | 语义 |
|---|---|---|
| `phase_is` | `phases[]` | 当前相位属于集合之一（月夜 = `phases:[night,midnight]` + 月相条件） |
| `luminance_compare` | `cmp, n` | 光照度比较（`cmp:'<=', n:2` = 暗夜档） |

可与既有 `any_of` / `all_of` / `not` 组合子嵌套。

### 5.3 战场算子（新增 2 个，原语 27 → 29）

| 算子 | 参数 | 语义 | 触发 |
|---|---|---|---|
| `advance_clock` | `ticks` | `clock += N`（mod 72）→ 相位可能跃迁 | 触发 `on_phase_change` |
| `set_luminance` | `value, duration` | 写入 L3 覆写层，到期回落 | 写入时触发 `on_phase_change` |

**不做 `rewind_clock`。**

### 第二批的开放问题（挂 dimHooks 前必须先定）

1. **战士黎明/黄昏双峰是否互拆**：`hunt` 轴只在 dawn、`twilight` 轴只在 dusk，还是两轴都在晨昏档受益？
