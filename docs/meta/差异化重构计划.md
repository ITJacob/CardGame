### 阶段一：体系建立（2026-10-01 批次，已完成）

### 阶段二：逐途径风格迭代（进行中，后续会话按队列推进）

每途径一轮，沿用环节⑤纪律（WORKFLOW.md）+ 两条风格专项规则：

1. **身份卡前置**：改卡前必读该途径身份卡（`途径设计身份.md` §二）——步①定位以「签名键空白/发芽」
   为优先立项依据，与轴评分失分项并列。
2. **第七维必涨**：风格迭代轮的改前改后对比含第七维「风格签名」，签名键落地数只增不减；
   新卡数值照旧过数值锚点（数值标定基准 §一–§四）与四门禁。
3. 一途径一 commit；REDESIGN_LOG 记「风格迭代」行（日期/途径/签名键 改前→改后/主要改动/commit）。

**收官实测**：mount_status 占 prim 节点 41.9%→**26.8%**、三件套 68.7%→**44.1%**、22 途径均距最低值 0.089→**0.339**（全部远超毕业线 0.12）、
最近对最低值 0.017→**0.119**（毕业线 0.04）。四门禁全绿（validate 832 卡 0 错、validate_schema 22 文件 0 错、枚举与词典同步）。

**本性豁免（4 项，不再压指标）**：monster 35.4% / hunter 31.0% / sleepless 31.1% mount 略超 30%，
sailor 三件套 53.2% 略超 50%——这四个是「双极状态池」或「元素直伤」本性途径，mount/damage 正是它们的表达主体，
继续稀释反而损伤身份。**全库口径才是验收口径**（27.0% / 44.5%，均已达标）。

**矫形记录（同一轮，第二批校准）**：一次性铺完 20 途径后，扫描全邻接矩阵发现两组新近邻——
apprentice×assassin 0.119（两家的收益段都写了 translocate + 迷失租金）、arbiter×lawyer 0.120（两家都在动 rule_slot 原语族）。
按各途径身份红线重新归属：
- **刺客**收益段的 banish 改为 `modify_targetability`（留一具替身承接指向，不再抢 translocate），
  translocate 只保留在 dmg 段的 pull_into；
- **仲裁人**审判段的 `modify_rule_slot(remove)` 改为 `take_control`（判决即执行：判决生效时由法庭代为执行一次动作，随后归还行动权）。
结果：全库最近对 0.119→**0.154**，均距最低值抬到 0.332，全库均分 73.3→**73.6**；
代价是两条先发途径因独占原语被稀释而分数回落（lawyer -5.3 / supplicant -4.2），但仍是第一梯队（81.4 / 82.7）——
**风格签名分是相对量，全库普遍抬高必然互相抵消，验收应以绝对指标（指纹距离、mount 占比）为准**。

**校准要点（第二批追加）**：③ 注入段必须含**非通用六件套**的原语，否则卡面换了写法但计分器仍判“通用骨架”
（本轮囚犯首批只注了 modify_resource，30 张改完全数仍判通用，补 transfer_status 后才清零）；
④ 优先起用全库零使用/低频原语（transfer_status / take_control / set_luminance / restore_snapshot / echo_last_skill / grant_immunity
在轮前均近乎闲置），它们既贴合途径语义又是指纹距离的主要贡献项。

**试点校准结论（2026-10-02，两批后）**：手术力度以「把通用骨架卡清零」为剂量标准——两批实测均达
0 张通用卡、mount_status 落在 24–28%、三件套落在 39–46%，均距抬到 0.23–0.30（原 0.09），
四项毕业线全部达标且无副作用（四门禁全绿、文本完备满分）。剂量可直接推广剩余 17 途径。
**校准要点**：① 每途径先定 1 个「句式」（如秘祈人＝血肉账本四句式、律师＝篡改六件工具），
再让所有卡按句式改写，而不是逐卡各想一招；② 低阶卡同样换形、不设豁免（拍板已定）；
③ 优先启用**全库零使用/低频原语**（drain / modify_skill / modify_rule_slot）——既是风格富矿，
也是指纹距离的主要贡献项。

**毕业线**（逐途径验收，两项达标即毕业）：三件套占比 ≤50%；途径均距 ≥0.12；最近对 ≥0.04；
mount_status 全库占比 ≤30%（现 41.7%）。手术批同样一途径一 commit、四门禁 + build_analysis 同轮、
REDESIGN_LOG 记行（骨架手术轮改前改后分数 + 三件套占比 + 均距 + 最近对四项对照）。

## 推进规则（照此执行，不再逐批请示）

- **节奏**：一次会话 1–2 条途径（环节⑤既有纪律）；每轮四门禁 + build_analysis.py 同轮全量重跑。
- **顺序**：严格按排队表销账；跳批须在 REDESIGN_LOG 注明理由。
- **立项**：每轮开工先读身份卡 + scorecard 该途径失分项 + STYLE_DISTANCE 该途径最近邻——
  三者交集即本轮立项清单。**2026-10-02 起加第四输入**：机制所有权矩阵（途径设计身份.md §三）——
  该途径的正主维度须成体系、共享维度须语义分叉、禁入维度不得触碰；四机制扩展（尸体物件/死亡簿/
  rank_gap/tag_chain）已落 ddd，批次补卡可直接消费。**骨架手术轮再加第五输入**：途径设计身份.md
  §二·五骨架风格——通用卡换形必须按本途径五维形状写，改完核毕业线。
- **验收**：四门禁全绿；该途径第七维 ≥ 改前且签名键落地数增加；STYLE_DISTANCE 该途径对最近邻
  距离 ≥ 改前；REDESIGN_LOG 记风格迭代行。
- **改卡纪律**：DESIGN_CHECKLIST 8 步不变；数值照旧走锚点；身份卡「风格红线」是硬约束
  （违反红线的新卡即使涨分也打回）。
- **冲突仲裁**：新卡想用的机制已被他途径主签名占用 → 按身份文档「次级共享须语义分叉」规则
  评审，分歧升级用户拍板。
