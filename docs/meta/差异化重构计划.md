### 阶段二：逐途径风格迭代（进行中，后续会话按队列推进）

### 阶段二·五：骨架手术批（2026-10-02 立项，待执行）

阶段二（加法批）已把 22 途径签名键全部落地，但统计复核发现集中度未解：643/832 卡（77%）仍是纯

最近对 sleepless~spectator 0.017。签名增量撼动不了同构底座——须做**换形手术**：
通用卡数值可不变、AST 形状换成本途径写法。22 途径五维骨架风格定义见
`途径设计身份.md` §二·五（卡面骨架/私有状态/zone/召唤/domain 五维 + 手术总则 + 拍板记录：
zone 差距项补录、全部换形不设豁免）。

**试点校准结论（2026-10-02，两批后）**：手术力度以「把通用骨架卡清零」为剂量标准——两批实测均达
0 张通用卡、mount_status 落在 24–28%、三件套落在 39–46%，均距抬到 0.23–0.30（原 0.09），
四项毕业线全部达标且无副作用（四门禁全绿、文本完备满分）。剂量可直接推广剩余 17 途径。
**校准要点**：① 每途径先定 1 个「句式」（如秘祈人＝血肉账本四句式、律师＝篡改六件工具），
再让所有卡按句式改写，而不是逐卡各想一招；② 低阶卡同样换形、不设豁免（拍板已定）；
③ 优先启用**全库零使用/低频原语**（drain / modify_skill / modify_rule_slot）——既是风格富矿，
也是指纹距离的主要贡献项。

**毕业线**（逐途径验收，两项达标即毕业）：三件套占比 ≤50%；途径均距 ≥0.12；最近对 ≥0.04；
mount_status 全库占比 ≤30%（现 41.7%）。手术批同样一途径一 commit、四门禁 + build_analysis 同轮、
REDESIGN_LOG 记行（骨架手术轮改前改后分数 + 三件套占比 + 均距 + 最近对四项对照）。

## 推进规则（照此执行，不再逐批请示）

- **节奏**：一次会话 1–2 条途径（环节⑤既有纪律）；每轮四门禁 + build_analysis.py 同轮全量重跑。
- **顺序**：严格按排队表销账；跳批须在 REDESIGN_LOG 注明理由。
- **立项**：每轮开工先读身份卡 + scorecard 该途径失分项 + STYLE_DISTANCE 该途径最近邻——
  三者交集即本轮立项清单。**2026-10-02 起加第四输入**：机制所有权矩阵（途径设计身份.md §三）——
  该途径的正主维度须成体系、共享维度须语义分叉、禁入维度不得触碰；四机制扩展（尸体物件/死亡簿/
  rank_gap/tag_chain）已落 ddd，批次补卡可直接消费。**骨架手术轮再加第五输入**：途径设计身份.md
  §二·五骨架风格——通用卡换形必须按本途径五维形状写，改完核毕业线。
- **验收**：四门禁全绿；该途径第七维 ≥ 改前且签名键落地数增加；STYLE_DISTANCE 该途径对最近邻
  距离 ≥ 改前；REDESIGN_LOG 记风格迭代行。
- **改卡纪律**：DESIGN_CHECKLIST 8 步不变；数值照旧走锚点；身份卡「风格红线」是硬约束
  （违反红线的新卡即使涨分也打回）。
- **冲突仲裁**：新卡想用的机制已被他途径主签名占用 → 按身份文档「次级共享须语义分叉」规则
  评审，分歧升级用户拍板。
