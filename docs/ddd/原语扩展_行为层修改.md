# 原语扩展提案：行为层修改（modify_skill / modify_status / 状态行为封锁）

> 状态：已落地 schema v1.2.0（`docs/json/schema/skills.schema.json`）+ 两个校验器 0 错误。
> 日期：2026-09-17
> 背景：原 19 个效果原语全部作用于「战斗状态」（单位 / 资源 / 状态 / 站位 / 区域），**没有任何原语能改写技能实例本身，也没有原语能改写一个「运行中」的状态实例**。用户提出的三类缺口——清 CD / 改消耗 / 吟唱转瞬发 / 单体转范围、改状态最大层数 / 持续、行为层封锁（禁移 / 禁普攻 / 禁跳过等）——均属此范畴。

---

## 1. 三类缺口与对应设计

| 用户诉求 | 属于哪层 | 设计落点 | 是否新原语 |
|---|---|---|---|
| 清除当前技能 CD | 技能实例 | `modify_skill.clearCooldown` | ✅ 新原语 |
| 增减技能施法消耗 | 技能实例 | `modify_skill.costDelta` | ✅ 新原语 |
| 吟唱技能改瞬发 | 技能实例 | `modify_skill.setInstant` / `castTimeDelta` | ✅ 新原语 |
| 单体技能改范围技能 | 技能实例 | `modify_skill.targetingModeOverride` | ✅ 新原语 |
| 修改状态最大可叠加层数 | 状态实例 | `modify_status.maxStacksDelta` / `maxStacksSet` | ✅ 新原语 |
| 修改状态持续时间（运行中） | 状态实例 | `modify_status.addDuration` / `setDuration` | ✅ 新原语 |
| 禁止移动 / 禁止普攻 / 禁止跳过 … | 行为（行动许可） | 状态属性 `statusDef.disallowActions` | ❌ 复用 `mount_status` |

**关键判断**：前两组是「作用于运行期实例」的能力，既有原语体系里确实不存在，必须新增原语。第三组「行为封锁」本质是「单位持有时禁止某些行动」——这与 `seal` 类别、`眩晕 disable`、状态 `charges` 的既有建模完全一致，**无需新原语**，只需在 `statusDef` 上新增一个结构化的 `disallowActions` 字段（枚举受控、可被 schema 校验），仍走既有 `mount_status` 挂载。

---

## 2. `modify_skill`（行为层修改一）

```json
{
  "type": "modify_skill",
  "skillRef": { "selector": "self_last" },
  "clearCooldown": true,
  "note": "清除施法者刚刚释放技能的剩余冷却"
}
```

字段语义：

| 字段 | 类型 | 说明 |
|---|---|---|
| `skillRef.selector` | enum | `self_last`(最近一次主动技能) / `self`(配 `skillId`) / `target`(目标单位身上，配 `ofSkill`) / `by_id`(按卡 id) |
| `skillRef.skillId` | string | `self`/`by_id` 时必填；`target` 时可省 |
| `skillRef.ofSkill` | enum | `target` 时取目标哪种技能：`active`/`channeling`/`last` |
| `clearCooldown` | bool | 剩余冷却清零 |
| `cooldownDelta` | int | 剩余冷却 ± |
| `costDelta` | {energy,cooldown,castTime} | 施法消耗（cost 三件套）±，负=减少 |
| `castTimeDelta` | int | 吟唱时长 ± |
| `setInstant` | bool | 吟唱→瞬发（castTime 置 0） |
| `targetingModeOverride` | enum | `single`/`all`/`splash_adjacent`，单体改范围 |
| `target` | effectTarget | 技能归属单位（默认 caster） |

设计要点：
- **只动实例，不动卡静态字段**。技能的 `cost`/`cooldown`/`castTime`/`reach`/`target` 仍是卡面静态定义，本原语改的是「运行期该技能实例的当前值」，符合 INV-C2（数值单点定义：Def 管默认、实例侧管运行时）。
- `selector` 封闭枚举，避免「哪个技能」歧义；`self_last` 直接对应「清除当前技能的 CD」最常见诉求。
- 与已有的 `modify_stat` 区分：`modify_stat` 改的是**单位属性**（attack/armor/...），`modify_skill` 改的是**技能的运行参数**，二者不重叠。

## 3. `modify_status`（行为层修改二）

```json
{
  "type": "modify_status",
  "statusId": "burn",
  "target": "target",
  "addDuration": 3,
  "note": "给目标身上的灼烧额外续 3 tick"
}
```

字段语义：

| 字段 | 类型 | 说明 |
|---|---|---|
| `statusId` | string | 要改写的已存在状态实例 id；`$self` 可用 |
| `target` | effectTarget | 持有该实例的单位 |
| `addDuration` | int | 剩余持续 ±（正=延长） |
| `setDuration` | int\|null | 覆盖剩余持续；null=常驻 |
| `maxStacksDelta` | int | 最大可叠加层数 ± |
| `maxStacksSet` | int | 直接设定最大层数 |
| `stacksDelta` | int | 当前层数 ±（可选，配合层数玩法） |

与既有能力的边界：
- `mount_status` 是「施加一个新状态」，支持在施加瞬间用 `durationDelta`/`maxStacksOverride`/`maxBonusDuration` 定制——但**只对「即将挂上的那次」生效**。
- `modify_status` 是「对已经挂在单位身上的实例**事后改写**」，这是此前唯一缺口。想延长已存在状态，原先只能重新 `mount_status`（refresh）或靠 `transfer_status` 的 `durationMul` 在转移时缩放——现在可直接 `addDuration`。
- 不破坏 A21（mount_status 可见/可驱散）：`modify_status` 改的就是可见/可驱散的那个实例，语义自洽。

## 4. 状态行为封锁 `disallowActions`（行为层修改三）

```json
{
  "id": "bind",
  "name": "禁锢",
  "category": ["control", "seal"],
  "dispelable": true,
  "duration": 3,
  "disallowActions": ["move", "basic_attack"],
  "note": "定身：禁止移动与普攻，但仍可释放技能"
}
```

`actionLock` 封闭枚举（不可自由拼，须登记）：

| 值 | 含义 |
|---|---|
| `move` | 禁止移动（禁用 `move` 原语 / 站位变动） |
| `basic_attack` | 禁止普攻 |
| `skill` | 禁止使用主动技能 |
| `skip` | 禁止跳过自身行动周期（强制行动） |
| `react` | 禁止反应 / 反击（封 `reactive` 类状态触发） |
| `channel` | 禁止吟唱 |

要点：
- **复用 `mount_status` 挂载**，因此天然享有 dispelable / duration / stacks / 转移（`transfer_status`）等全部既有机制——不需要为「封锁」单独造一套。
- 与 `category: "seal"`/`"control"` 是正交的：类别描述「这是什么」，`disallowActions` 描述「禁止哪些行动」，一个控制状态可以禁多个行动、一个行动可被多类状态禁。
- 引擎侧需要一份「行动许可表」：单位结算某行动前，检查其身上所有状态的 `disallowActions` 并集。这是内核新增逻辑（不在 JSON 表达层），属实现欠账，登记为 frameworkFlag 候选。

## 5. 数据现状与试点建议

- 当前 22 份技能池 **0 处**使用三个新能力（这是框架补盲，不是回填数据）。
- 试点职业建议：
  - `modify_skill` → **reader（读者）/ monster（怪物）**：读者有「抄录/模仿敌方技能」的设定，最适合做「清敌方技能 CD」「敌方吟唱转瞬发反制」；怪物 `wheel_of_fate` 已用 `op:swap` 做过资源交换，可顺手验证 `modify_skill`。
  - `modify_status` → **savant（通识者）/ apothecary（药师）**：层数/持续玩法密集（毒、增益），最需「续层/续时」。
  - `disallowActions` → **warrior（战士）/ prisoner（囚犯）**：已有大量 `control`/`seal` 类状态（shackle、cage、beast_form），把「禁移/禁普攻」从隐式 disable 升级为显式 `disallowActions` 最自然。

## 6. 校验器登记（已做）

- `docs/json/schema/skills.schema.json`：`effect` 联合类型新增 `effModifySkill`/`effModifyStatus`；新增 `actionLock` 枚举；`statusDef` 新增 `disallowActions`。
- `docs/json/validate.py`：`PRIMS` 注册 `modify_skill`/`modify_status`；新增 `ACTION_LOCKS`/`SKILL_SELECTORS`/`EFFECT_TARGETS` 枚举与对应校验；`statusDefs` 循环校验 `disallowActions`。
- 两个校验器 **errors=0**（结构 22 文件 / 语义 828 卡）。

## 7. 待办（实现侧欠账，非 JSON 表达层）

1. 内核实现「行动许可表」：结算 move / 普攻 / 技能 / 跳过 / 反应 / 吟唱前，取单位状态 `disallowActions` 并集判定。
2. 技能实例运行期参数容器：当前技能是卡静态字段，需新增「实例层覆盖」结构以承载 `modify_skill` 的 delta/override。
3. `skillRef.selector=target` 的解析：需定义「目标单位当前/最近技能」的运行时引用协议。
4. 上述三项建议登记 frameworkFlags（`landed:false`），待内核实现后翻转。
