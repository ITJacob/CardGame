# 召唤物参数

> 召唤单位（unitDef）的定义权威：种类归属（unitType 枚举）、属性基线（H1 四参）、技能模型、克制承载。
> 召唤行为本身（spawn 原语参数族、落位、模板语义）的权威在 `效果参数.md` §1.1；召唤位上限 summon_cap 在 `编队参数.md` §1.1b。
> 本文档不重复它们，只回答「召唤出来的是什么」：有哪些单位、各是什么种类、什么属性、会什么、被谁克制。

## 〇、一句话结论

召唤物是 **unitDef 蓝本 + spawn 实例参数** 的合成体：种类由 `unitType` 封闭枚举（12 值）判定，属性走「unitDef base × spawn 段比率（hpRatio/atkRatio）」，技能走三模式（蓝本自带 / 模板继承 / 白板纯战力），克制不加新原语——走 `damage_mul.filter.unitType` 乘区 + `target_unit_type` / `target_is_summoned` 谓词。

**边界**：

- unitType 是**编目层（unitDef）属性**，不是 Unit 运行时字段；运行时判定走 filter/谓词层（`编队参数.md` §1.2b）。filter.unitType 的 schema 侧保持开放 string，本文档为值域权威。
- **编目落点（2026-10-01 Def 编目独立化批）**：unitDef 集中于各途径 skills.json 顶层 `unitDefs` 池（同途径多卡共享），原卡级内联字段已撤；Catalog 快照时随文件整体入编目。
- 跨途径复用同一 unitId（wraith：收尸人/耕种者；relic/homunculus：囚犯/通识者）时**种类恒定**，差异只许出现在 spawn 实例参数上（见 §二裁定）。
- 召唤物身份判定走 filter `isSummon`（实现侧），不设 StatusDef 身份状态——与「身份状态途径私有」口径一致，不另立 taunt 式身份。

## 二、属性：H1 基线四参落地

**合成公式**：`最终属性 = unitDef base（按 unitType 基线档） × spawn 段比率`。比率缺省 = 1.0（即按 base 原值出场）。

**裁定（2026-10-01）**：`hpRatio` / `atkRatio` 是 **per-spawn 实例参数**，不是 unitDef 属性；同 unitId 跨卡/跨途径比率不一致（wraith 70%/50%、relic 60%/40%、homunculus 有/无）属正常定价差异。**二者冲突时以 spawn 段显式值为准**，unitDef base 只兜底缺省段。

**unitType 基线档（⚠️D 全表待平衡期逐条审批）**：

| unitType | hp 基线 | atk 基线 | reach | 亡语载荷默认 | 已定锚点 |
|---|---|---|---|---|---|

## 三、技能：单位技能模型三模式

召唤物的「会什么」只有三种来源，不得混出第四种：

1. **蓝本自带**：unitDef 显式声明 `behaviorSlots` / `skillSlots`（如石制壁钟的登场/碎裂推条行为、士兵的常规攻击行为）。声明了什么就有什么，没声明就没有。
2. **模板继承**：`spawn.template` = 源单位时，**属性按比例 + 完整技能组（skillSlots/behaviorSlots 快照复制）**，除非显式覆写（2026-09-04 已裁）。`inheritSkills:true` 是此模式的显式开关（观众·身份分离「继承施法者已装配技能组」依此）。动态模板 killed_unit / primary_target / holder 均属此模式。
3. **白板纯战力**：unitDef 无技能声明且无模板——只有常规攻击行为。观众·空想造物「高属性但无技能」即此模式，是白板模式的锚。

**口径**：

- 「常规攻击行为」不计入技能组——它是所有单位的默认行为槽，不占 skillSlots。
- 登场/消散载荷（on_spawn 硫磺火、亡语回血/全场伤）走 `triggers`（14 封闭触发点，`执行参数.md` §2.1），不是技能。
- 放牧体系的借技能（混沌海放牧源堡灵魂临时用提线/寄生）走规则槽/状态槽机制（`编队参数.md` slots），不是召唤物技能组的一部分。

## 四、克制：现有承载登记（不新增原语）

克制特定召唤物走三条既有承载，全部已在库：

| 承载 | 机制 | 在库实例 |
|---|---|---|
| `damage_mul.filter.unitType` | 对指定类型伤害乘区（H4 过滤族） | 战士·晨曦领域（DEMON/UNDEAD/SPIRIT 减伤）；收尸人·天然灵视/灵之主宰/亡灵权柄（SPIRIT/UNDEAD 减伤与联动） |
| `target_unit_type` 谓词 | if 条件分支按类型分道 | 收尸人·驱使亡者（UNDEAD/SPIRIT）；不眠者·安魂/灵之统帅（SPIRIT/UNDEAD，对敌方） |
| `target_is_summoned` 谓词 | 按「是否召唤物」分道（不细分种类） | 药师·灵性材料辨识（击杀召唤物回 4 能 vs 常规 2 能）；水手·海洋之歌（对召唤物追加精神伤+沉默）；秘祈人·灵肉之刃（对召唤物追加 7 物伤） |

- 退化方案：暗/不死/污秽单位预置负 `resist:holy`（`编队参数.md` §1.2b），不另立克制字段。
- flavor 未落卡：水手·闪电克亡灵（资料库 `混沌海系技能设定.md`）目前无对应卡面，平衡期出卡时挂 `filter.unitType UNDEAD` 即可。
- 自用例（非克制）：耕种者 filter anyOf [PLANT,VERMIN,CONSTRUCT] 指向己方召唤物加益；收尸人·灵之同类减伤 branch 指向己方亡灵——filter 不区分敌我，克制/加益只由方向决定。
- 克制乘区数值锚点对齐 H4 过滤族与 `数值标定基准.md` §五，不在本文档另立。

## 五、召唤参数族与边界红线

- **spawn 键名裁定（2026-10-01）**：`unitId` = 静态具名单位引用（唯一正键）；`template` = 动态模板（killed_unit / primary_target / holder）或固定蓝本 template 名（秘祈人/窥秘人系）；~~`unit`~~ 键废弃并入 unitId（schema 与数据已同批收口）。`reviveOf` 不产生新单位（复活语义，G4）。
- **summon_cap**：每施法者召唤位上限，超限 = 最早在场者自动消散（走 on_remove 消散路径，不静默拒绝，H39 已裁）。全局 summon_cap 数据几乎未铺（仅秘祈人放牧系），平衡期按途径补。
- **companionBuff**（F54 已登记）：召唤物自带增益 EffectRef[]，数据零直接使用——已登记的承载，等待首张用它的卡。
- **summonMapping**：状态层数 → 召唤强度/数量映射（罪犯仪式刻印→深渊召唤 f(N)），对象只许是具名单位，映射值覆盖 spawn 段比率时同 §二裁定（显式者胜）。
- **红线**：召唤物（有血量、占格、可被攻击）与 Zone（纯坐标效果、不占格）的判别权威在 `战场参数.md` §1 与 `战场上下文.md`——Zone 注册段不得借用 unitId 键；`first_empty` ≠ `empty_ally_slot`（`共享内核参数.md` §一）。
