# 共享内核参数与取值域

本文件收容共享内核的枚举取值域（目标系统、元素）。默认值与上下限只写在 Def，实例值只写在 Grant/params（INV-C2）。

## 一、目标系统（TargetRequest / TargetSpec）

| 字段 | 取值 | 归属 | 说明 |
|---|---|---|---|
| faction | enemy / ally / self / self_or_ally | 共享内核 | 敌方默认取对位阵营 |
| laneRef | same_lane / cross_lane / all_lanes / auto | 共享内核 | auto 在 I 节点之前由施法者上下文预处理为具体值（same_lane / all_lanes），保持流水线纯函数 |
| anchor | front_line / self / front_of_self / behind_self / cross_same_index / absolute / first_empty / taunt_source / manual / nearest_any / any_lowest_hp / self_faction_hp_desc / spawned_unit / empty_ally_slot / last_dead_ally / <指定单位> | 共享内核 | absolute 需配 fixedIndex；`first_empty` 已验证可指向空格（召唤/空坐标攻击）；`self_faction_hp_desc` 指己方阵营血量最低者；`spawned_unit` 指本次登场的新单位；`empty_ally_slot` 为己方半场空格（自身位移落点用）；`last_dead_ally` 指最近死亡的己方单位（死者寻址，配合 `spawn.reviveOf` 实现复活——耕种者最后回归之地、通识者毁灭新生） |
| scope | single_point / whole_lane / adjacent | 共享内核 | radius 已从取值域删除，改用 adjacent + spread 组合 |
| sort | none / hp_asc / hp_desc / atk_desc / index_asc / index_desc / energy_desc / armor_desc / buff_count_desc / debuff_count_desc / gauge_asc / gauge_desc / stat_max_desc / `status:<id>:asc` / `status:<id>:desc` | 共享内核 | 扩展排序键统一带 `index_asc` 确定性破平，避免为每种属性开一个 ID（H13）。`status:<id>` 为参数化状态键：按「是否持有指定状态」排序——`:asc` 持有者排后（选取降权：收尸人灵之同类、学徒守秘），`:desc` 持有者排前（优先命中：偷盗者混淆分身、仲裁人混乱感应）（2026-09-04 拍板：候选池加权走本键族，不新增 weight 字段） |
| spread | none / lane_line / splash_adjacent / splash_behind / cross_same_index | 共享内核 | —— |
| mode | unit / area | 共享内核 | —— |
| consumption | instant / zone / summon / domain / translocate | 共享内核 | mode=unit 时强制 instant 或 translocate；domain = 注册界域（战场级，不经 Placement）；translocate = 跨层位移（单位离场为 detached） |
| selectionMode | auto / manual | 共享内核 | 候选数 ≤ pickCount 时不触发玩家选择 |
| fallbackSort | 同 sort 取值域 | 共享内核 | manual 时必填（INV-E6），用于 AI / 状态触发 / 超时 |
| scope | single / all | 共享内核 | all = 全场（配合 faction 过滤 + unitType/tags 过滤 + exclude_self），不要为每种组合建一个 ID（H18） |
| filter | { unitType?, tags?, hasStatus?, hasCategory?, hpPercent?, casterHasSummon?, isSummon?, casterOwned?, adjacency? } | 共享内核 | targetSpec 参数化过滤；`adjacency` 配合 spread 表达相邻 / 溅射目标域；与候选池过滤器共用 |

## 二、元素属性

| 字段 | 取值 | 归属 | 说明 |
|---|---|---|---|
| EffectDef.element | fire / ice / poison / shock / mental / physical / water / holy / none | EffectDef | 八元素 + none；纯标签（`lightning` 否决，雷电复用 `shock`） |
| DamageCategory | physical / magic / true | 派生（编目映射表） | 只读，服务于 UI 分组与流派规约；默认不参与结算（INV-EL3） |
| element → damageCategory 映射 | physical → physical；fire/ice/poison/shock/mental/water/holy → magic；none → none | 参数层 | 映射表单点定义（`lightning` 否决，雷电复用 `shock`） |
| ResistanceSet 槽位 | fire / ice / poison / shock / mental / physical / water / holy | BaseProfile + ModifierLayer | 逐元素一槽，走 sourceId 撤销；基线建议全 0（详见编队参数）；`resist:*` 通配见编目参数 §1.3 |
| EffectCondition 元素谓词 | ElementIs(e) / ElementIn([...]) | 共享内核 | 供状态触发与流派判定 |

元素挂在 EffectDef（可被 EffectRef.params 覆写），不挂在 BehaviorTemplate 上。一次行动可产出多段不同元素的伤害；技能的"这是个火系技能"是派生：`derivedElements = union(全部 effect 的 element)`，只读、缓存、不双写。

element = poison 与"中毒"状态互不隐含：毒元素伤害不必然施加中毒状态，中毒状态的跳伤通常带 poison 元素，但那由状态本体声明。桥接一律走状态本体的触发表声明——是数据，不是代码。

## 三、效果条件谓词（EffectCondition）

条件判定统一为**带参谓词族**，不为每种比较新开一个 ID。

| 谓词 | 参数 | 语义 |
|---|---|---|
| `has_status` | `side, id, cmp, n` | 指定方是否持有某状态，且层数满足比较 |
| `has_category` | `side, categories` | 指定方是否持有指定类别的状态 |
| `hp_percent` | `side, cmp, n` | 指定方生命百分比比较 |
| `stat_compare` | `aUnit, bUnit, key, cmp` | 两名单位的指定属性相互比较 |
| `caster_has_summon` | `tag?, unitId?` | 施法者是否持有召唤物 |
| `caster_status_exists` | `id` | 施法者是否持有指定状态 |
| `zone_active` | `zoneId` | 场上是否存在指定区域 |
| `gauge_above` | `n` | 行动条进度高于阈值 |
| `dispelled_count` | `cmp, n` | 本次驱散数量比较 |
| `target_has_tag` / `target_unit_type` / `target_is_summoned` | tag / type / — | 单位标签体系谓词 |
| `dead_count` | `side, cmp, n` | 指定方已死亡单位数比较（死者存在 = `cmp: '>=', n: 1`；通识者毁灭新生、耕种者最后回归之地的条件面） |
| `field_status_count` | `id, cmp, n` | 全场（不分敌我）指定状态实例数比较（存在性 = `cmp: '>=', n: 1`；耕种者枯荣循环、罪犯恶意化身的「场上仍有人带着我的污染」） |
| `hp_percent_compare` | `aSide, bSide, cmp` | 两名单位的生命**百分比**相互比较（歌颂者：目标 HP% < 自身 HP%；与 `stat_compare` 的绝对值比较互补） |
| `gender_is` | `side, value(male/female)` | 指定方性别判定（性别约束技能的条件面） |

> 位格比较**不新增谓词**——走既有 `stat_compare(aUnit, bUnit, key: 'rank', cmp)`（判定规则见 `../params/编队参数.md` §1.4）。

## 四、候选池过滤器

目标系统级过滤器，供 `untargetable` / `untargetable_by_targeted` / 「识破」等候选池排除机制共用：

| 字段 | 取值 | 语义 |
|---|---|---|
| `direction` | `inbound` / `outbound` / `both` | 过滤方向：仅 inbound = 敌方不可选中；both = 双向；outbound = 不可选中全向排除 |
| `effectCategories` | `buff` / `heal` / `guard` / `damage` | 按效果类别分流，实现「不可被增益但可被伤害」这类非对称排除 |

**识破分支**：反向开关，参数 = 忽略隐匿 / 不可选中 × 对隐匿目标的伤害乘区。与候选池过滤器同出口，不另立机制。
