## 一、crossPathway 枢纽状态白名单（地基）

### 1.1 StatusDef 新增字段（见 `编队参数.md` §1.1b）

| 字段 | 类型 | 归属 | 语义 |
|---|---|---|---|
| `crossPathway` | boolean | StatusDef | 枢纽状态跨系可读标志。`true` 时该状态可被**非本途径**的友方技能读取（combo 卡依赖此标志 + `participants` 白名单） |
| `participants` | PathwayId[] | StatusDef | 跨系读取白名单：列出可读取本状态的途径 id。未列入的途径即便 `crossPathway:true` 也不可读 |

### 1.2 运行时读取规则

```
combo 卡读友方 X 的 state S 合法 ⟺
    S.def.crossPathway == true
    AND S.def.participants.includes(caster.pathway)
    AND X 当前对该目标持有 S 的实例（StatusInstance 存在且未过期）
```

## 二、隐秘值维度 (secrecy)

- **层级**：战场级属性 `board.secrecy ∈ [0, 10]`，独立于力/敏/智/灵/体/魅六维。
- **写入方（累计 +1/次 的"愚弄/隐秘/conceal"类效果）**：源堡三途径（占卜家/学徒/偷盗者）+ 永暗之河（不眠者/收尸人/战士）+ 暗影世界（囚犯/罪犯）+ 混沌海（秘祈人）。
- **阈值档（数值 ⚠️D）**：
  - `≥4`：场上所有 `puppet_string` 每回合 +1 层（提线轴直接受益）。
  - `≥7`：友方「愚弄 / 隐秘 / conceal」类技能 **+50%**（见乘区挂钩）。
  - `=10`：触发「**源堡共鸣**」——本回合所有带 `puppet_string` 的目标可被任意友方（含跨源质）操控一次。
- **乘区挂钩（核心待落地项）**：结算层新增乘区 `secrecy_mul`。
  - 触发条件：`board.secrecy ≥ 7` 且 技能 tag ∈ {愚弄, 隐秘, conceal}。
  - 效果：`final = base × 1.5`（系数 ⚠️D）。
  - 落点：效果结算层（效果上下文）读取 `board.secrecy`，与既有 `damage_mul`/`damage_taken_mul` 同乘区加算（参照 `编队参数.md` H4）。
- **验收**：愚者 §六 #20（🟡）、收尸人 §六 #20（🟢）、不眠者/战士 §六 对应项。

## 三、秩序度维度 (order) + 规则槽 Rules[3]

- **秩序度**：战场级 `board.order ∈ [0, 10]`。仲裁人推高、律师压低，双向改写全场规则强度。
- **规则槽**：共享棋盘 `Rules[3]`（容量 3 的数组槽位）。各系造物/规则可登记入槽：
  - 通识者「造物入规则槽」：`mount_status(rule_slot, {slot:auto, content: construct})`。
  - 律师「规则槽改写」：`modify_rule_slot(slot, {field, op, value})`（改 trigger / 转 punish / 加 exempt / 换对象）。
- **算子**：
  - `modify_order(delta)` → 战场属性。
  - `modify_rule_slot(slotIndex, patch)` → 共享棋盘。
  - `read_rule_slot(slotIndex)` → 结算引用（通识者造物 payoff 读取）。
- **验收**：仲裁人/律师 §六 秩序度与规则槽项（🟢）。

## 四、命运值维度 (fate_value)

- **层级**：战场双极 `board.fate_value ∈ [−10, +10]`。**怪物专用写入**，他人（占卜家/偷盗者/刺客/不眠者）可触发读取——怪物为「命运总线」调度方。
- **阈值档（⚠️D）**：
  - `≥ +5`：我方好运类 payoff 放大（赐福 ×1.3、赢家免死阈值 4→3）；敌方厄运叠层 ×2。
  - `≥ +8`：命运总线满载——怪物可远端调度一次命运（减费 / 强制判定生效）。
  - `≤ −5`：反噬——怪物施法后自身挂 `厄运` 确定性 debuff（非伤害，R5 合规）。
  - `= ±10`：命运洪流 / 命运债务——终焉卡全屏改写。
- **枢纽状态 `命运`(fate)**：标 `crossPathway:true`，白名单 怪物/占卜家/偷盗者/刺客/窥秘人（§一.3）。
- **验收**：怪物 §六 命运值项（🟢）、窥秘人「命运删除」combo。

## 五、恶欲值维度 (lust)

- **层级**：**单位级** `unit.lust ∈ [0, 10]`（注意：非战场级，挂在单位身上，与 secrecy/order/fate 不同）。
- **流动**：罪犯产（推高）/ 囚犯消（消纳转诅咒链接）/ 律师拧（腐蚀扭曲）/ 仲裁人审判（超度清零）。
- **阈值档（⚠️D）**：`4–6` +20% / `7–9` +50% 伤害乘区；失控风险随层数上升。
- **枢纽状态 `恶欲值`(lust)**：标 `crossPathway:true`，白名单 罪犯/囚犯/律师/仲裁人。
- **验收**：罪犯 §六 恶欲值项（🟢）、囚犯「厄缚汲取」、律师「恶欲共鸣·改」。

## 六、月相节拍器 (moonphase)

- **层级**：母巢系**内部**节拍器，五相 `moonphase ∈ {满, 血, 银, 红, 缺}`，每 tick 推进。
- **串轴**：药师/耕种者四轴按当前月相触发不同 payoff（满→增益、血→吸血、银→净化、红→爆发、缺→蓄力）。
- **算子**：`moonphase.advance()`（调度上下文每 tick 调用）、`on_moonphase(phase, effects)`。
- **跨系**：默认不跨系；除非特定 combo（暂无）。
- **验收**：药师/耕种者 §六 月相项（🟢）。

## 七、万能接口

### 7.1 放牧 Grazing（混沌海 · 全局唯一跨系借技能）

- **数据结构**：`grazing_slot` 存储「任意途径灵魂 → 其能力引用」的动态槽。
- **算子**：`graze(unit)`（存入灵魂）、`release_grazed(skillRef)`（释放其能力）。
- **枢纽状态 `grazing_slot`**：标 `crossPathway:true`，白名单 混沌海五途径（观众/歌颂者/阅读者/水手/秘祈人）内部互读；外部经放牧接口借能（如观众「放牧·借能」、水手「放牧·借雷」）。
- **检定/净化语义**：放牧释放的灵魂可被「净化」克制（收尸人 `净化` 反制）。

### 7.2 集众 Gathering（灾祸之城 · 全局唯一团队接口）

- **数据结构**：团队资源池 `massing_pool`（共享，跨单位累加）。
- **算子**：`gather(contribution)`（写入池）、`draw_from_pool(ally, amount)`（友方抽取）。
- **枢纽状态 `集众 massing`**：标 `crossPathway:true`，白名单 猎人（写入）/ 母巢（兽群可读）。
- **验收**：猎人 §六 集众项（🟢）、耕种者「兽群指挥·改」、药师「兽群指挥·改」。

## 九、软引用缺口的裁定结论（2026-09-13 拍板）

> 两项来自全库一致性审查，属「术语借位」而非硬错误。均已裁定，**引擎侧同步落地**；技能稿以此为准回溯校准。

### 9.1 `亡灵` / `undead` / `spirit` → 走既有类型标签体系（两层），**不作 StatusDef**

**裁定**：亡灵不建 StatusDef、不进 crossPathway 白名单，而是拆成 §1.2b 已有的**两层**表达：

| 层 | 载体 | 何时用 | 运行时可否增删 | 读取谓词 |
|---|---|---|---|---|
| **主类** | `Unit.unitType ∈ { UNDEAD, SPIRIT }` | 本体就是亡灵/灵体（收尸人召唤物、不死单位） | **否**（定义层恒常） | `target_unit_type` |
| **细类** | `Unit.tags ∋ 'undead'` | 运行时被施加/剥离的亡灵属性（诅咒、转化、超度） | **是**（string[]，可增删） | `target_has_tag` |

**理由**

1. **零新增机制**：`unitType` + `tags` + 两个谓词在 §1.2b 里都已存在，不需要为亡灵发明任何东西；这也是当初设计双层类型体系的目的。
2. **本体属性 vs 施加关系**：一个单位是亡灵，是它**是什么**（主类）；而"被诅咒成亡灵""被超度掉亡灵属性"是**发生在它身上的事**（细类）。把所有情况塞进 StatusDef 会把这两件不同的事混为一谈。
3. **避免驱散/净化边界污染**：做成 StatusDef 会让它可被 purge / 驱散，等价于"把亡灵驱散成活人"，与设定和 INV-P7 打架。改成 tags 后，增删是**显式的 unit 属性写操作**，不经过状态驱散管道。

**连带结论（重要）**

- "带关系的衍生语义"（被奴役、被寄生、秘偶操控）**才**挂 StatusDef 并按需要标 `crossPathway:true`——它们是关系，不是类别。
- **超度类能力的正确写法**：`仲裁人·安魂审判` 的「清除 `undead/spirit` 标签」按本裁定即 **删 `tags` 中的 `undead` + 清 `奴役` 类关系状态 + 施加 `revive_blocked`**；**不得**改写 `unitType`（那是定义层，改了就无法回放对齐）。该稿现有措辞"清除标签"与本模型天然一致，无需返工。
- §1.4 表中该行已改为指向本节的处置说明。

### 9.2 `filth`（污秽）→ 在罪犯侧**显式登记**为 StatusDef

**裁定**：罪犯污秽轴显式登记 `filth` 状态并标 `crossPathway:true`，`participants: [罪犯, 耕种者, 怪物]`；`侵蚀` / `中毒` / `深渊之咒` 降级为**施加该状态的三种来源**，不再是被引用的目标术语。

**理由**

1. **给耕种者的引用一个根**：`秽土净化` 读 `filth` 目前是术语借位，若内核不登记就是死链；显式登记后才能走 §1.2 的合法读取判定。
2. **来源与目标分家**：多个来源挂同一记账状态，消费方只读一个名字——这正是 §1.3 枢纽状态的设计意图，反过来能省掉"每加一种施加方式就改一遍消费方"的耦合。
3. 已同步登记进 §1.4 扩展共享状态表。
