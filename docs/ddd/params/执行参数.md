# 执行参数与取值域

本文件收容执行上下文（含行为/状态交互）的枚举取值域。技能示例值（火球术、旋风斩、烈焰风暴等）属示例，已从参数层剥离，不在此列出。

## 一、行为枚举

| 字段 | 取值 | 归属 | 说明 |
|---|---|---|---|
| Behavior.trigger | active / passive | BehaviorTemplate | 主动 / 被动 |
| passive_hook | on_apply / on_remove / on_tick / on_turn_start / on_turn_end / on_battle_start / on_spawn / on_death / on_kill / on_attack / on_weapon_equip / on_active_skill / on_take_damage / on_deal_damage / on_phase_change / on_status_gain | BehaviorTemplate | 被动触发钩子，共 16 个，取值域与语义见 §2.1 |
| BehaviorTemplate.castTime | 非负整数（tick） | BehaviorTemplate / SkillDef.init | 吟唱时长，0 = 瞬发；>0 时提交后进入 Channel（引导），引导期可被带 `interrupt` 标志的状态打断——技能作废、资源不退（提交即承诺）；`cast_time_set` 修正聚合取最小（「免吟唱」= cast_time_set: 0） |
| BehaviorModifier.op | disable / force / energy_cost_mul / energy_cost_add / cast_time_set / cooldown_mul / target_override | StatusDef | 决策期约束算子；disable 的作用域可按行为过滤（全部 / 攻击 / 技能 / 按 consumption 类型——如禁止 domain 类技能，「回归现实」的界域锁定） |
| 聚合规则 | disable 并集 / force 并集 / mul 乘积 / add 求和 / cast_time_set 取最小 / cooldown_mul 乘积 / target_override 覆盖 | 引擎常量 | 已定；disable 优先于 force |
| RedirectRule.to | self / attacker / transfer_target / first_empty | StatusDef | 转向目标；`first_empty` = 转向至最近空坐标（occupant 为空即落空）——入射侧「闪避型转向」（怪物·水银之躯、反占卜类确定性落空）与 C7 目标改写共用同一锚点 |
| 转向优先级 | 守护 10 > 自转移 5 | 参数层 | 已定；单跳防环 |

## 二、转向（RedirectRule）说明

转向是执行期 R 节点的核心机制。守卫与守护同属一条 RedirectRule，只是选择器与来源过滤不同：

| 维度 | 守护 | 守卫姿态 |
|---|---|---|
| 受保护对象 | 一个指定单位（protectedSelector.kind = unit_ref） | 同路且 index 大于自己的全部单位（coordinate_relation） |
| 拦截来源 | 全部（sourceFilter: any） | 仅远程（sourceFilter: ranged） |

两个能力因此统一为一条机制，不必为"守卫"另造一套拦截系统。转向单跳（visited 集防环），伤害随转向走最终目标的防御，状态类效果留原目标。

**绕过转向**：`EffectRef.params.ignore_redirect: true` 时，本 Action 跳过 R 节点的转向收集（不被守护 / 守卫姿态 / 伤害转移拦截）——律师「踏月」、猎人「精准」的"必中"语义由此承载。与 `neverMiss`（H35，命中判定层面）是两个层面：一个绕过拦截，一个保证命中。

### 2.1 触发点（passive_hook）取值域

触发点是状态与被动挂载的 fire 时机。取值域封闭，共 16 个：

**载体规则**：触发器只挂在会持续存在的主体上——状态 `StatusDef.triggers`、被动 `BehaviorTemplate.hook/triggers`、武器 `weapon.triggers`、召唤物 `unitDef.triggers`、界域 `DomainDef.triggers`。**主动/召唤卡的顶层 `triggers` 不是合法载体**（一次行为没有持续监听语义）：本卡结算内的瞬时后果写效果树 `if`（如 `target_dead`），需要持续监听的写入状态/武器/召唤物蓝本。

| 触发点 | fire 时机 | 说明 |
|---|---|---|
| `on_apply` | 状态挂载到单位时 | 生命周期钩子；挂载期扣次数不在此计 |
| `on_remove` | 状态从单位卸载时 | 生命周期钩子；携带卸载原因 |
| `on_tick` | 每个 tick | 对全体持状态单位 fire；持续伤害/回复的承载点 |
| `on_turn_start` | 该单位**获得行动机会**时 | 只 fire 给本 tick 获得机会的单位，语义=自身回合开始，是「机会括号」的左端（INV-S6）。**机会随后被判 wasted 也照 fire**（被硬控 / 无可选行为 / 主动跳过）——订阅方若只要「真出手」语义，挂 `on_attack` + `on_active_skill` 而非本点。载荷 `opportunityId` |
| `on_turn_end` | 该单位**机会闭合**时 | 「机会括号」右端（INV-S6）：Action 走完 O 节点、或机会被判 wasted 时 fire，与同一次授予的 `on_turn_start` 一一配对。载荷 `opportunityId` + `consumedBy`（真实 Action id / `wasted`），订阅方按 `consumedBy` 自行区分「出手」与「空过」。承载回合末结算类效果（每回合消耗 1 层、回合末结算奖励）——不同于 `on_tick` 的时间尺度，也不同于 `on_active_skill`（后者只在真出手且非普攻时 fire） |
| `on_battle_start` | 战斗开始时，一次性 | 全局开局；不能用 `on_spawn` 表达 |
| `on_spawn` | 单位登场时 | 召唤物/增援登场会重复 fire |
| `on_death` | 单位死亡时 | fire 给死者自身 |
| `on_kill` | 击杀发生时 | fire 给**击杀者**，与 `on_death` 的接收方不同 |
| `on_attack` | 单位**发起攻击**时 | 含落空与被免疫；区别于 `on_deal_damage` |
| `on_active_skill` | 单位发动**主动技能**（`trigger: active` 且非 `basic_attack` 的行为）提交时 | fire 给技能发动者；攻击类主动技能同时 fire `on_attack`。仲裁人 decree「禁止使用技能」判定、窥秘人知识回层的承载点（2026-09-04 拍板：独立第 12 触发点，取代待拍板清单 H22 的 `on_attack + kind` 方案） |
| `on_deal_damage` | 单位造成伤害时 | 仅在真正造成 damage 后 fire |
| `on_take_damage` | 单位受到伤害时 | 被击侧钩子 |
| `on_phase_change` | 战场相位跃迁时 | 2026-09-21 新增：`clock` 跨越相位边界、或 `set_luminance` 写入覆写层时 fire。战场级监听（不隶属单位），载荷携带 `fromPhase` / `toPhase` / `cause`(advance/override)。时钟只进不退，故不存在「回退相位」事件 |
| `on_status_gain` | 单位获得状态时 | fire 给**获得者**；语义层强制 frameworkFlag 登记制（2026-09-29 采纳为封闭集第 14 成员，怪物·意外之财首个消费方） |
| `on_weapon_equip` | 单位装备武器时 | fire 给**装备者**；在实例建立后、战吼结算前 fire（2026-10-23 采纳为封闭集第 16 成员，战士·武器大师首个消费方）。替换旧武器时也 fire，`caster` = 本卡施放者 |

两条语义纪律：
触发器载荷内的 `move` 与其他 move 同纪律：一律过 G8 faction 校验（2026-09-29 裁定，刺客·羽毛般轻盈）。`on_remove` 在自然到期（reason=expired）、驱散、消耗、被顶掉时均 fire，卸载原因四值 expired / dispel / consumed / overwritten（窥秘人·末日预言的到期爆发成立）。触发器 `condition` 用既有谓词族过滤事件（如 on_deal_damage + element_is = 仅某元素伤害时 fire，观众·细微观察）。


- `on_tick` / `on_turn_start` / `on_turn_end` 的时间尺度：`on_tick` 每 tick；机会级两点按**该单位自己的行动机会**（敏捷 0 约每 5 tick，高敏捷更密）。状态内触发器挂机会级两点时，其 `duration` 必须覆盖该单位行动周期，否则改用 `on_tick`；**更稳的写法是时长直接写 `durationUnit: 'self_turn'`**（按持有者自身机会数递减，见 调度参数 §〇点五），使时长与触发器天然同尺度，不受敏捷影响。
- `on_spawn` 会在召唤物/增援登场时重复 fire，凡"战斗开始时生效"一律用 `on_battle_start`。
- `on_attack` 与 `on_active_skill` 的分工：普攻只 fire `on_attack`；非攻击主动技能只 fire `on_active_skill`；攻击类主动技能**两者都 fire**（一次行为两条事件，各自独立判定）。需要「任何主动行为」语义的订阅方同时挂两者。

**全局第三方监听：** 触发点除挂载于单位自身外，还支持不隶属于特定单位的全局监听者（战场级规则、第三方触发）。其 fire 与结算独立于任何单位的生命周期；`on_death` 的全局监听会向**持有该被动的单位** fire，与 fire 给击杀者的 `on_kill` 分属两条路径。

> ✅ **机会级触发的口径**（2026-10-15 转正）：`on_turn_start` / `on_turn_end` 在引擎侧按**该单位获得的行动机会** fire，不再用「每 5 tick 给全体广播」近似。旧广播口径下高敏捷单位收不到自己的回合开始、未出手者照样收——现已与上表语义一致；依赖它的约 45 处数据（被动 4 + 界域触发器 15 + 状态/卡面其余）随之转正，界域「`on_turn_start` + `duration: 5` 刷新」类写法不再依赖宿主周期恰好等于 5 tick。
>
> **写法偏好**：凡「每回合」语义，优先用 `on_turn_start` / `on_turn_end`，时长配 `durationUnit: 'self_turn'` 表达；「`on_tick` + `minIntervalTicks` 节流」降为最后手段（tick ≠ 回合，语义会漂移）。固定时间口径的换算基准：1 回合 = 5 tick（调度参数 §〇点五，2026-09-30 拍板）。

### 2.1b 触发器载荷主体（触发点 → 语境主体）

触发载荷（`triggers[].effects[]`）上的 `EffectRef.target` 简写在**载荷语境**下求值：先解析为「语境主体」，再按 `共享内核参数.md` §一 的 faction + scope + sort + filter 展开。语境主体由触发点决定：

| 触发点 | host（宿主） | caster（作用者） | target（受害 / 受作用方） | attacker（攻击方） | killed_unit（被击杀者） |
|---|---|---|---|---|---|
| `on_apply` / `on_status_gain` | 状态被挂载的持有者 | 施加该状态的一方 | = host | — | — |
| `on_remove` | 被卸载状态的持有者 | 该状态的施加者 | = host | — | — |
| `on_tick` / `on_turn_start` / `on_turn_end` | 持状态单位 | 该状态的施加者 | — | — | — |
| `on_battle_start` / `on_phase_change` / `on_attack` / `on_active_skill` / `on_weapon_equip` | 监听单位 | = host（武器牌施放时为卡施放者） | — | — | — |
| `on_spawn` | 触发载荷所属的单位（召唤者） | = host | 本次登场的新单位 | — | — |
| `on_deal_damage` | 造成伤害的单位 | 该状态的施加者 | 承伤方 | = host | — |
| `on_take_damage` | 承伤单位 | 该状态的施加者 | = host | 造成伤害的单位 | — |
| `on_death` | 死者 | 该状态的施加者 | 击杀者 | 击杀者 | = host |
| `on_kill` | 击杀者 | 该状态的施加者 | 被击杀者 | = host | 被击杀者 |

- **「该状态的施加者」**= 挂载该状态的那次施法的作用者（`StatusGrant.casterId`）。被动卡没有施加者，其 `caster` = host。这正是 `caster` 与 `self` 的分野：链接 / 转移 / 被动场景中「作用者」≠「触发者」。
- **缺省回退**：上表记「—」的主体在简写求值时退回 host，与「效果默认作用于宿主」同义——故 `target` 在无受害方的触发点上等于 host。
- **群体与几何简写**从 host 展开：`all_allies` / `allies_except_self` / `all_enemies` / `enemy` / `all_other_enemies` / `all_units` / `all` 的阵营取 host 阵营，`adjacent_enemy` 取宿主相邻的敌方；`splash_adjacent` / `splash_behind` 以 `target` 为原点扩散。
- **适用面**：本节口径只适用于载荷语境（`triggers[].effects[]`，含被动卡 `hook` 编译成的触发器）。技能卡自带的 `EffectRef.target` 走**卡片语境**，主体由本次 Action 决定——见 §2.1c。
- **全局监听（`global: true`）的事件源主体**：触发器把**事件源**作为 `target` 求值——`on_active_skill` 为施法者、`on_death` 为死者、`on_kill` 为被击杀者。条件过滤按事件源判定（如 `faction_is(side:"target", value:"enemy")`）；非全局触发器仍按上表。

### 2.1c 卡片语境主体（主动行为 → 语境主体）

技能卡自带的效果（`effects[]`，含 `opSequence` / `opIf` / `opRepeat` 展开出的节点）上的 `EffectRef.target` 简写在**卡片语境**下求值。主体由本次 Action 决定：

| 简写族 | 卡片语境落点 |
|---|---|
| `self` / `holder` / `status_holder` | 施法者本人 |
| `caster` | 施法者本人（主动行为中作用者即施法者） |
| `target` / `primary_target` / `same_target` | **该次选靶命中的单位集合**（`mode: unit` = pickCount 命中者；`mode: area` = 区域内全部在位单位） |
| `secondary_target` | **卡的第二组选靶**（卡级 `secondaryTargets[]`）命中集合——逐组按各自 `request` 解析（与主选靶同口径）后取并集；**未填该字段的卡回退主选靶**（向后兼容） |
| `attacker` / `killed_unit` | 卡片语境无此主体，退回施法者 |
| `all_allies` / `allies_except_self` / `all_enemies` / `enemy` / `all_other_enemies` / `all_units` / `all` / `adjacent_enemy` | 按**施法者**阵营展开（同 §2.1b 群体口径，基准换成施法者） |
| `splash_adjacent` | 以选靶命中集合内**每个单位**为原点扩散相邻域，取并集，原点自身不含在内 |
| `board` | 不寻址任何单位，仅承载战场级量表写入（落点取施法者，使 `modify_resource(secrecy/order/fate_value)` 抵达量表；见 `共享内核参数.md` §一 EffectRef.target 末条） |

- **与载荷语境的分野**：`self` / `caster` 在两语境下都落到「施法者 / 宿主」，但 `target` 不同——载荷语境是**单元素**（该触发点的受害 / 受作用方，无主体时退回宿主），卡片语境是**集合**（选靶命中者）。
- **空集即空转**：卡片语境下选靶命中为空时，效果不落在任何人身上——**不退回施法者**（否则「指定一名敌人」的卡会在无合格敌人时打到自己）。
- **节点不带 `target` 时**：效果落在该次 Action 的选靶结果上，即与写 `target` 等价；数据里 415 处显式 `target` 属重申，多用于多段效果中的二次寻址标注。
- **无语境的路径**：区域（zone）/ 跨层载荷（translocate）/ 回响（echo_last_skill）效果沿用外层落点，节点上的 `target` 不参与求值。

### 2.3 同标签连击计数器（cast_chain，2026-10-02 拍板）

施法者级计数 `caster.chain {tag, count}`：一次技能成功进入结算时，若其 `SkillDef.tags` 与施法者上一张已结算技能存在交集，则对应 tag 计数 +1；无交集（或跨回合/换 tag）则全部计数归零。计数被条件谓词 `tag_chain(tag, cmp, n)` 读取，承载同标签连击降费/增效（歌颂者圣咏连唱、猎人战阵号令、罪犯污秽连锁——机制所有权矩阵）。纯计数器、不改写行为本身；与 BehaviorModifier 的 energy_cost_mul 配合生效。

### 2.2 目标改写（target_override）

效果结算前可改写最终目标锚点。**锚点枚举同共享内核 anchor 全集（16 关键字 + <指定单位>，absolute 配 fixedIndex），不再有可用子集**（2026-10-01 补齐：原清单 7 值漏列 taunt_source 等，与总枚举漂移）。

改写为 `BehaviorModifier` 的 `target_override` 算子，聚合规则为覆盖（后者胜），单跳不递归。**层级：target_override（含嘲讽强制）> 行为显式 targetSpec > 缺省目标基准**（同路排首，见 `../params/共享内核参数.md` §一）；反制开关 = `target_override_immune`（H12 族）。

**嘲讽细则（2026-10-01 拍板）**：

- **force 语义 = 行为白名单**：被嘲讽期间仅可执行普攻，攻击类主动技能与其余技能全禁（聚合规则「disable 优先于 force」不变）。
- **嘲讽强制免疫转向**：I 节点对 taunt-forced Action 打标记，R 节点跳过转向收集——守护 / 守卫姿态 / 自转移均不可拆嘲讽（与 `ignore_redirect` 同出口）。
- **嘲讽与隐匿互斥**：嘲讽生效期间，嘲讽来源单位的 untargetable 类修饰符不生效（嘲讽 = 吸引注意，藏不住）。
- **多嘲讽源**沿用聚合规则「覆盖，后者胜」= 最近施加者胜出（施加时序在战斗记录内，确定性可复现）。
