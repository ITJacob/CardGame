### 1.2b 单位类型标签体系

`UnitDef` 统一一组标签，支撑「定向检索/克制/增益」类技能，避免为每个类型写死负抗性：

| 字段 | 取值 | 说明 |
|---|---|---|
| unitType | 主类（SPIRIT / UNDEAD / MACHINE / PLANT / VERMIN / CONSTRUCT / FLESH / DEMON / ABERRATION / ITEM …） | 主分类 |
| tags | string[] | 细分类（shadow / spirit / flesh / beast / relic …） |
| 谓词 | target_has_tag / target_unit_type / target_is_summoned | EffectCondition 配套 |
| 乘区/过滤 | 按 tag 的伤害/受伤乘区 + targetSpec 的 tag 过滤 | 与 H18 统一过滤器共用 |

退化方案：黑暗/不死/污秽单位预置负 `resist:holy`（弱圣光，legacy hack 保留）；`dark` 现已为正式元素，dark 伤害走独立 `resist:dark` 槽，可做定向减伤与检索。对称地，光/holy 单位可预置负 `resist:dark`（弱暗）。原负 `resist:shock` 随 shock 退役改为负 `resist:lightning`。

### 1.4 位格（rank）与性别（gender）

| 字段 | 取值 | 归属 | 说明 |
|---|---|---|---|
| rank | 非负整数 | AttributeSet 源属性 → BaseProfile → ModifierLayer → EffectiveProfile | 位格。可经 `modify_stat(rank, ±N)` 修正、经 `stat_compare(key: rank)` 比较；比较仅发生在同场战斗内 |
| 位格基准 | 序列 9→1、8→2、7→3、6→4、5→5、4→6、3→7、2→8、1→9、0→10 | 内容侧映射（英雄配置 / 敌方战斗配置块供给） | 仅 L0 序列基准。**L1 途径修正 / L2 遗物修正见 §1.4a**（原 ⚠️D 缺口已于 2026-09-13 补齐，具体数值仍 ⚠️D） |
| gender | male / female（可选，缺省 = 不限） | Unit（CombatSetup 传入） | 战外养成事件（如序列晋升）确定，战斗内不可变。可得性约束与效果差异走 `gender_is` 谓词，不污染核心结算逻辑 |

**位格判定规则**（拉入 / 放逐 / 置换类卡统一走这条）：

- `目标 rank < 施法者 rank` → 必定生效，且目标"无察觉"——不触发亡语、不触发反击、不触发敌方增益。
- `目标 rank ≥ 施法者 rank` → `Chance(基础值 + 状态修正)`：基础值 40%（⚠️D）；目标处于眩晕/冰冻/虚弱 +35%、狂乱/失控 +20%、Boss（位格 +2 以上）−20%。
- 合规边界：判的是"控制是否生效"（非伤害维度，R5 内）；Chance 必须登记（R3）、只在判定处读一次（R4）；目标选择本身仍零随机（R1）。写法 = 嵌套 If 链（互斥概率分支纪律见编目参数 §一）+ `stat_compare(key: rank)`。

### 1.4a 位格修正源分类与结算序列

> **为什么位格修正必须单独建模**：位格判定是**阶跃函数**——`目标 rank < 施法者 rank` 出 100%，否则骤降到 `Chance(40% + 修正)`。因此 +1 位格的价值不是"+N%"，而是**翻转一整个序列层级的判定归属**。把它当普通属性做线性堆叠会让判定体系瞬间崩坏，所以修正必须按"断点"而非"数值"管理。

**四类修正源**

| 层 | 来源 | 生命周期 | 可否经 `modify_stat` 撤销 | 供给方 |
|---|---|---|---|---|
| L0 | 序列基准（上表映射） | 恒定 | 否 | 内容侧（英雄 / 敌方配置块） |
| L1 | **途径修正表** ⚠️D | 恒定，战斗内不可变 | 否 | 内容侧，随 `UnitDef` 下发 |
| L2 | **遗物修正表** ⚠️D / 编队配置 | 战斗开始时锁定 | 否 | `CombatSetup` 传入 |
| L3 | 战斗内临时修正 | tick / 回合 / 状态持续 | 是（按 sourceId） | 效果层 ModifierLayer |

**结算公式**

```
Effective.rank = clamp( L0 + L1 + L2 + Σ L3,  0,  RANK_MAX⚠️D )
```

- L0–L2 是**不可撤销的基底**，只在 `CombatSetup` 期装配；战斗开始后没有任何 Source 能撤销它们。
- L3 逐条进 ModifierLayer，按 sourceId 撤销、按既有时序结算，**不得回写基底**——避免 Frame-Perfect 型 bug 与回放指纹漂移。
- 比较统一读双方 `EffectiveProfile.rank`（同 §1.4 既有口径，走 `stat_compare(key: 'rank')`）。

**四条设计约束**

1. **L1 / L2 默认 0。** 位格赛道由 L0 序列基准垄断；途径与遗物修正只是"特例补偿"，**不得**用来做途径强弱或遗物强度的平衡杠杆——那是伤害层与资源层的事。
2. **幅度上限 ±2（⚠️D），默认开的是 ±1。** 相邻序列差恰好是 1 点 rank，所以每 +1 就等于跨过一个完整序列层：默认只允许 ±1，触及 ±2 的必须单列并在 §1.4a 表里写明理由。
3. **不引入"位格乘区"。** 「位格条件常驻乘区」一律写成**条件**（`stat_compare` 判 true/false）而非把 rank 喂进伤害公式。同一份 rank 若同时影响判定与数值，平衡将不可控，且会越过 R5 的伤害维度边界。
4. **与九大源质维度的边界。** 隐秘值 / 秩序度 / 命运值 / 恶欲值 / 月相 / 规则槽**不得直给 rank**；它们只能通过显式效果段转成 **L3 临时修正**（如源堡共鸣 → L3 +⚠️D），并必须随该效果的生命周期撤销，防止维度与位格双重计价。

**L1 途径修正表（草稿；值全 ⚠️D）**

| 途径 | L1 修正 | 依据 |
|---|---|---|
| 全部途径（默认） | **0** | 位格赛道由序列垄断，不给没有明确理由的偏离 |
| 律师 | +1 ⚠️D | 僭越轴以位格压制为核心玩法：「上位者·威严」、身不由己门槛依赖自身高位格 |
| 偷盗者 | +1 ⚠️D | 原著序列3 欺瞒导师：「位格提升，欺骗不可被识破」 |

> 观众 / 刺客等稿虽大量使用位格判定，但那是**判定规则的消费方**，不是**自带高位格**，故不给 L1——这条要守住，否则用到判定的途径会集体通胀。

**L2 遗物修正表（草稿；值全 ⚠️D）**

| 遗物类 | L2 修正 | 依据 |
|---|---|---|
| 位格类遗物 | +1 ⚠️D，且**全队同时至多 1 件生效** | 位格遗物直接改变判定归属，强度高于任何数值遗物，必须用数量而非幅度控制稀缺 |
| 其余遗物 | 0 | 遗物不对 rank 出手；锚（`anchor`）归迷失系统，不走 rank 通道 |

**待校验项（落地时补）**

- 不变量建议：战斗内不存在写入 L0/L1/L2 的路径；`modify_stat(rank, ±N)` 必须携带 sourceId 且可被 purge / mute 撤销（与既有 `modify_stat` 纪律一致）。
- 确定性：rank 全程无随机源采样，不影响既有回放指纹。
- 平衡入口：调位格感受时改 **L1/L2 两张表**，不要改 §1.4 的判定公式。

| 一张卡预算 | ≈ 3 能量 ≈ 6 伤害 ≈ 10% 最大生命 | 三种口径等价；任一口径超标须在其他维度补偿 |

| 护甲 | 5 一档 | 护甲按 5 为最小档位增减 |
| 抗性修正 | ±10% ~ ±20% | 单卡抗性修正幅度 |

定价规则：

- 伤害技能按"能量 × 1.2"折算为伤害。
- 位移 / 控制 / 资源类技能须压低直伤——位移在"双路各 4 格 + 坍缩 + 插队"的战场结构里本身即硬资源，不可与纯伤害同价。

### 2.4 参数化状态母版

状态 / 单位 / 算子按底层机制归并为以下母版族。各途径只填参数与外观，避免状态 / 单位表随途径数线性膨胀。具体状态实例落在编目数据（catalog），不在本设计稿。

| 母版 | 覆盖机制 | 关键参数 |
|---|---|---|
| H1 召唤物基线 | hpRatio/atkRatio/reach/亡语载荷 四参 | 一条模板，各途径填数值 |
| H2 参数化复合 debuff | debuff×乘区×时长×属性 的排列 | on_tick 载荷 / damage_taken_mul / heal_received_mul / maxStacks / ramp / stackThreshold / on_remove 载荷 / contagious / spread |
| H3 参数化减伤/免伤 | 次数型免伤 | damage_taken_mul（支持 0）× charges × 触发点 × 消耗后载荷 |
| H4 过滤/条件伤害乘区 | 按途径/元素/状态/血量/caster 过滤 | filter + dynamic（按层数/计数） |
