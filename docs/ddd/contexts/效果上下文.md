# 效果上下文（Effects）

## 一、职责定位

效果上下文负责**结算**：一次效果最终如何改变世界。它把"算"和"改"分开——伤害先被算成一个纯函数结果（DamageChain），再由 O 节点依据结果去改状态。这种分离是 R 节点能预计算结算计划、O 节点只做应用的前提。

## 二、效果三件套

```
EffectDef（Catalog · 不可变）: id, type, 默认参数, 元标记（如 bypassArmor）
EffectRef（运行时引用实例）  : ref, params（覆写）, condition, target（覆盖）
Effect（执行体）             : 由 EffectDef + EffectRef.params 组合而成
```

### 效果类型族（11 类）

| # | type | 职责 | 结算落入 | 是否进通用乘区 | 备注 |
|---|---|---|---|---|---|
| 1 | damage | 造成伤害 | 效果 → DamageChain | ✅ | 已定义 |
| 2 | heal | 治疗语义地恢复池型资源 | 编队 | ❌ | A22 划界：只作用于生命类 |
| 3 | mount_status | 挂载状态 | 编队（StatusDef + StatusGrant） | ❌ | 间接（状态实例） |
| 4 | modify_stat | 写入无宿主属性修正 | 编队（StatProvenance） | ❌ | A21 划界 |
| 5 | modify_resource | 直接增减池/进度资源 | 编队 | ❌ | A22 划界：绕过一切修正 |
| 6 | move | 位移 | 战场（必须经 Placement） | ❌ | 已定义 |
| 7 | spawn | 生成单位 | 战场（Placement）+ 编队（建 Unit） | ❌ | 已定义 |
| 8 | dispel | 驱散（清状态 / 拆区域 / 解除界域） | 编队（单位）/ 战场（坐标 / 界域栈） | ❌ | A23 新增 |
| 9 | drain | 吸血（先伤后回，效果内部闭环） | 效果内部 | ✅ | A17 登记 |
| 10 | domain | 界域操作（降临 / 置换 / 英雄域注册） | 战场（Battle.domains，不经 Placement） | ❌ | 2026-09-06 拍板新增 |
| 11 | translocate | 跨层位移（拉入 / 放逐：单位离场为 detached，到期回归） | 战场（Placement）+ 编队（detached 标志） | ❌ | 2026-09-06 拍板新增 |

> 10/11 为何是独立原语而非塞进 `move` / `mount_status`：`move` 的全部语义绑定坐标与 Placement（INV-B6），translocate 的单位离场后**不持有坐标**；`mount_status` 必须有宿主单位，界域是**战场级无宿主实体**，强塞会污染驱散边界（INV-P7）。二者均不走伤害链。

### 界域六范式 → 原语映射

原著把"战斗内切换场景"写成六种范式，映射如下（投影/潜入不新增机制）：

| 范式 | 落点 |
|---|---|
| ① 降临 | `domain(op: overlay)` —— 压入上层界域栈顶 |
| ② 拉入 | `translocate(op: pull_into, duration)` —— 目标 detached N tick |
| ③ 放逐 | `translocate(op: banish, duration, returnPayload?)` —— detached + 回归时结算载荷（可含 Chance，走 R3/R4） |
| ④ 置换 | `domain(op: swap)` —— 底层与栈顶上域对换（INV-B11 的唯一出口） |
| ⑤ 投影 | `spawn(template 继承比例)` + `modify_stat.mode: to_at_most`（力量封顶）—— 不新增 |
| ⑥ 潜入 | 候选池过滤（untargetable）+ 次数型免伤（charges）—— 不新增，见 `../params/编队参数.md` §1.1b（H5/H3） |

**detached（跨层离场）语义**：被 translocate 的单位经 `Placement.remove` 离场（占位坍缩照常、不触发亡语与 on_death、不触发反击），置 detached 标志——不持有坐标、不进入任何候选池、不获得行动机会、不参与 tick 推进（Gauge / Pool / Channel / Cooldown / Status 计时全部冻结，见调度上下文）。到期后经 `Placement.insert` 于己方队尾回归，冻结状态原样续走；`returnPayload`（放逐的"时空乱流"）在回归时结算。

**位格门槛**：translocate / 置换类效果通常带位格判定条件（规则见 `../params/编队参数.md` §1.4）：目标位格 < 施法者 → 必定生效；≥ → `Chance(基础值 + 状态修正)`，R3 登记、R4 单次抽样；目标选择本身不引入随机。

### 2.1 扩展效果算子（在十一原语之上登记）

以下算子/标志均为 `EffectDef` 的新类型或既有原语的新参数（非新原语族）：

| 算子 | 落点 | 语义 |
|---|---|---|
| `status.consume(statusId, n)` | EffectDef / 状态触发 | 读取并扣减指定状态层数（计数型状态消费） |
| `transfer_status` | EffectDef | 状态搬运/复制/改写/重排，mode: move/copy/rewrite/rotate |
| `convert` | EffectDef / roster | 改判目标 faction + 替换技能组 + 套用属性模板 + 落施法者队尾 |
| `swap_resource(resource)` | EffectDef | 双向交换两名单位指定资源当前值 |
| `gauge_shuffle` | EffectDef | 行动条数值集合守恒重排 |
| `heal_invert` | StatusDef 载荷 | 持有者获得的 heal 转为等量 damage |
| `pay_hp` | EffectDef | 仅扣血，不 fire on_take_damage / 反伤 / 亡语 / 致死判定 |
| `snapshot` / `restore` | EffectDef | 全场 / 状态集合快照与回滚 |
| `echo_last_skill` | EffectDef | 重放目标上次技能（含 potency）；SkillDef 标 `authority: true` 的权柄技能不可被重放/模仿（阅读者「模仿不含权柄」，见 `../params/编目参数.md` §二） |
| `execute` / `damage.lethal: true` | damage 标志 | 处决，直达死亡结算 |
| `modify_stat.mode: set / to_at_least / to_at_most` | modify_stat 参数 | 直接置值 / 取不低于 / 取不高于（投影力量封顶） |
| `spawn` / `drain` / `modify_resource` / `move` 扩展 | 既有原语新参数 | 见 `../params/效果参数.md` §1.1 |

### heal vs modify_resource（A22）

- **heal** 是治疗语义：未来要吃"治疗加成 / 治疗减益"修正，只作用于池型资源中的生命类。
- **modify_resource** 是直接资源操作：绕过一切修正，用于支付、消耗、设定值（如"献祭 3 生命""回复 5 能量"）。
- 判别：这个数值应不应该被治疗修正影响？应该 → heal；不应该 → modify_resource。

`modify_resource` 的作用范围（A24）：Pool 的 `hp / energy / shield / armor`（当前值）；Gauge 的 `gauge.current`（击退即用此键）/ `gauge.rate`（加速减速）/ `gauge.threshold`（触发阈值），各自带钳制下限。⛔ 行动周期是派生值，禁止被 modify_stat 直接修正。

### modify_stat vs mount_status（A21）

二者在"属性修正 + 撤销"上同构（都走 StatProvenance），但宿主不同：前者无实例、不可驱散、无层数、无触发器；后者是 StatusInstance，能力全开。判别：需要被玩家看见 / 可被驱散 / 可叠加 / 带触发器或行为约束 → mount_status；纯粹的、不可交互的面板修正 → modify_stat。⚠️ 带 duration 的 modify_stat 不产生 StatusInstance，其计时由账本条目自带 remaining 负责，到期 revertBySource。

### drain 为什么是独立类型而不是术语（A17）

它的后一段（回血）依赖前一段的实际结算结果（可能被护盾吃掉、被抗性削过），编目期无法确定入参。硬塞进术语会破坏"编目期展开成扁平 EffectRef"的根基。由引擎在单个效果内部闭环：先算伤害 → 再按结果回血 → 只发一条 EffectApplied。

### dispel 的目标与边界（A23）

| 目标 | 行为 |
|---|---|
| unit | 清除 StatusInstance（按 dispelable / category / count 过滤）；不碰属性修正（INV-P7） |
| coordinate | 移除该坐标上的 Zone（"拆陷阱"） |
| domain | 解除 active 的上层/英雄界域（按 tier / dispelable 过滤）；base 层不可驱散（INV-B11），解除后下层被压制界域恢复生效 |

## 三、DamageChain（伤害链）

建模为有序的减伤阶段管道，而不是硬编码的两步。配置决定组成，顺序固定且可见。

```
DamageChain {
    stages: MitigationStage[]     // 顺序固定，配置决定组成
}

resolve(raw, attacker, defender, chain):
    cur ← raw
    for stage in chain.stages:
        cur ← stage.apply(cur, attacker, defender)
    return DamageResult { raw, stageBreakdown, final }
```

**阶段类型：**

| 阶段 | 语义 | 典型 |
|---|---|---|
| 吸收型 | 优先扣减一个消耗性资源池，扣完为止 | 护盾 / 护甲 |
| 减免型 | 线性加减（可为负 → 增伤） | 防御 |
| 抗性型 | 按防守方对本次伤害元素的抗性做修正，逐元素取槽 | 火抗 / 冰抗 / 毒抗 / 雷抗(lightning) / 精神抗 / 物抗 / 暗抗(dark) / 圣抗(holy) |
| 乘区型 | 乘性修正 | 易伤 / 坚守 |
| 穿透标记 | 跳过后续若干阶段 | DoT 穿透护甲 |
| 下限钳制 | 最终结果的下限 | 最低伤害保底 |

抗性型插在减免型之后、乘区型之前，与"防御线性减伤"是两笔独立的账，不合并成一个数。抗性阶段自带上下限钳制（避免 100% 免伤与负抗性无限放大）。

## 四、不变量（效果 · 9 条）

| 编号 | 名称 | 规则 |
|---|---|---|
| INV-D1 | 阶段顺序固定 | 减伤阶段顺序固定且配置可见，不允许在代码里散落修改 |
| INV-D2 | 结算无随机 | 伤害结算全程无随机；DamageResult 必须可由输入完全复现 |
| INV-D3 | 纯函数 | 伤害链是纯函数——不改任何状态，只产出 DamageResult |
| INV-D4 | 状态伤害隔离 | 状态来源的伤害不进通用乘区；如需进入，必须在 EffectDef 上显式开关 |
| INV-D5 | 治疗隔离 | heal 与 modify_resource 不得混用——同一次资源增加只能走其中一条路径 |
| INV-D6 | 补丁纯声明 | 界域 rulePatches 由流水线既定节点被动读取，不得引入新流水线节点、不得直接改写状态（算改分离） |
| INV-EL1 | 元素纯标签 | 元素是纯标签，自身无数值语义；语义由抗性/状态触发/流派规约赋予 |
| INV-EL2 | 元素挂 effect | 元素挂在 effect 层，不在 behavior 层；一个 Action 可产出多段不同元素的伤害 |
| INV-EL3 | 大类只读派生 | damageCategory 是 element 的只读派生，映射表单点定义于 Catalog |
| INV-EL4 | 元素不隐含状态 | 元素与状态互不隐含；poison 元素不隐式挂中毒，桥接必须显式配置 |
