# 战场上下文（Battlefield）

## 一、职责定位

战场上下文负责战斗的**空间与结构**：单位站在哪里、队列如何排布、坐标如何寻址、区域（陷阱/祝福地面）如何挂载与触发、界域（战场级规则环境）如何叠加与更替。它是纯粹的空间容器，不关心单位的属性数值，也不关心伤害怎么算。

整个战斗的占位变更只有一个出口——`Placement`。任何模块想移动、插入、移除单位，都必须经过它，不允许直接写坐标。这一约束是战场一系列不变量的基础。

## 二、核心概念

### Coordinate（坐标）
全局唯一、结构稳定的值对象，由 `(faction, lane, index)` 三元组构成。坐标不随任何单位迁移而改变，可比较、可作字典键。它是战场上一切寻址的依据。

### Slot（槽位）
一个可占位单元，持有 `occupant: UnitId | null`。空槽用 `null` 表示。

### Lane（队列）
一条线性队列（实体），持有定长 `slots: Slot[]`。`index` 从对峙线向队尾递增——`index 0` 永远是对峙前线。

### Faction（阵营）
战场的一方，持有 `lanes: Map<laneId, Lane>`。

### Battle（战斗）
空间容器实体，持有全部 `factions` 与挂载的 `zones: Zone[]`，聚集了整个坐标空间与所有区域效果。

### Zone（区域）
绑定到某个坐标的持续效果，以坐标为唯一键。陷阱、祝福地面、危险区都属于 Zone——区域不是一种"特殊的单位状态"，而是坐标版的状态。召唤物（有血量、占格、可被攻击）与区域（纯坐标效果、不占格）由这一判别规则区分。

**Zone 放置与跨半场**：Zone 落点由 `ZoneDef.coord` 决定，不依赖任何 UnitId（INV-B6）。纯伤害/减益类 Zone 可跨中线落敌方半场——G8 只约束"单位位移"，不约束区域效果。含单位位移（relocate）或生成（spawn）载荷的 Zone 落点恒为施法者己方半场，其载荷内的位移/生成同样走 Placement / EffectPipeline 的 G8 合规校验，不可越中线。

**Zone 母版（H9）**：按 `unitType` 分派 Zone 视觉/交互族；同一 ZoneDef 可携带按阵营（owner / enemy_of_owner / any）分支的双载荷，由 `ZoneGrant.affects` 推导生效分支。

### Domain（界域）

战场级的规则环境实体，与 Zone 平级但**无坐标、战场级作用域**——Zone 是"坐标版的状态"，Domain 是"战场版的规则包"。设定依据是"灵界与现实完全重叠"：切换界域**不清空战场**，已存在的单位、状态、Zone 全部保留，只是换了规则环境。

界域遵循 Definition + Grant 三件套：`DomainDef`（Catalog · 不可变）→ `DomainGrant`（值对象：duration / priority / params / sourceId）→ `DomainInstance`（运行实例），由 `Battle.domains` 持有。按 `tier` 分三层：

| tier | 来源 | 生命周期 |
|---|---|---|
| `base`（底层界域） | `CombatSetup` 以 DomainGrant 注入（塔层/Boss 决定，属主项目配置；本内核只认 Grant） | 不可驱散，仅可被「置换」（domain op: swap）对换 |
| `hero`（英雄域） | 英雄被动开局挂载（`on_battle_start` 通道） | 常驻；规则冲突优先级高于 overlay |
| `overlay`（上层界域） | 卡牌打出（domain op: overlay） | 压制栈：可多层共存，同一时刻仅栈顶 active |

## 三、Placement：唯一占位出口

所有改变占位的操作必须且只能通过 Placement。它是战场上唯一有权写 `Slot.occupant` 与 `Unit.position` 的组件。每个操作都走统一的执行模板：

1. `snapshot ← 当前 Battle 空间结构`
2. `next ← 执行变更`
3. `next ← collapse(next)`（坍缩，见下文）
4. `next ← syncProjections(next)`（刷新各单位的 position 只读投影）
5. `if !invariantCheck(next) then return snapshot, Failure(reason)`
6. `occupancyDiff ← diff(snapshot, next)`（进入/离开某坐标的单位集合）
7. `emit(OccupancyChanged(occupancyDiff))`
8. `return next, Success`

| 操作 | 前置条件 | 行为 |
|---|---|---|
| `insert(unit, coord)` | 目标 lane 未满；coord 合法 | 写入 slot → 坍缩 → 刷新投影 → 发 OccupancyChanged |
| `remove(unitId)` | 单位在场上 | 置空 slot → 坍缩 → 刷新投影 → 发 OccupancyChanged |
| `swap(a, b)` | 两者均在场 | 交换 slot → 坍缩 → 刷新投影 → 发 OccupancyChanged |
| `relocate(unit, coord)` | 目标 lane 未满；**to.faction 必须 === from.faction** | 原位置空 → 新位置写 → 双端坍缩 → 刷新投影 → 发事件 |
| `applyExternal(mutator)` | — | 快照 → 执行 mutator → 坍缩 → 校验门禁 → 通过则提交，否则回滚到快照 |

第 7 步是 Zone 触发的唯一入口——Zone 不监听"移动"这个动作，只监听"占用关系变化"这个事实。这条让击退、召唤、死亡补位、跨路移动全部自动获得区域触发能力，无需逐个特判。

`relocate` 是位移（move）类效果的唯一落点出口。己方单位不得越中线进入敌方半场：跨阵营的 relocate 直接被拒绝。

## 四、Collapse（坍缩）契约

```
collapse(Lane) -> Lane'
  取出 slots 中所有非空 occupant，保持相对顺序，从 index 0 起依次填回，其余置 null
  副作用：刷新每个被移动单位的 position 投影
```

- **幂等**：对已紧凑的 Lane 调用，结果与原值相等。
- **保序**：不改变相对顺序（队列语义）。

坍缩的目的是保证队列"无内部空洞"——占用永远是 `{0, 1, …, k-1}` 的前缀。这是战斗可读性与跨单位规则（先手、转向）正确性的前提。

## 五、Zone 生命周期

```
place(ZoneDef.id + ZoneGrant)
   │
   ▼
┌─────────┐  triggerOnExisting=true   ┌──────────────┐
│ Created │──────────────────────────►│ 结算在场单位  │
└────┬────┘                           └──────────────┘
     │（默认 false：在场者不触发）
     ▼
┌─────────┐   OccupancyChanged(enter, coord 命中且阵营匹配)
│ Active  │──────────────────────────► 逐条执行 ZoneGrant.effects（各带 condition）
└────┬────┘                            消耗 uses（若定义了，整次触发算一次）
     │
     ├── duration 耗尽 ──► Expired
     ├── uses 耗尽 ─────► Expired
     └── 被显式移除 ────► Removed
```

进入判定用 before/after 两张战场快照做 diff——凡在 after 中处于某 Zone 坐标、且在 before 中不处于该坐标者，判定为进入。坍缩导致的落入视同进入，同坐标换人（A 死 B 补位）也判定为进入。Zone 的解耦性：Zone 的坐标与生命周期均不依赖任何 UnitId。

## 六、界域生命周期与覆盖规则

**注册**（domain 原语在 M 节点结算，不经 Placement）：

| op | 语义 | 行为 |
|---|---|---|
| `overlay`（降临） | 打出上层界域 | 压入上层栈顶，原栈顶转入压制 |
| `swap`（置换） | 底层与栈顶上域对换 | 新域成为 base（不可驱散），原 base 转为 overlay（可被驱散/覆盖）；仅改层籍，不删除实例 |
| `hero`（英雄域） | 被动开局挂载 | 战斗 init 时经 `on_battle_start` 通道注册 |

**覆盖（压制栈）**：上层界域可多层共存，**同一时刻仅栈顶 active**，其余压制——不删除、不结算任何规则，且 `duration` 暂停递减。栈顶到期或被驱散后，下一层的剩余时长恢复生效。规则冲突时（同 kind 补丁指向同一对象）按优先级取舍：**hero > overlay > base**。

**消亡**：`duration` 耗尽 → Expired；被 `dispel(target: domain)` 命中 → Dispelled（仅 `dispelable` 且非 base 者）。active 集合恒为 = 底层 + 英雄域（若有）+ 上层栈顶。

**界域的两类载荷**（均声明式，取值域见 `../params/战场参数.md` §1.2）：

- `rulePatches: RulePatch[]` —— 规则改写补丁，由流水线既定节点（I 候选池 / commit 成本校验 / O 节点）**被动读取**，不引入新节点、不直接改状态（INV-D6）。交互规则（"镜像标签卡在镜中效果翻倍"）统一为带 tag 过滤的补丁。
- `triggers` —— 战场级触发器，走执行参数 §2.1 的「全局第三方监听」通道，挂 `on_tick` / `on_turn_start` 等触发点结算 EffectRef 载荷（如"全场每回合腐蚀 2 点"）。

**与 Zone 的正交性**：Zone 以坐标为键、只监听 OccupancyChanged；Domain 无坐标、不进 Placement、不触发坍缩。两者互不感知，零冲突。

## 八、不变量（战场 · 12 条）

| 编号 | 名称 | 规则 |
|---|---|---|
| INV-B1 | 容量 | `|occupied(L)| ≤ |L.slots|` |
| INV-B2 | 无内部空洞 | `occupied(L) = {0,1,…,k-1}`（必须是前缀） |
| INV-B3 | 即时紧凑 | 任何占位变更后，collapse 必须在同一原子步内完成 |
| INV-B4 | 坐标唯一 | `∀u, coordOf(u) = (f,l,i) ⟺ Battle[f][l].slots[i].occupant = u.id` |
| INV-B5 | 投影只读 | `Unit.position` 只能由 Placement 写入；其他任何模块读多写零 |
| INV-B6 | 区域解耦 | `Zone.coord` 与 Zone 生命周期均不依赖任何 UnitId |
| INV-B7 | 满则拒绝 | `isFull(L) → insert` 被拒绝（不静默丢弃，返回失败原因） |
| INV-B8 | 区域载荷 | Zone 的载荷是 `EffectRef[]`（多条、逐条独立判定），与状态的触发载荷结构对齐；整次触发只消耗一次 uses |
| INV-B9 | 界域无坐标 | DomainInstance 不持有坐标，不参与 Placement / collapse / syncProjections，不触发 OccupancyChanged（与 Zone 正交） |
| INV-B10 | 覆盖压制 | 上层界域同一时刻仅栈顶 active；被压制者不删除、不结算规则、duration 暂停递减；规则冲突优先级 hero > overlay > base |
| INV-B11 | 底层不可驱散 | base 层界域不可被 dispel；解除 base 仅允许 `domain(op: swap)` 置换 |
| INV-B12 | 跨层出入唯一出口 | translocate 的离场/回归同样只经 Placement（remove / insert）；detached 单位不持有坐标 |
