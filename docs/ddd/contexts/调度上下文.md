# 调度上下文（Scheduling）

## 一、职责定位

调度上下文负责**时间与机会**：世界怎么推进一个 tick、谁在这个 tick 获得行动机会、获得机会后哪些行为是可选可用的。它把"时间流逝"和"行动资格"两件事做成确定的、可复现的过程。

## 二、BattleClock 与 Tick

一个 tick 是一个原子步，先把世界推进到稳定态，再决定谁行动——这两步严格分离，否则会出现"单位 A 行动时 B 的资源还没恢复"这种依赖 tick 内顺序的隐蔽 bug。

```
tick():                                   // 一个原子步
    1. clock.advance()
    2. 所有 Unit 的 Gauge.advance()        // 可能发 GaugeCrossed
    3. 所有 Pool 按 regen 恢复
    4. Channel.remaining--
    5. Cooldown.remaining--
    6. StatusInstance.remaining--（到期者 unmount）；StatProvenance 带时限条目 remaining--（到期者 revertBySource）
    7. Zone 与 active 界域的 duration 递减（到期者移除；被压制的上层界域不计时）
    8. 收集本 tick 内所有 GaugeCrossed → 交由 InitiativePolicy 排序 → 依次授予机会
```

顺序纪律：推进（1–7）与授予（8）严格分离——先把世界推进到稳定态，再决定谁行动。

detached（跨层离场）单位不参与第 2–6 步：其 Gauge / Pool / Channel / Cooldown / Status 计时全部冻结，回归后原样续走。

## 三、ActionOpportunity（行动机会）

行动机会是"资格"的载体，与"资源成本"是两个独立的概念。这一拆分的核心收益是：**资格校验**和**成本校验**可以分开做。

| 字段 | 说明 |
|---|---|
| unitId | 获得者 |
| tickIndex | 授予时刻 |
| consumedBy | 被哪个 Action 消耗（未消耗则记录为 wasted） |

两条独立校验：
- **资格校验**（调度层）：是否持有未消耗的机会。没有机会就不能执行主动行为。
- **成本校验**（编队层）：Gauge 扣减量 + Pool 是否足够。资源不够则行为进不了可选列表。

```
commit(behavior):
    assert opportunity != null and !opportunity.consumed      // 资格
    assert cost.payable(unit)                                  // 成本
    unit.gauge.consume(cost.gaugeAmount)
    unit.pools.consume(cost.energyAmount)
    opportunity.consumedBy ← new Action
    → 进入执行流水线
```

默认纪律：`cost.gaugeAmount = threshold`（扣满阈值进度条），任何偏离需平衡评审。

## 四、InitiativePolicy（先手）

契约：输入本 tick 内全部 `GaugeCrossed`，输出确定性的行动序列。

```
resolveOrder(crossed):
    己方序列 ← sort(crossed.where(己方), by (lane, index))
    敌方序列 ← sort(crossed.where(敌方), by (lane, index))
    return 交替合并(己方序列, 敌方序列)     // 按既定交替模式
```

原设计踩过坑：初版按 index 分层实现，给分兵方不公平先手（22:14）。修正为"双方各自排序后交替合并"后对称性恢复，并固化为不变量防止回归。

## 五、OpportunityFilter（可选行为列表）

```
availableBehaviors(unit):
    unit.behaviorSlots
      .where(b => b.trigger == Active)
      .where(b => !b.isRedirectDisabled)        // 决策期约束：disable
      .where(b => force 集合为空 or b ∈ force)   // 决策期约束：force
      .where(b => b.cooldownRemaining == 0)
      .where(b => unit.channel == null)
      .where(b => cost.payable(unit))           // 含 energy_cost_mul / add 修正后的最终成本
```

过滤顺序固定，结果确定。

## 六、不变量（调度 · 5 条）

| 编号 | 名称 | 规则 |
|---|---|---|
| INV-S1 | 触发条件 | Gauge 触发条件为严格越过阈值（>，非 ≥） |
| INV-S2 | 先手序列 | 序列必须按双方各自排序后交替合并得出，不得按战场位置分层合并 |
| INV-S3 | 机会唯一 | 同 tick 内每个单位至多获得一次机会 |
| INV-S4 | 浪费记录 | 机会未被消耗（如无可用行为）时，明确记为 wasted，不累积到下一 tick |
| INV-S5 | 派生保护 | 行动周期是派生值（threshold / rate）；禁止被 modify_stat 直接修正（见编队上下文） |
