# 编队上下文（Roster）

## 一、职责定位

编队上下文负责**单位与挂载**：一个单位是什么、它有哪些属性与资源、身上挂了哪些状态、能执行哪些行为。它是战斗里实体最密集的一层，也是"属性修正"和"溯源账本"所在之处。

编队上下文不关心单位站在哪个坐标（那是战场的事），也不关心一次攻击的流水线怎么走（那是执行的事）。它只回答：给定单位当前状态，它的有效攻防是多少、它还有多少血、它身上某个状态该不该触发。

## 二、Unit

Unit 是聚合内的实体，持有自身全部可变与派生状态：

| 字段 | 类型 | 说明 |
|---|---|---|
| id | 标识 | 战斗内唯一 |
| faction | 值对象 | 所属阵营 |
| gender | 枚举（male / female，可选，缺省不限） | 战外配置（CombatSetup 传入）；战斗内可被 `gender_shift` 改写——性别约束技能的条件面 |
| attributes | AttributeSet | 配置的唯一源头（属性点） |
| baseProfile | BaseProfile | 由属性点按公式派生的基础面板，战斗内不可变 |
| modifiers | ModifierLayer | 全部属性/资源修正的集合 |
| effectiveProfile | 派生（缓存） | baseProfile 应用 modifiers 后的有效值，脏时重算 |
| gauges | Map | 进度型资源（如行动条） |
| pools | Map | 池型资源（生命 / 能量 / 护盾…） |
| statuses | StatusInstance[] | 挂载中的状态 |
| behaviorSlots | BehaviorSlot[] | 可执行的行为（含单位级覆写） |
| skillSlots | SkillSlot[] | 可用技能引用 |
| channel | Channel \| null | 进行中的引导 |
| cooldowns | Map | 各行为的冷却剩余 |
| position | Coordinate（只读投影） | 由 Placement 单向同步，禁止其他模块写入 |
| provenance | StatProvenance | 本单位的属性写入溯源账本 |

## 三、属性三层模型

属性不是"一个值"，而是一条派生链。把修正独立成层，是为了让任何属性都能被持续修正并按来源撤销，而不需要在属性本身里塞撤销逻辑。

```
AttributeSet ──公式──► BaseProfile ──┐
                                     ├──► EffectiveProfile（有效值）
   modifiers（修正集合）─────────────┘
                    ▲
                    │ 写入 / 回滚
              StatProvenance（溯源账本）
```

| 层 | 可变性 | 说明 |
|---|---|---|
| AttributeSet | 战斗内不可变 | 属性点是配置，战斗中不改 |
| BaseProfile | 战斗内不可变 | 由属性点派生一次，缓存 |
| ModifierLayer | 可变 | 修正条目集合，每条带 sourceId |
| EffectiveProfile | 派生 + 缓存 | 写入/回滚修正时失效缓存，下次读取重算 |
| ResistanceSet | 派生 + 缓存（逐元素） | 每个元素一个抗性槽；基础值在 BaseProfile，增减走 ModifierLayer，按 sourceId 撤销 |

**关键设计：抗性不是一个特殊属性。** 它走与攻防完全相同的三层模型与同一份 StatProvenance，只是按元素分槽（六个元素 → 六个槽）。这样"冰抗 -30% 持续 3 回合"和"攻击 +5"是同一种修正，撤销逻辑零新增。

位格（rank）同样走这套三层模型：`AttributeSet` 源属性 → BaseProfile → ModifierLayer（可经 `modify_stat` 修正、按 sourceId 撤销）→ EffectiveProfile。位格比较读取双方 EffectiveProfile.rank，仅发生在同场战斗内（基准值与判定规则见 `../params/编队参数.md` §1.4）。

## 四、资源：Gauge 与 Pool

资源分为两类，语义迥异：

| 维度 | Gauge（进度条） | Pool（资源池） |
|---|---|---|
| 语义 | 累积到阈值就触发一件事 | 一个可以被增减的量 |
| 字段 | current, rate, threshold, overflowPolicy | current, min, max, regen |
| 变更后果 | 越过阈值 → 发领域事件 + 按策略扣减 | 数值变化；触底/触顶可发事件（如死亡） |
| 典型 | 行动条 | 生命、能量、护盾 |
| 关键性质 | 是"资格"的来源 | 是"成本"与"状态"的载体 |

```
Gauge.advance(tick):
    current += rate
    if current > threshold:                  // 严格大于，非等于
        emit(GaugeCrossed(unit, gauge))
        overflow = current - threshold
        current = (overflowPolicy == Keep) ? overflow : 0
```

"严格越过而非等于"是固定下来的不变量：行动资格的判定必须发生在阈值被跨过的那一 tick，而不是恰好停在阈值上。

Gauge 可被效果修改（开放三维度）：经 `modify_resource` 的三个键——
- `gauge.current`（当前进度，击退即用此键）
- `gauge.rate`（累积速率）
- `gauge.threshold`（触发阈值）

各自带钳制下限。**但行动周期 = threshold / rate 是派生值，禁止被 modify_stat 直接修正**——要改周期就改上面两个源属性之一。这是防止"偷偷改派生值导致一致性破裂"的硬约束。

迷失值（lost）是挂在英雄单位上的特殊 Pool：战斗内累积——卡面以显式 `modify_resource(lost, +N)` 段付租金，引擎无隐式累积；`regen = 0`，只增不减，清零靠「回归现实」类卡的 set 0；越档经 `thresholdTrigger` 挂载惩罚状态。锚（anchor，战外遗物配置）在 CombatSetup 期提高 Pool.max 与各档触发值，战斗内无独立机制。取值与档位见 `../params/编队参数.md` §2.5。

## 五、StatProvenance 溯源账本

溯源账本是属性写入的一等实体，记录"每一项修正来自谁"。溯源键是 `StatusInstanceId`（实例 ID，不是类型 ID），因此同种状态的两个实例各自记账、各自撤销，互不干扰。

| 操作 | 说明 |
|---|---|
| `apply(stat, newValue, sourceId)` | 写入永久修正；记录 `(stat, oldValue, sourceId)` 并返回句柄（remaining = null） |
| `applyTimed(stat, newValue, sourceId, duration)` | 写入带时限修正；条目自带 remaining，由 tick 递减，到期自动 revertBySource |
| `revertBySource(sourceId)` | 按来源回滚全部条目（状态到期 / 被驱散 / 光环移除 / 时限耗尽 / 单位离场时调用） |
| `revertAll()` | 清空本单位全部修正（单位离场） |
| `entriesOf(stat)` | 审计视图：某项属性的全部修正来源 |

## 六、状态三件套（Definition + Grant）

状态遵循通用模式：`StatusDef`（定义）→ `StatusGrant`（实例参数）→ `StatusInstance`（运行实例）。

| 角色 | 内容 |
|---|---|
| StatusDef（Catalog · 不可变） | id, category、触发表 TriggerDef[]、行为约束算子 BehaviorModifier[]、转向声明 RedirectRule、defaultDuration、maxStacks、stackPolicy、dispelable；**扩展字段族见 `../params/编队参数.md` §1.1b**（charges / immune / lethalProtect / damage_mul / heal_received_mul / heal_output_mul / durationModifier / moveImmune / gaugeReductionImmune / neverMiss / buffBlocked / statPerStack / formGroup / slots / casterId / contagious·spread·ramp / suppress·untransferable / silent_immune·ignoreDispelable / immune_stat_reduction / revive_blocked·dot_cannot_kill·damage_cap / summon_cap / maxTriggersPerBattle / thresholdTrigger / on_remove reason 等） |
| StatusGrant（值对象） | duration、stacks、强度参数 params、sourceId、特殊绑定 binding（守护目标 / 转移目标） |
| StatusInstance（运行实例） | instanceId、defId、grant 副本、remaining、currentStacks、已解析绑定 |

> ⚠️ **触发点纪律（G15-b）**：`on_turn_start` 在单位**行动开始**时 fire（约每 5 tick 一次，敏捷 0），与每 tick 都 fire 的 `on_tick` 不同。状态内若用 `on_turn_start` 作触发器，其 `duration` 必须 ≥ 该单位行动周期（建议按"N 个自身回合 × 5 tick"标注），否则改用 `on_tick`，否则触发器一次都碰不到。

**挂载流程（含叠加）：**

```
mount(defId, grant):
    existing ← 找本单位同 defId 的 Instance
    if existing == null:
        inst ← new StatusInstance(instanceId = newId(), defId, grant)
        inst.remaining ← clamp(grant.duration ?? def.defaultDuration, 0, 上限)
        inst.currentStacks ← clamp(grant.stacks ?? 1, 1, def.maxStacks)
    else:
        if existing.currentStacks < def.maxStacks:
            existing.currentStacks += grant.stacks
        existing.remaining ← max(existing.remaining, grant.duration)   // stackPolicy = refresh
    emit(StatusMounted | StatusRefreshed)
    触发 def.triggers 中 event == on_apply 的条目（产出 Action）
```

**销毁流程（含撤销）：**

```
unmount(instanceId, reason):     // reason: Expired | Dispelled | UnitLeft | Consumed
    触发 def.triggers 中 event == on_remove 的条目（若定义）
    provenance.revertBySource(instanceId)      // 恢复到写入前的值，而非"减去写入量"
    移除 instance
    emit(StatusExpired | StatusDispelled)
```

> **on_remove 自续链合法化（2026-09-04 确认）**：`on_remove` 载荷允许重新挂载同一 defId（含挂载自身）——重挂载产出**全新实例**（新 instanceId、溯源独立、remaining 重置）。防无限循环：同一单位同一 defId 的 on_remove 重挂载**每 tick 至多 1 次**。怪物途径「5 技能周期引擎」依此合法化。

**状态对战斗的两类贡献（二者正交，一个状态可同时携带）：**

- **(a) 触发型**：事件命中 → 产出 Action → 走流水线（由 `StatusDef.triggers` 声明）
- **(b) 声明式约束**：挂载期间被流水线特定节点被动读取，不是 Action（`BehaviorModifier` → 流水线前；`RedirectRule` → R 节点）

## 七、BehaviorSlot / SkillSlot 与套件解析

```
BehaviorSlot {
    instanceId
    templateId          // ref -> BehaviorTemplate
    reach               // Melee | Ranged | None —— 攻击类行为的属性
    overrides           // 单位级覆写（成本 / 冷却 / 引导 / 目标规格 / 效果清单 / reach）
    cooldownRemaining
}

SkillSlot { skillDefId }   // ref -> SkillDef
```

套件（职业默认携带的行为集合）由 Catalog 侧的领域服务 `resolveKit(ClassDef)` 解析：未声明 kit 的职业自动继承全局默认套件；引擎全程不特判任何具体行为键，`basic_attack` 与任何自定义行为在调度器眼里无差别。

## 八、Channel 与 Cooldown

| 概念 | 字段 | 说明 |
|---|---|---|
| Channel | sourceInstanceId、remaining、resolvedTargets（点火时已解析并冻结）、pendingEffects、interruptible | 延时结算；提交即已占机会、已扣资源 |
| Cooldown | behaviorInstanceId、remaining | 从提交时刻起算（引导期与冷却重叠） |

```
submit(castTime > 0)
   ▼
┌───────────┐  tick 递减   ┌────────────┐
│ Channeling│─────────────►│ remaining=0│──► 结算 pendingEffects → Completed
└─────┬─────┘              └────────────┘
      │ 硬控命中 且 interruptible
      ▼
  Interrupted（清 channel、效果作废、资源不退）
```

纪律：打断只作废效果，不退资源——提交即承诺。

## 十、死亡结算链（复活优先级）与状态触发器原语

单位生命触底进入 Dying 时，按以下链逐项判定，命中即短路、不再向下：

1. `revive_blocked`：存在该标记 → 禁止任何复活（含 on_death 复活与 substitute 压制），直接走死亡结算。
2. `defined_substitute`：存在替身/替死实体压制 → 由替身接管死亡，本体不入死亡流程。
3. `lethal_protect`：存在该保护 → 阻止致死，生命钳制在 1（不进入 Dying，不触发 on_death）。
4. `on_death` 复活：否则进入 Dying → 触发 on_death → 若载荷含 revive（spawn + `reviveOf`）则复活，否则离场。

`lethal_protect` 与 `dot_cannot_kill` 共用一个死亡结算插桩，以 `trigger: 'any' | 'dot'` 区分（任意致死 vs 仅 dot 致死）；`damage_cap` 为独立截断机制（限制单次伤害值，不阻止死亡），二者不复用参数。

**状态触发器内执行非状态原语（H43）**：状态触发表（`triggers`）的 Action 不限于状态类载荷，可声明非状态原语——`mount_status` / `unmount_status`（状态触发器挂载/卸载另一状态）、`move`（状态触发器施加位移，受 G8 约束：跨阵营 relocate 直接拒绝，落点恒为合法己方坐标）。禁止在状态触发器中绕过 Placement 直接写 `Slot.occupant`。

## 十一、攻击类型（reach）与姿态（stance）

**站位、reach、目标选择三者正交**——这是编队/执行层最重要的澄清：

| 维度 | 属于 | 决定 | 不决定 |
|---|---|---|---|
| Coordinate（站位） | 战场 | 单位在队列中的物理位置 | 攻击方式 |
| reach（近战 / 远程） | 攻击类行为的属性 | ① 是否触发同步对撞 ② 是否可被拦截 | 能打哪些坐标 |
| targetSpec | 行为的属性 | 能选哪些坐标（含排序与选择模式） | 攻击方式 |

"近战"描述的是交战方式（贴身互搏、双方同时受伤），"打哪个坐标"由 targetSpec 独立决定。因此刺客「越过最前一个单位打其后方单位，且算近战伤害」是自然的组合——只需在该行为的 targetSpec 里用 `absolute + fixedIndex` 指定目标坐标，reach 仍为 Melee，越位攻击照样触发对撞，不需要新增任何机制。

| reach | 目标对攻击者同时造成伤害 | 可被守卫姿态拦截 | 典型 |
|---|---|---|---|
| Melee | ✅ 是 | 否（直接交锋） | 战士普攻、刺客越位突袭 |
| Ranged | ❌ 否 | ✅ 是 | 远程普攻、投射类技能 |
| None | — | — | 非攻击类行为（加甲、治疗、召唤…） |

**守卫姿态**是一种状态（挂在单位上、有持续时间、可被移除），分类为 `stance`。硬控（stun）命中时清除目标身上的全部 `stance` 状态。设计要点：用"分类驱动"批量行为，而不是在眩晕里枚举要清除哪些状态——每加一种姿态都要回头改眩晕配置，否则就是玄学 bug。

## 十二、不变量（编队 · 9 条）

| 编号 | 名称 | 规则 |
|---|---|---|
| INV-P1 | 溯源唯一 | 每个 sourceId 在单位上全局唯一（是实例 ID，不是类型 ID） |
| INV-P2 | 撤销语义 | revertBySource 必须把属性恢复到该来源写入前的值，而非"减去写入量" |
| INV-P3 | 账本对应 | 账本条目与 ModifierLayer 的修正条目一一对应，不存在无主修正 |
| INV-P4 | 离场清理 | 单位离场时 revertAll() 必须被调用（否则修正泄漏到对象池复用时） |
| INV-P5 | 姿态清除 | 硬控（stun）命中时清除目标身上全部 category == stance 的状态 |
| INV-P6 | reach 正交 | reach 与 targetSpec 正交：reach 不得限制可选坐标范围 |
| INV-P7 | 驱散边界 | dispel 只作用于 StatusInstance；modify_stat 写入的属性修正不可被驱散，只按 duration 到期回滚 |
| INV-S5 | 派生保护 | 行动周期是派生值（threshold / rate）；禁止被 modify_stat 直接修正，只能改 gauge.rate / gauge.threshold 源属性 |
| INV-B8 | 区域载荷 | Zone 的载荷是 `EffectRef[]`（多条、逐条独立判定），整次触发只消耗一次 uses |
