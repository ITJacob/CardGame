# 执行上下文（Execution）

## 一、职责定位

执行上下文负责**动作与流水线**：一个行为从被点燃到落地的完整过程。它把"决策期"（选目标、算成本）和"动作期"（结算伤害、挂状态）物理隔离，保证流水线是一个可测试、可缓存、可复现的纯函数段。

## 二、ActionSource 薄接口

所有"会产出一个 Action 的东西"——主动行为、被动触发、状态触发——都统一在 `ActionSource` 薄接口之下，只共享这个契约与产物类型（Action），不共享生命周期管理。未来加装备/地形/光环触发，流水线零改动。

```
ActionSource {
    ignition    : Commit(消耗机会+扣资源) | EventTrigger(不消耗)
    targetSpec  : TargetSpec | null
    effects     : EffectRef[]
}
```

| 来源 | ignition | 说明 |
|---|---|---|
| BehaviorSlot（主动） | Commit | 玩家/AI 选定 |
| BehaviorSlot（被动） | EventTrigger | 绑定 passiveHook 事件 |
| StatusInstance | EventTrigger | StatusDef.triggers 命中 |

## 三、Action 实体

| 字段 | 可变性 | 说明 |
|---|---|---|
| id | 不可变 | 唯一标识 |
| sourceRef | 不可变 | 来源（行为实例 / 状态实例 / 技能定义） |
| caster | 不可变 | 施法方快照 |
| opportunityId | 不可变 | 消耗的机会（EventTrigger 时为 null） |
| committedTargets | 不可变快照 | I 节点产出，此后不再修改 |
| behaviorContext | 不可变 | 决策期约束聚合结果 |
| finalTargets | 增量写入 | R 节点产出 |
| redirectLog | 追加 | 每次转向的审计 |
| settlementPlan | 增量写入 | 逐最终目标的结算计划 |
| consumption | 不可变 | instant / zone / summon |
| outcomes | 追加 | 每个效果的落地结果 |

**核心纪律**：`committedTargets` 是干净快照，动作期干预只能在它之上做增量改写，绝不回写。决策期与动作期因此物理隔离。

## 四、流水线四节点契约

| 节点 | 输入 | 输出 | 读取状态 | 职责 |
|---|---|---|---|---|
| I 目标解释 | caster + targetSpec | committedTargets: ResolvedTarget[] | 战场坐标空间、施法方状态 | 可被 target_override 覆盖 request |
| R 动作期干预 | committedTargets | finalTargets + settlementPlan + redirectLog | 目标方及其友军的状态 | 目标归属 + 结算计划 |
| M 消费分流 | finalTargets + consumption | 三条路径之一 | — | 无 |
| O 结果应用 | 路径 + effects | outcomes + 领域事件 | 每条效果的 condition | 单位/战场状态 |

### I 节点（目标解释：拆为「候选池 → 收缩」两段）

**I-1 · 候选池**
1. 解析 targetSpec.request 中的上下文相关项（如 laneRef 的"自动"）→ 具体值，在 I 节点之前由施法者上下文预处理
2. 按 faction 确定扫描阵营；按 laneRef 确定扫描路线
3. 按 anchor 解析锚点坐标；按 scope 圈定候选坐标
4. 每个坐标附当前 occupant 快照 → `ResolvedTarget{coord, occupant}`
5. 产出 `CandidatePool { targets, stateVersion, pickCount, selectionMode, fallbackSort }`

**I-2 · 收缩（依据 selectionMode）**

| 模式 | 行为 |
|---|---|
| Auto | 按 sort 排序 → 截 pickCount → committedTargets |
| Manual | 候选数 ≤ pickCount → 全取，不打断玩家；候选数 > pickCount → 等待玩家选择输入；无玩家在场时走 fallbackSort |

要点：
- 产出物是坐标，occupant 仅是该坐标在结算时刻的租客，可以为 null（空坐标是合法目标——召唤依赖此）。
- 候选为空时返回空集合，上层跳过而非抛异常。
- `stateVersion` 用于提交时校验战场是否发生变动。

**Manual 的确定性兜底（必须）**：`fallbackSort` 必填。原因——状态触发与被动行为产生的 Action 没有玩家在场（自动点火），若此时遇到 Manual 目标规格且无兜底，结果将依赖未定义行为，直接违反随机性铁律。`fallbackSort` 同时服务三种场景：AI 决策 / 状态与被动触发 / 网络对战超时。附带纪律：候选数 ≤ pickCount 时不弹选择，避免出现"只有唯一合法目标还要玩家点一下"的无效交互。

### R 节点（动作期干预：转向 + 结算计划）

职责明确为：解析转向 + 生成逐目标结算计划。它**不**执行结算。

```
for each original in committedTargets:
    candidates ← 收集 original 自身的 RedirectRule
               ∪ 收集其存活友军中 guardTarget == original 的 RedirectRule
    winner ← 取 priority 最高者（同优先级按既定默认序）
    final ← resolveTarget(winner)               // self | attacker | transfer_target
    if final ≠ original:
        redirectLog.append({from: original, to: final, rule, priority})
    单跳：final 不再二次触发其自身 RedirectRule（visited 集防环）
    if 涉及伤害:
        settlementPlan[original] ← computeDamage(使用 final 自己的护甲与减伤)
finalTargets ← 去重后的所有 final
```

### M 节点（消费分流）

| 模式 | 行为 |
|---|---|
| instant | 对 finalTargets 中每个 occupant 非空者，进入 O |
| zone | 对每个 coord 注册 Zone（ZoneDef.id + 由 effects 翻译出的 ZoneGrant） |
| summon | 取 occupant == null 的坐标，落位新单位 |

### O 节点（结果应用）

```
for each effect in effects:
    for each target in pathTargets:
        if !condition.evaluate(target): continue      // 逐目标判定（可"群攻只烧残血"）
        outcome ← executeEffect(effect, target)
        outcomes.append(outcome)
        emit(EffectApplied)
```

## 五、Action 状态机

```
   ignite(Commit | EventTrigger)
        ▼
   ┌──────────┐   castTime == 0   ┌────────────┐
   │ Created  │──────────────────►│  Resolving │
   └────┬─────┘                   └─────┬──────┘
        │ castTime > 0                   │ I → R → M → O
        ▼                                ▼
   ┌───────────┐  引导完成         ┌──────────┐
   │ Pending   │─────────────────►│ Resolved │
   └───────────┘                  └──────────┘
```

## 六、近战同步对撞

近战类攻击结算时，双方在那一刻彼此同时造成伤害（被攻击者未丧失还击能力的前提下）。

**建模为「反作用动作」而非给每个单位配被动**：把它做成引擎级结算规则，但复用 `ActionSource` 抽象产出一个同型的 `Action`（MeleeClash），好处是——复用流水线（对撞伤害走完整 I→R→M→O，自动获得转向、减伤、条件过滤）、可被状态干预（眩晕 disable 掉还击能力 → 自动不触发）、审计可见（Action 带 sourceRef = melee_clash，回放可区分）、防环（on_take_damage 不再二次触发）。

**触发条件**：行为的 `reach == Melee` ∧ 主目标存在且存活 ∧ 主目标未被剥夺还击能力（眩晕/同类硬控） ∧ 主目标够得着攻击者。首批不校验可达性（近战一律对撞），可达性校验作为扩展点保留。

**「同步」的执行语义（关键）**：
1. 主结算：计算 caster → target 的伤害结果（纯函数，不改状态）
2. 对撞结算：计算 target → caster 的伤害结果（纯函数，不改状态）
3. 同时应用两条结果

对撞不能中断主攻击：即使第 2 步算出攻击者会被对撞致死，第 1 步的伤害仍然结算——因为二者发生在同一刻。这是"同步"一词的实际含义，也是它与"先攻后反击"的根本区别。对撞伤害属行为伤害，正常进入通用乘区（区别于状态来源伤害不进乘区）。

## 七、不变量（执行 · 9 条）

| 编号 | 名称 | 规则 |
|---|---|---|
| INV-E1 | 转向单跳 | 转向单跳，用 visited 集防环 |
| INV-E2 | 伤害随转向 | 伤害随转向走（用最终目标的防御）；状态类效果留原目标 |
| INV-E3 | 群攻独立 | 群攻 = N 条独立结算链，不是"一次算总再分摊" |
| INV-E4 | 反向防环 | on_take_damage 触发的 Action 不再二次触发 on_take_damage |
| INV-E5 | 快照不可变 | committedTargets 不可变，干预只做增量 |
| INV-E6 | 兜底必填 | selectionMode == Manual 必须定义 fallbackSort；状态/被动触发只能走 fallback |
| INV-E7 | 对撞同步 | 近战对撞同步结算：对撞致死不中断主攻击 |
| INV-E8 | 对撞乘区 | 对撞伤害属行为伤害，正常进入通用乘区（区别于 INV-D4 的状态伤害） |
| INV-E9 | 版本校验 | 候选池提交时校验 stateVersion，不一致则重算候选池 |
