## 1. 方法：从「手写 modifier」里读需求，而不是拍脑袋

`statusDefs[].modifiers` 是**刻意开放**的结构（SCHEMA.md §9：谓词与修正维度在持续扩展，封闭会阻碍内容生产）。但开放也意味着——**凡是设计者反复手写、却没有原语背书的键，就是事实上的缺失原语**。

全库统计：**122 种手写键 / 累计 495 次使用**。按「同一语义的拼写数量 × 总次数」排序，缺口一目了然：

| 语义 | 手写拼写（次数） | 种数 | 合计 | 结论 |
|---|---|---:|---:|---|
| 揭示 / 穿透隐匿 | `pierceConceal`4 `revealToSource`3 `seeThroughStealth`3 `detectConceal`2 `reveal_stealth`2 `detect`2 `concealRevealBlock`2 `revealConcealment`1 `reveal`1 `concealReveal`1 `concealPiercedForCaster`1 `concealInvalidForCaster`1 `seeConceal`1 `detectMirrored`1 | 14 | ~26 | ⚠️ 一个概念造了 14 个名字 → 强烈缺口 |
| 不可被选为目标 | `untargetableByTargeted`29 `untargetable`2 `untargetableByAll`1 | 3 | 32 | ⚠️ 最大单一缺口（含已知候选池过滤） |
| 免疫 | `immune`11 `gaugeReductionImmune`5 `movePierceImmune`1 `immune_stat_reduction`1 `targetOverrideImmune`1 | 5 | ~19 | ⚠️ 缺口（statusDef.immune 仅 2 处，覆盖不住） |
| 可驱散性覆盖 | `dispelableOverride`5 `outgoingDispelOverride`3 `dispelableOverwrite`2 `dispelOverride`2 `runtimeDispelOverride`1 `dispelParams`1 `runtimeDispelLock`1 `contractDispelLock`1 | 8 | ~16 | ⚠️ 应补进刚落地的 `modify_status` |
| 目标优先级 | `targetOverride`7 `targetPriority`2 `targetPriorityLowest`1 `targetPriorityToSummons`1 `candidateWeight`1 `excludeCasterTargeting`1 `ignoreFrontline`1 `ignoreGuardIntercept`1 `ignoreRangeRestriction`1 `ignoreRedirect`1 | 10 | ~17 | ⚠️ 候选池过滤缺口 |
| 行为封锁 | `moveImmune`18 `action_nullify`4 `disable`3 `disableSkills`2 `disableAllActions`1 `excludeFromActionOrder`1 | 6 | ~29 | ✅ 已被 `disallowActions` 覆盖（待回填） |
| 层数上限 | `stackCapOverride`2 `maxStacksOverride`1 `fortuneMaxStacksBonus`2 | 3 | 5 | ✅ 已被 `modify_status.maxStacks*` 覆盖 |
| 施法消耗 | `energyCostAdd`1 `energyCostMin`1 | 2 | 2 | ✅ 已被 `modify_skill.costDelta` 覆盖 |
| 持续时间增幅 | `durationModifier`12 | 1 | 12 | 🟡 半覆盖（见 §2.9） |
| 禁止获得增益 | `buffBlocked`5 `buffUndispellable`1 | 2 | 6 | 🟡 中 |
| 伤害分担/转移 | `damageShare`2 `damageTransfer`1 `damageRedirect`1 `lethalRedirect`1 `redirect`1 | 5 | 6 | 🟡 中（link 类别已有，缺建立手段） |
| **阵营夺取** | —（仅 `control_undispellable`1 无关） | 0 | 0 | ⚠️ **完全空白** |

另有卡面语义扫描（describe/lore/note 关键词）佐证需求分布：

| 概念 | 总次数 | 主要途径 |
|---|---:|---|
| 操控/支配 | 72 | fool(10) spectator(8) hunter(7) prisoner(6) chanter(5) |
| 预知/命运 | 50 | monster(15) supplicant(6) fool(5) thief(4) |
| 免疫/不受 | 47 | prisoner(6) hunter(5) criminal(4) lawyer(4) arbiter(3) |
| 规则改写 | 41 | lawyer(11) arbiter(7) hunter(4) fool(3) |
| 链接/共享 | 24 | fool(5) lawyer(4) apprentice(3) |
| 揭示/识破 | 22 | spectator(4) fool(3) hunter(3) pryer(3) |
| 窃取/夺取 | 21 | **thief(19)** ← 几乎独占 |
| 额外行动 | 18 | lawyer(3) apprentice(2) pryer(2) sleepless(2) |
| 复制/模仿 | 14 | **reader(7)** ← 模仿轴 |

**这三条交叉验证极强**：
1. `moveImmune`(18) / `stackCapOverride` / `energyCostAdd` 恰好对应我刚落地的三个能力 → 说明**方向是对的**，只是这些需求此前只能在开放字段里裸写。
2. 「窃取」21 次里 thief 独占 19，而 thief 的构筑轴就叫 🜁**窃取** → 语义与途径完全对齐，却没有对应原语。
3. 阵营夺取 = 0，但「操控/支配」被提到 72 次 → 全靠 `target_override`（改目标）+ `gaugeRateMul:0`（定身）勉强凑，**没有真正的控制权转移**。

## 2. 候选新原语清单（按证据强度分档）

### Tier 1 — 证据充分，建议优先落地

#### 2.1 `modify_targetability`（目标可选性）｜证据 32 次 / 3 拼写
改单位的「可被选为目标」属性，带方向（对谁不可选）与持续。
```json
{ "type":"modify_targetability", "target":"self", "untargetable": true,
  "direction":"enemy_targeted", "duration":3, "pierce":"none" }
```
字段：`target`(effectTarget) `untargetable`(bool) `direction`(all/enemy_targeted/enemy_aoe/ally) `duration` `pierce`（谁能看穿：none/source/all）。
> 当前 `untargetableByTargeted` 只能写在状态里且无校验；升格后可被 `dispel` 按类驱散、可被 `reveal` 穿透，形成闭环。

#### 2.2 `reveal`（揭示 / 穿透隐匿）｜证据 ~26 次 / 14 拼写
```json
{ "type":"reveal", "target":"all_enemies", "scope":"to_source", "dispel": false }
```
字段：`target` `scope`(to_source/to_all) `dispel`(bool，是否顺带驱散隐匿) `pierceTargetability`(bool)。
> ⚠️ 与既有能力的关系要说清：**纯驱散**可用 `dispel(filter.category=[conceal])`（已有 5 处）。但「只对施法者显形」「看穿但不驱散」没法表达，这才是 14 种拼写想做的事。

#### 2.3 `grant_immunity`（授予免疫）｜证据 ~19 次
```json
{ "type":"grant_immunity", "target":"self", "against":["control","fear"],
  "element":"fire", "charges":1, "duration":4 }
```
字段：`target` `against`(statusCategory[]) `element` `damageType` `charges` `duration`。
> 现状：`statusDef.immune` 只有 **2 处**（chanter.fearless、hunter.iron_courage），要靠「先定义一个带 immune 的状态再 mount」才能授予——写一次状态成本太高，所以设计者直接在 modifiers 里裸写 11 次。

#### 2.4 `take_control`（夺取控制权 / 阵营翻转）｜证据：完全空白，但「操控/支配」72 次
```json
{ "type":"take_control", "target":"primary_target", "duration":5,
  "onExpire":"revert", "note":"秘偶化：目标 5 tick 内视为己方" }
```
字段：`target` `duration` `onExpire`(revert/die/keep) `actionPolicy`（是否可放技能/普攻）。
> **这是最大的空白**。现有 53 个 control/retarget 状态，实现手段只有三招：`target_override`（强制改目标）、`gaugeRateMul:0`（定身）、`untargetableByTargeted`（不可选）。**没有任何手段让一个单位真的转为己方阵营行动**。

#### 2.5 `steal`（窃取）｜证据 21 次，thief 独占 19
```json
{ "type":"steal", "target":"primary_target", "what":"skill",
  "ofSkill":"last", "grantTo":"caster", "charges":1 }
```
字段：`target` `what`(skill/resource/status/stat) `ofSkill` `grantTo` `resource` `charges` `duration`。
> 边界：资源窃取已有 `drain`、状态窃取已有 `transfer_status`（mode copy/rewrite）。**真正缺的是「窃取技能」**——拿走敌方一个技能自己用。

#### 2.6 `modify_rule`（战场规则补丁）｜证据 41 次，lawyer 11 / arbiter 7
```json
{ "type":"modify_rule", "scope":"battle", "rules":[
  {"kind":"heal","allowed":false,"duration":5} ],
  "durationUnit":"tick" }
```
字段：`scope`(battle/domain/lane) `rules[]`(kind/allowed/mul) `duration` `durationUnit`。
> 现状：`domainDef.rulePatches` 已能做规则补丁，但**绑死在界域内**。战场级/单路级规则改写（禁治疗、伤害反转、普攻禁止）无处表达。

### Tier 2 — 有价值，建议次轮

#### 2.7 `grant_action`（额外行动）
证据 18 次提及 + `excludeFromActionOrder`1 / `extraSpawn`1。字段：`target` `count` `immediate`(bool)。
#### 2.8 `link`（建立链接：伤害/治疗/状态共享）
证据 ~6 次（damageShare/damageTransfer/damageRedirect/lethalRedirect/redirect）。`link` 类别已存在，缺「建立」手段。字段：`targets`[] `share`(damage/heal/status) `ratio` `duration`。
#### 2.9 `delay`（延迟结算）
证据 0（空白）。字段：`effects`[] `ticks` `condition`。用于「注定降临」「延时陷阱」。
#### 2.10 `rewind`（回溯）
证据 4 次提及。现状 `snapshot`/`restore_snapshot` 需**手动成对**书写且无时间轴概念。字段：`target` `ticks` `fields`(hp/gauge/status/position)。
#### 2.11 `block_gain`（禁止获得增益/减益）
证据 `buffBlocked`5。字段：`target` `category`[] `duration`。
#### 2.12 `modify_status.dispelableOverride`（补字段，非新原语）
证据 ~16 次 / 8 拼写。**直接给刚落地的 `modify_status` 加一个布尔字段即可**，性价比最高。

## 3. 不该加的（避免重复造轮子）

| 直觉上想加 | 为什么不必 |
|---|---|
| `reveal` 的「驱散隐匿」部分 | `dispel(filter.category=[conceal])` 已覆盖（5 处在用） |
| 层数上限修改 | 已由 `modify_status.maxStacksDelta/Set` 覆盖 |
| 改能量消耗 | 已由 `modify_skill.costDelta` 覆盖 |
| 禁止移动 | 已由 `disallowActions:["move"]` 覆盖（原 `moveImmune` 18 处待回填） |
| 伤害倍率 | 本就该是状态 `modifiers`，不是原语（`damage_taken_mul` 74 次是正确用法） |

### ⚠️ 该做的是「命名治理」而不是加原语
`modifiers` 里同义异写严重，应先建**白名词表**再谈升格：
- 受伤倍率：`damage_taken_mul`(74) / `damageTakenMul`(8) / `damageTakenBonus`(2)
- 造成伤害：`damage_mul`(62) / `damageMul`(2) / `damageDealtMul`(1) / `damageDealtMulPerStack`(1) / `damageDealtMulVsConcealed`(1) / `damageBonus`(1) / `damage_mul_2`(1)
- 揭示隐匿：14 种拼写（见 §1）

建议：把 `damage_taken_mul`/`damage_mul` 定为唯一规范拼写，其余列为别名并在 `docs/tools/validate.py` 加**别名告警**（不阻断，渐进收敛）。

## 4. 原著途径映射（哪条途径最契合）

依据：各途径构筑轴主题 + 原著 22 途径能力设定。

| 新原语 | 🎯 最契合途径 | 原著/设定依据 |
|---|---|---|
| `take_control` | **fool（愚者·🜃秘偶）** ★★★ | 愚者途径的核心能力就是**秘偶化**——把他人躯体化为秘偶操纵。当前 53 个 control 状态竟无一处真控制权转移，这是对愚者最大的亏欠。次选：spectator（观众·🜂暗示，心理操控）、corpse_collector（收尸人·🜃亡者，驱使尸体） |
| `steal` | **thief（偷盗者·🜁窃取）** ★★★ | 错误途径的本命就是窃取、欺诈、寄生、时命。「窃取」21 次里 thief 独占 19，轴名即答案。次选：reader（阅读者·🜃模仿，抄录敌方能力） |
| `modify_rule` | **lawyer（律师·🜄扭曲规则）** ★★★ | 黑皇帝途径的权柄就是**扭曲规则、钻规则空子**；规则改写 41 次里 lawyer 占 11。次选：arbiter（仲裁人·🜄律令，审判途径制定律令） |
| `reveal` | **pryer（窥秘人·🜁窥秘）** ★★★ | 隐者途径即窥探秘密、识破隐藏。次选：spectator（🜁洞察）、hunter（🏹收割，追踪猎物）、chanter（🜂圣光，光下无所遁形） |
| `grant_immunity` | **prisoner（囚犯·🜍诅咒）** ★★★ | 被缚者途径以抗性/诅咒见长；免疫 47 次里 prisoner 占 6。次选：hunter（`iron_courage` 已有先例）、chanter（`fearless` 无畏，太阳途径净化）、warrior（黄昏巨人·🜂守护） |
| `modify_targetability` | **sleepless（不眠者·🗝隐秘）** ★★★ | 黑暗途径掌隐秘与噩梦，藏于暗影不可被锁定。次选：apprentice（学徒·🜁开门，藏入异空间 `hidden_space`）、assassin（刺客·🜄形）、apothecary（药师 `stealth`） |
| `grant_action` | **thief（偷盗者·🜄时命）** ★★★ | 错误途径窃取「时间」，抢一个额外行动最贴题。次选：monster（怪物·🜄循环）、apprentice（🜁开门，空间捷径） |
| `link` | **fool（愚者·🜃秘偶）** ★★★ | 秘偶与本体共享伤害/感知，是本命机制。次选：supplicant（秘祈人·🜃牧魂）、lawyer（🜃贿腐，利益绑定） |
| `rewind` / `delay` | **monster（怪物·🜄循环）** ★★★ | 命运之轮掌幸运与循环，「回溯」「灾厄注定降临」皆其权柄；预知/命运 50 次里 monster 独占 15。次选：fool（🜁预知）、criminal |
| `block_gain` | **criminal（罪犯·🜂污秽）** ★★★ | 深渊途径的污秽侵蚀阻断一切增益。次选：supplicant（🜄秽堕） |

### 综合：哪条途径受益最大？

**🥇 fool（愚者）** —— 一口气吃到 3 个原语：`take_control`（秘偶化，本命能力当前竟无法表达）、`link`（秘偶共享）、`rewind`/`delay`（历史与预知）。愚者的四条轴里，**秘偶轴是目前亏欠最严重的**：它想做的是「操控他人」，而现有 53 个 control 状态只能做到改目标/定身/不可选。

**🥈 thief（偷盗者）** —— `steal` 是其存在的意义，`grant_action`（窃取时间）再加一层。

**🥉 lawyer（律师/黑皇帝）** —— `modify_rule` 就是它的权柄，现有 `domainDef.rulePatches` 绑死界域，根本撑不起「扭曲规则」。

## 5. 建议实施顺序

1. **先做命名治理**（零风险，立刻见效）：`docs/tools/validate.py` 加 modifiers 别名告警，把 14 种 reveal 拼写、damage 倍率拼写收敛。
2. **补 `modify_status.dispelableOverride`**（一个布尔字段，覆盖 16 次手写需求，性价比最高）。
3. **落地 Tier 1 四件**：`modify_targetability` / `reveal` / `grant_immunity` / `take_control` —— 这四个覆盖了 32+26+19+0 的硬缺口，且恰好对应 sleepless / pryer / prisoner / fool 四条途径的本命能力。
4. **`steal` + `modify_rule`** 单独立项（语义最重，需与 `drain`/`transfer_status`/`domainDef.rulePatches` 划清边界）。
5. Tier 2 按需。

> 落地纪律（沿用既有约定）：**先改 `skills.schema.json` → 再改 `docs/meta/SCHEMA.md` → 同步 `docs/tools/validate.py` 枚举白名单 → 两校验器 0 错**，最后才回填数据。
