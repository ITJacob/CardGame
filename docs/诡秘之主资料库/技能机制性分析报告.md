# 卡牌技能设计 · 机制性诊断报告

> 分析对象：`../analysis/SKILLS_OVERVIEW.md`（22 途径 / 773 张卡）、`card game总设计.txt`（DDD 战斗内核）、`诡秘之主职业路径与能力对照表.md`\
>     分析目标：回答"职业内构筑不明显 / 职业间联动太少"的根因，并给出可落地的改造方向\
>     判定口径：用脚本对 773 张卡的机制 AST（`机制` 字段）做了结构化扫描，数字见文末附录

---

## 〇、结论速览（先看这个）

| 维度 | 现状数据 | 结论 |
| --- | --- | --- |
| 职业内"自堆叠引擎"（enabler→payoff 状态链） | **9 / 22 途径有，13 / 22 平铺** | 多数职业没有成型构筑内核 |
| 4 个构筑轴的厚度 | 多条轴仅 **3–4 张卡**（兽群4 / 灵视3 / 讼辩4 / 蛮力4 / 阴谋4 / 愤怒4 / 猎魔5 / 牧魂5 / 隐秘5） | 薄轴撑不起一个套牌原型 |
| 跨职业"类型钩子"（指向 undead/spirit/foul/dark/conceal） | **14 / 773 张（1.8%）**，且 15/22 途径为 0 | 跨职业联动几乎不存在 |
| "跨途径共享" 181 张（23.4%） | 实为**同一张卡复刻进两个池子** | 是复用，不是联动 |
| 同名状态被多途径共用 | 易伤(13途径)/护盾(11)/枷锁(7)/提线木偶(4)/寄生(thief+supplicant)/诡秘(sleepless+warrior)/厄运(monster+sleepless) | **联动的"地基"已存在但完全没被设计利用** |

一句话：**构筑轴是"内容标签"而非"机制钩子"，真实构筑藏在未对外暴露的状态堆叠里；跨职业联动则停留在复刻卡，内核虽已支持统一状态目录却没有任何卡去引用别家招牌状态。**

## 一、为什么"职业内构筑不明显"

### 根因 1：4 个构筑轴只是元数据标签，没有 payoff 卡去"奖励扎堆"
每张卡只挂一个轴符号（如 `🜄药剂`），但**没有任何一张卡读取"你本场施放了 N 张该轴卡"或"你身上有该轴层数"来放大效果**。轴与轴之间是并列的独立效果，不构成"流派"。

以 `apothecary`（药师）为例，它的 4 个轴分布是 `药剂11 / 兽群4 / 血月7 / 月相12`：

- "药剂"卡：治疗4、治疗3+再生、预服药水(攻防buff)、无味香水(净化)、隐身药剂——彼此互不咬合，只是"都是治疗/辅助"的归类。

- 整条途径没有任何自堆叠引擎（扫描结果：引擎状态为空）。玩家走"药剂流"得到的 11 张卡，没有任何一张会因为"你堆了药剂"而变强。

> 对比有引擎的途径（`monster` 幸运层数、`sleepless` 夜色/沉眠/梦陷、`apprentice` 记录层数）：它们的构筑感来自**状态层数被多张卡共同累积并消费**，而不是轴标签。也就是说——**真正的构筑机制和你贴的 4 个轴是脱节的**。

### 根因 2：多条轴太薄，撑不起"套牌原型"
一份可玩的流派通常需要 6–8 张卡形成"起手→铺垫→爆发"的节奏。但扫描显示大量轴只有 3–4 张：

| 途径 | 最薄的轴 | 该轴卡数 |
| --- | --- | --- |
| apothecary | 兽群 | 4 |
| corpse\_collector | 灵视 | 3 |
| arbiter | 辖区 | 7（但讼辩、蛮力在 lawyer 侧） |
| lawyer | 讼辩 / 蛮力 | 各 4 |
| hunter | 阴谋 | 4 |
| sailor | 愤怒 | 4 |
| warrior | 猎魔 / 黄昏 | 5 / 6 |
| supplicant | 牧魂 | 5 |
| fool | 预知 | 8（但时命仅 6） |

薄轴 + 无引擎 → 玩家在这些职业里很难感知到"我在走某条路线"。

### 根因 3：旗舰卡（238 张）没有承担"轴心"职责
全库有 238 张旗舰卡，但它们大多只是"数值更大的同类效果"，而不是**把整条轴串起来的枢纽**。一个合格的旗舰应当：消费本轴累积的资源、并给后续卡提供平台（如展开界域 / 给全队挂本轴增益）。当前旗舰卡多数缺这条"收束"作用。

## 二、为什么"职业间联动太少"

### 根因 1："跨途径共享"是复刻，不是联动
181 张共享卡的真实形态是 **`**跨途径共享**：planter** 这类标注——同一张卡原样出现在两个职业池里（如 `药剂调配\` 同时挂在 apothecary 和 planter）。这是**内容复用\*\*，玩家抽到它时只感受到"这张卡我也有"，不会触发任何跨职业配合。它把"共享率 23.4%"这个表面数字撑得很高，却对联动零贡献。

### 根因 2：真实的跨职业钩子极少且零散
全库只有 **14 张卡**的机制里包含跨职业类型钩子（指向 `undead/spirit/foul/dark/conceal` 等单位标签）。它们是真正能联动的卡，例如：

- `chanter` 日照/神圣之光：对 `undead/foul/dark` 标签 ×1.5（圣光克死灵）

- `corpse_collector` 驱使亡者：对 `UNDEAD/SPIRIT` 挂提线木偶

- `sleepless` 安魂/灵之统帅：对 `SPIRIT/UNDEAD` 延长/控制

- `sailor` 雷击：对 `undead/spirit` 追加电击

但**15 / 22 途径一张都没有**，且这些钩子都是"我单方面打某种单位更狠"，是**单向克制**而非**双向配合**（没有"友军制造了 undead，我因此增益"这类搭档逻辑）。

### 根因 3：内核已支持统一状态目录，却没人写"引用别家招牌状态"的卡
DDD 内核里 `StatusDef` 是**独立聚合、全局共享目录**（`StatusInstance` 由 `StatusDef → StatusGrant → StatusInstance` 生成）。这意味着只要两条途径共用同一个状态名，A 途径挂的状态 B 途径就能读——**机制上零成本**。扫描也证实大量同名状态已被多途径共用（见第三节）。但**没有任何一张卡被设计成"读取另一条途径的招牌状态来触发效果"**。联动的通道是通的，只是没车在跑。

## 三、好消息：跨职业联动的"地基"已经铺好（未被利用）
扫描发现这些**同名状态被多条途径共用**，它们就是天然的"跨职业 lingua franca"：

| 共享状态 | 出现途径 | 可衍生的联动原型 |
| --- | --- | --- |
| 易伤 | 13 途径 | "易伤"是全民 debuff → 任意控制职业都能给输出职业铺伤害 |
| 护盾 | 11 途径 | 守护/辅助职业给全队挂盾，攻击职业吃盾加成 |
| 枷锁 | 7 途径 | 控场职业定身，爆发职业收头 |
| 提线木偶 | corpse\_collector / fool / prisoner / sleepless | **"傀儡/操控"跨职业原型**（永暗之河+源堡系的天然组合） |
| 寄生 | thief / supplicant | **"寄生"跨职业原型**（偷盗者+秘祈人，原著相邻） |
| 诡秘(conceal) | sleepless / warrior | 潜行+战士的"暗影突袭"组合 |
| 厄运 | monster / sleepless | 命运+黑夜的"厄运降临"组合 |
| 灵之主宰 / 天然灵视 | corpse\_collector / sleepless | 永暗之河系内部（不眠者+收尸人，原著同属永暗之河）强联动 |
| 混乱 | lawyer / monster | 失序之国+光之钥的"混乱"主题 |

> 注意这些状态组合与原著**源质相邻关系高度吻合**：源堡系（fool/apprentice/thief/supplicant）、永暗之河系（sleepless/corpse\_collector）、失序之国系（arbiter/lawyer）、灾祸之城系（hunter/assassin）……**联动设计可以直接照搬原著的"相邻途径"设定**，既合理又有 IP 背书。

## 四、可落地的改造方案

### A. 让"职业内构筑"显形（针对 13 条平铺途径 + 薄轴）

1. 每条轴强制 enabler→payoff 结构：每个轴至少配 1–2 张"充能卡"（挂载该轴层数/资源）和 1–2 张"结算卡"（消耗层数放大）。把现有隐藏堆叠状态显式命名为轴身份（如把 apothecary 的"月相"做成 `月相层数`，让满月/月光化/血月都围绕它转）。

1. 薄轴（≤4 张）二选一：要么补到 6–8 张，要么并入相邻轴。例：`apothecary` 兽群(4) 太薄，可扩成"召唤物"主题或并入月相；`lawyer` 讼辩(4)/蛮力(4) 合并为"讼辩即战力"。

1. 旗舰卡承担轴心职责：每张旗舰应"收束本轴"——消费本轴累积资源 + 给后续卡铺平台。例：apothecary 旗舰应从"更大治疗"改为"若本场已施放≥3张🜄药剂，则治疗×2 并给全队挂再生"。

1. 补 13 条平铺途径的引擎：apothecary / arbiter / assassin / chanter / corpse\_collector / fool / hunter / lawyer / planter / savant / spectator / supplicant / thief 目前无自堆叠引擎，需各自设计 1 个核心层数（如 chanter 做"信仰层数"、assassin 做"镜中层数"、fool 做"诡秘层数"）。

### B. 把"跨职业联动"从复刻变成配合

1. 把一部分 181 张复刻卡改成" combo 卡"：不再让 `药剂调配` 原样出现在两边，而是让 apothecary 的一张卡写"友军(planter)施放治疗时为自身回能"——把复用转化为配合。

1. 沿原著"相邻途径"建联动关键词：定义 9 个源质组的共享关键词（如源堡系 `灵体之线`、永暗之河系 `灵体`、失序之国系 `规则`），让组内途径互相读取对方招牌状态。例：
  - `thief` 寄生 + `supplicant` 牧魂 → "被寄生且被放牧的单位，你额外获得其攻击力"
  - `sleepless` 灵之统帅 + `corpse_collector` 提线木偶 → 共享亡灵/灵体控制权

1. 类型钩子从 14 → 40+ 且做成双向：现有钩子都是"我打某类更狠"，补"友军制造了 X 类单位/状态，我因此增益"的搭档逻辑。例：`chanter` 加一张"友军召唤 undead/spirit 时，对其施加圣光护盾"。

1. 利用既有共享状态做"全民 combo"：以 `易伤`(13途径) 为枢纽，让控制职业的"挂易伤"卡显式标注"为友军输出职业提供 combo 标记"，把散落各池的易伤卡串成一条战术线。

### C. 表达层建议（让玩家"看见"构筑）

- 在技能卡面增加轴内提示："本卡属于 🜄药剂轴 · 与同轴上张卡联动"。

- 在构筑/编组界面显示轴完成度："你已选 5 张 🌙月相 卡，解锁月相层数机制"——把隐藏引擎外显成进度条。

- 跨职业卡标注联动对象："联动：友方 thief 的寄生"——把复用卡升级成可见 combo。
