## 10. 共享内核

### 10.1 TargetSpec

TargetSpec {
    request       : TargetRequest   // 查询：阵营 / 路线 / 锚点 / 范围 / 排序 / 数量 / 扩散
    mode          : Unit | Area     // 点目标 / 区域目标
    consumption   : Instant | Zone | Summon
    selectionMode : Auto | Manual   // 【v1.1 新增】自动选目标 / 玩家手动选目标
    fallbackSort  : SortRule        // 【v1.1 新增】Manual 时必填的确定性兜底
}

- mode == Unit 时 consumption 强制为 Instant；mode == Area 时 consumption 必填（无默认值）。
- selectionMode == Manual 时 fallbackSort 必填（INV-E6）。
- 四个维度正交可组合——这是技能表达力的主要来源。
|||
|---|---|---|
|Auto|系统按 sort 规则定目标，玩家不介入|绝大多数普攻与单体技能（打最前排、打最低血）|
|Manual|系统圈出候选池，玩家从中选|需要玩家决策的技能（打谁由我定，而非规则定）|


### 10.2 EffectRef

EffectRef { ref, params?, condition, target? }

- ref 指向 EffectDef.id；params 覆写默认参数；condition 决定对谁生效；target 覆盖行为级目标（状态触发常用）。
### 10.3 EffectCondition（规约）

组合式谓词，判定上下文是单个最终目标：

Always | Chance(via RandomSource) | TargetHpBelow | TargetHpAbove
| CasterHasStatus | TargetHasStatus | Not(of) | And(of[]) | Or(of[])

B1 约束：Chance 是唯一允许引入随机的条件，且必须满足 §11 的治理规则。

### 10.4 RandomSource

RandomSource {
    seed        // 战斗创建时确定，写入战斗记录
    next()      // 唯一抽样入口
    snapshot()  // 供回放/验证读取
}

## 11. 随机性治理（B1 落地）

|||
|---|---|
|R1|默认零随机：伤害链、治疗、资源增减、目标选择，默认路径上不存在任何抽样|
|R2|概率必须走 RandomSource：显式、可注入、可播种；种子在战斗创建时确定并写入战斗记录|
|R3|登记制：引入概率的效果必须被显式标记，可被平衡审计工具筛出单列，逐个评审|
|R4|单次抽样：随机源只在生效条件判定处被读取一次，禁止在结算链内部二次抽样|
|R5|建议边界：概率用于非伤害维度（是否挂载附加状态、触发哪条附加效果）；伤害/治疗数值保持确定；目标选择不引入随机|
|R6|可复现契约：战斗结果 = f(初始状态, 输入序列, seed)。同三者相同，结果必须逐位相同|


R2 不是洁癖而是硬需求：你已有 20 万局 MC 验证与回放。散落的 Math.random() 会让回放不可复现、验证不可回归（今天 50:50 明天 49.8:50.2，你无法判断是改动还是噪声）。
R6 与 INV-C3（Catalog 快照）合起来，才构成完整的确定性闭环。

## 13. 核心流程序列

[tick 推进]
BattleClock.tick()
  → Gauge.advance() ×N  → GaugeCrossed
  → InitiativePolicy.resolveOrder() → 确定性序列
  → grant(ActionOpportunity)

[主动行为]
持有机会的单位
  → OpportunityFilter.availableBehaviors()
  → 玩家/AI 选定
  → commit(): 资格校验 + 成本扣减 + 消耗机会      ← A2 的两条独立校验
  → Action 创建（快照：caster / targetSpec / effects（**已展开的扁平 EffectRef 序列**，INV-T1）/ opportunityId）

[流水线]
I-1 候选池          → CandidatePool（带 stateVersion）
                      Manual 且候选数 > pickCount → 等待玩家选择（否则不打断）
I-2 收缩            → committedTargets（Auto 按 sort；Manual 按输入或 fallbackSort）
R  转向 + 结算计划  → finalTargets / settlementPlan / redirectLog
                      守卫姿态在此拦截：按 protectedSelector + sourceFilter 命中 → 转给自己
M  消费分流         → instant | zone | summon
O  逐目标条件过滤   → 执行 effect
       ├ damage → 读本次 element → DamageChain（含**抗性阶段** · 纯函数）→ 应用结果
       │           └ originTerm 随 DamageResult 透出，供战报 / UI / 流派统计（不参与结算）
       ├ 近战对撞 → 额外产出 MeleeClash Action（EventTrigger，不耗机会）→ 与主伤害同步应用
       ├ mount_status → StatusDef + StatusGrant → StatusInstance → 溯源记账
       ├ modify_stat  → StatProvenance.apply(sourceId)
       ├ move / spawn → Placement（唯一出口）→ 坍缩 → OccupancyChanged
       └ zone         → 注册 Zone

[后续]
OccupancyChanged → Zone 进入检测 → 触发区域效果
UnitDied         → 亡语 → Placement.remove → 坍缩 → revertAll
StatusExpired    → revertBySource
