## 0. 结论摘要（先给数值）

| 层 | 代号 | 承载 | 动画 | 周期 / easing | 层不透明度 |
|---|---|---|---|---|---|
| 廿二刻度环 | **R2** | 内联 SVG + CSS transform | 旋转 + 明灭 | 反转 **420s linear** ／明灭 **67s** `cubic-bezier(.37,0,.63,1)` | **0.11** |
| 七光符文环 | **R1** | 内联 SVG + CSS transform | 旋转 + 明灭 | 正转 **300s linear** ／明灭 **49s** `cubic-bezier(.37,0,.63,1)` | **0.12** |
| 九芒内阵 | **S0** | 内联 SVG（**无动画**） | — | 无 | **0.06** |

- **只有 2 个运动 group**（R1、R2），符合 BG-02 §3.3「最多 2 个运动 group、≤2 个持续合成层」。S0 静态，不占合成层。
- 内容区内有效叠加 alpha **硬上限 0.12**，典型 0.06–0.12。实测预测：`--text-dim` 最坏 realistic **4.59:1**，仍过 AA（真实渲染实测 ≥6:1，见 §7.1）。
- **2026-10-13 数值上调**：原定 R1 0.045 / R2 0.040 / S0 0.028（有效 alpha ≈0.03）在 1px 细线上低于人眼可感知阈值，首页实测「啥都看不出」。细线的 alpha 不等于区域的 wash——一层 0.03 的平铺能看见染色，一条 0.03 的 1px 线看不见。故整层约 2.7× 上调；各档派生值（明灭区间、reduce 静态、af-low）由 CSS `calc(var(--af-op-*))` 自动跟随。
- 全部图形为内联 SVG / CSS，**零新增位图资产**。
- 现有 `.cg-bg`、`.cg-bg--fog::after`、`.cg-nav` 三者规则**一行不改**。

## 1. 概念锚点

### 1.1 意象依据（全部取自 `docs/诡秘之主资料库/` 与 `assets/frames/TAROT_SYMBOLS.md`，无外来设定）

| 锚点 | 出处 | 落到本设计 |
|---|---|---|
| **灵界「完全重叠、互不干涉」** | `诡秘之主-世界体系素材库.md:43` ——「灵界和现实世界完全、全部重叠，却又互不干涉……这是最好的游戏设定：没有『入口』，只有『穿透』」 | **本背景的存在方式本身就是这条设定的复刻**：一个与现实层完全重叠、看得见却碰不到、绝不干涉的层。技术上的 `pointer-events:none` + 极低不透明度，是把设定翻成 CSS，不是偷懒。这是选择「灵修满屏慢转」而非「局部贴片动效」的根本理由。 |
| **灵界七光** | 同表第 2 层 ——「七道净光（俗称灵界七光，活着的高位存在，位格仅在神灵之下，成立净光兄弟会教导人类知识）」 | R1 上 **7 枚符文**。数量不是为美学凑的：它是灵界的主位序列。光是「活着」的，所以它们**明灭**而不只是旋转。 |

| **九大源质** | `docs/诡秘之主资料库/九大源质总览.md` | S0 的 **九芒星**。原质是世界最底层的水泥，所以它画在最内、最暗、最不动的地方。 |

### 1.2 符文选字：为什么是这 7 枚

`ui-kit.svg` 现有 `cg-sigil-*` 精灵恰好 **7 枚**：愚者 / 隐者 / 命运之轮 / 塔 / 星星 / 月亮 / 太阳。

选它们的理由，按重要性排序：

1. **它们已经存在** —— `<use href="#cg-sigil-…">` 直接引用，新增 bit 为 0，硬约束 1 零成本达标。
2. **它们覆盖了全套牌序的两端与中段**（0 / IX / X / XVI–XIX），不是随便抓的截图大多省略的碎片。
3. **数量刚好对上七光**。但要事先说清一处免责：这 7 枚是「途径徽记」，**不是**七光的本体，只是在**数量**上与七光共振—— 这是借用口彩，不是设定宣告。规格里必须说清楚，避免以后有人把它当考证依据。

> 扩展路径（非本轮）：补满 22 枚进 `ui-kit.svg` 后，R1 可升级为完整途径环。**仍是矢量，不违反硬约束 1**。

### 1.3 为什么它适合「首页主菜单」这个门面位置

1. **首页是全站唯一不需要信息密度的地方**——它只有标题 + 6 个按钮。屏幕剩下的时间是空着的，屏幕剩下的空间是全站唯一的留白，也是世界观唯一能说话的地方。（BG-02 §2.1 第 1 条同向，且 BG-02 已判定为**首页专属**。）
2. **它是「入站」而非「出站」的符号**：用户还没进游戏，此时给的是「这是什么世界的暗示」，不是「当前状态」。符文环是静止的世界观徽记，不含进度、不含数值、不含指向某人/某事的具体信息——**语义上不可能误导**。
3. **它给标题做了框而不做背景板**：同心圆 + 中央留白天然是「文字处于阵眼」，而 `#menu-title` 用 `--accent` 黄铜、`#menu-sigil` 用 `cg-sigil-star`—— 阵中心空出来，正好供它们呼应。
4. **它可持续存在而不疲劳**：所有元素的视觉换气节奏都在 **49s 以上**。一个用户看首页的平均时间是 3–8 秒，他看到的是一个「已经存在很久、还会存在很久」的东西，而不是「正在给我表演」的东西。这是「克制」在语义层的定义。

## 2. 分层结构

### 2.1 与现有分层的插入位置

```
┌─ html                                      canvas 背景 = var(--bg) #1d2026
└─ body.cg-kit.cg-bg.cg-bg--fog  ← 必须加 isolation: isolate（见 §2.2）
   ├─ body 自身 background-image（现有，不改）
   │     径向亮晕 · 径向暗角 · 160px 八芒环 tile(soft-light)
   │
   ├─ ★ .cg-arcane-field  z-index:-1   ← 【本规格新增】3 个子组
   │    ├─ S0 九芒内阵      静态，r=236u
   │    ├─ R1 七光符文环    正转 300s，r=300/356/412u
   │    └─ R2 廿二刻度环    反转 420s，r=458/470u
   │
   ├─ main.menu / nav.cg-nav / #app 内容     z-index:auto（正常流）
   └─ body::after 暗雾(screen)  z-index:auto  ← 现有，不改，仍在内容之上
```

**顺序即 BG-02 §4.1 的目标关系 1→2→3→4，逐条对应：**
- 现有底图在最底 ✓；新层在其之上 ✓；内容在新层之上 ✓；暗雾仍按现有规则叠在内容之上 ✓（观感零变化）；`.cg-nav` 的 `z-index:40` 与毛玻璃采样照旧 ✓。

### 2.2 一个必须写进实现的坑（高优先级）

BG-02 §4.2 的 `isolation` 决策是**必需的，不是可选的**。原因：

- 现状 `body` 只有 `position:relative; z-index:auto` → **不构成 stacking context**。
- 此时 `z-index:-1` 的子元素会逃逸到 html 的根堆叠上下文，落在**步骤 2**（负 z-index），而 `body` 自身背景在**步骤 3**绘制 → **新层会被 `.cg-bg` 的背景图整个盖住，现场表现为「写了没效果」**。
- 一旦 `body { isolation: isolate }`，body 自己成为 stacking context，body 背景降为该上下文的步骤 1，负 z-index 子层成为步骤 2 → **正确落在背景之上、内容之下**。

> 给 BG-02 的实现注记：验收时**第一件事**是确认 `getComputedStyle(document.body).isolation === 'isolate'`。这一步漏掉，后面所有视觉调试都是白调。
>
> 副作用核查（已确认无）：`isolation` 只让 `z-index:-1` 留在 body 上下文内；`#app` 内部 `z-index:2/3/4/40/50/54/55/60/62/80` 之间的相对次序不变，`body::after` 与它们的相对次序也不变 → **不改任何现有观感**，且避免了 BG-02 §4.2 明确担心的「把 nav/模态关进新盒子」。

## 3. 每层参数

> 单位说明：`u` = SVG `viewBox="0 0 1000 1000"` 内的用户单位，圆心 (500,500)。
> CSS 尺寸 `--af-size: min(104vmin, 92vw, 1000px)`，正方形。换算：`px = u × size ÷ 1000`。
>
> **`vector-effect: non-scaling-stroke` 是硬要求**：手机上 `--af-size` 只有 ~359px，1u 线宽会掉到 0.36px 变成脏锯齿。锁定后线宽恒等于设备 px，跨断点观感一致。

### 3.1 公共 token

```css
.cg-arcane-field{
  --af-size:  min(104vmin, 92vw, 1000px);
  --af-op-r1: 0.12;    /* 七光符文环 */
  --af-op-r2: 0.11;    /* 廿二刻度环 */

}
```

### 3.5 「明灭」的实现：与 BG-02 性能预算的调和 ★

BG-02 §3.3 明确约束：**「不在每个 rune 上创建独立 DOM/合成层」「不采用逐符文 DOM 动画」**。
而需求方要求「缓慢旋转/**明灭**」。表面冲突。解法：

**把亮度梯度烘进几何，让「波」由旋转自己带出来。**

- 给 7 枚符文烘上**静态**、不对称的 `stroke-opacity` 梯度（0.92 / 0.64 / 0.44 / 0.36 / 0.36 / 0.44 / 0.64，见表 §3.3）。
- R1 整体旋转 → 这条亮度分布跟着转 → 形成「一道光缓慢绕环游走」的观感，**完全等价于逐符文动画的视觉效果**。
- 成本：**0 个额外 DOM、0 个额外合成层、0 次 repaint**。
- 再叠一层 R1 整体 49s 呼吸（opacity 0.72↔1.00），让峰谷本身也在缓慢涨落。

于是：**2 个运动 group（R1/R2）交付了「旋转 + 明灭」两种质感**，双方约束同时成立。

> 这个梯度必须刻意不对称（以 i=0 为峰、向两翼衰减），而不是随机噪声——否则旋转起来只是明暗杂点，读不出「一道光在走」。
> 若未来补满 22 枚，同一手法继续适用（烘 22 个梯度值）。

### 3.6 双色调：为什么 S0 用 `--text-dim` 而不是黄铜

BG-02 §4.2 写的是「色彩从 `--accent`/`--accent-dim` 派生」。本规格扩展一枚 **`--text-dim`**，供审批：

- 品牌调性是「**黄铜 + 暗雾**」，从来不是单一色。`--text-dim` `#9aa1ad` 是 token 内**唯一的冷调**，用它当最内层，等于在纪律内合法借用出「雾」的冷调层。
- 现有 `.cg-bg--fog::after` 的蓝紫两团用的是**非 token** 硬编码色（`rgba(120,140,180)` / `rgba(150,120,180)`）—— 那是历史遗留。S0 用 `--text-dim` 可在**不引入新色号**的前提下达到同一冷调，是纪律内的正解。
- 空间上：**外暖内冷** → 黄铜在外围做框、冷灰在阵眼做空，视线自然被推向外围轨道而非中央文字区。

> **待审批项 A**：是否接受 S0 用 `--text-dim`（推荐）。否决则退 --accent-dim 0.06，观感略平。

### 3.7 混合模式：建议退到 `normal`

BG-02 §4.2 首选 root 层 `mix-blend-mode: screen`。本规格建议**默认 `normal`**，理由是可算的：

在本底图亮度（`--bg` #1d2026，线性亮度 L≈0.014）下，对我们这类≤0.05 的低 alpha 源，`screen` 与 `normal` 的差值 < **1/255**（手工验算两者分别给出 ≈0.1475 与 ≈0.1473）。**视觉无差别，但 `normal` 消除全部 blend 相关的 paint 风险**，连 BG-02 §3.3「若 paint flashing 持续闪烁则退 normal」这条降级分支都不需要了。

> **待审批项 B**：`normal`（推荐，更快更可预测） vs `screen`（BG-02 初始建议，此处不可测差异）。
> 若选 `screen`，注意本项目**已有** `.cg-bg--fog::after` 在跑 screen，两块 screen 层串联时 alpha 需按实测回调。

## 4. 动效编排

### 4.1 相位关系

| 层 | 旋转方向 | 周期 | 角速度 | 明灭周期 |
|---|---|---|---|---|
| R1 七光符文环 | **正转 CW** | 300s | +1.200 °/s | 49s |
| R2 廿二刻度环 | **反转 CCW** | 420s | −0.857 °/s | 67s |
| S0 九芒内阵 | — | ∞ | 0 | — |

**为什么用 `linear`（= `cubic-bezier(0,0,1,1)`）而不是带缓动的曲线：**
旋转是 360° 闭环。任何 ease-in-out 都会让每圈出现「加速—减速」的呼吸感，在慢速（每周 5 分钟）下会读成「卡顿/喘息」。**闭环 tiling 动画必须用线性**，这不是偷懒美学，是数学要求。用户要求的「cubic-bezier」体现在**明灭**上（4.2）。

**为什么 R1/R2 反向：** 同心环同向旋转会读成「一个刚体在转」，两层只是一个周期差——那是机件感，不是"各自运行的两个天体"。反向让 22 刻度与 7 符文**持续错位**，任何一个瞬间都独一无二。

**去同步验证（周期性/lockstep 分析）：**

- 旋转周期 300s / 420s：任两特征的最小公周期 175s（≈2 min 55 s）。但两层各自有 7 / 22 个均匀特征，**任意两特征重逢**频繁发生，不存在「全体同时对齐」的可感知时刻（对齐需要 7 与 22 的最小公倍数条件，即整环 46 单位周期，实际每 175s 出现一次部分对齐，肉眼不可辨）。
- 明灭 49s / 67s：lcm = **3283s ≈ 54分 43秒**，且 49、67 均不整除 300/420 → 与旋转无共振。
- 结论：无任何一组周期成简单整数比，**不存在可感知的循环感**。

### 4.2 明灭 easing

```
cubic-bezier(0.37, 0, 0.63, 1)
```

即 sine-ease-in-out 的标准近似（亦称 `ease-in-out-sine`）。选它的理由：

- **速度在两端连续地归于 0**（不像 `ease-in-out` 那样在端点有残余加速度），
- 周期性往复时**没有可听见的「顿」**，
- 与 sine 的最大偏差 < 0.5%，肉眼不可辨。

对 0.72↔1.00 这样的窄幅（Δα 仅 0.0126），它是**唯一不会在端点产生可见台阶**的选择。

### 4.3 时间轴草图（第一个揭示周期）

```
t=0s     三层静止，视觉上如同一帧（不可辨）
t=49s    R1 完成第一次完整呼吸（峰→峰）
t=67s    R2 完成第一次完整呼吸
t=175s   R1 与 R2 特征首次部分重合（不可辨）
t=300s   R1 转完 1 整圈（+360°）
t=420s   R2 转完 1 整圈（−360°）
```

**「进去三个呼吸、没能看过一圈」** 是这套东西的设计目标：用户 5–8 秒的停留期内，实际看到的只有极其缓慢的漂移 + 亮度的一次不完整涨落。

## 5. 减动效降级（`prefers-reduced-motion: reduce`）

### 5.1 最终静态形态

保留**三层全部几何**，取消全部 animation 与 transition：

- R1 / R2 冻结在 **几何烘入的初始相位**（各環均以 θ₀=−90° 为起点，即「愚者 / 顶点朝正上方」），轮辐对称地站在中轴上——与 `#menu-title` 的居中排版天然对齐，视觉稳定。
- S0 本就静态，不变。
- 每层不透明度取**动效区间的中值**，保证亮度既不比动态峰值亮、也不比动态谷值暗：

| 层 | 动效区间 | reduce 静态值 |
|---|---|---|
| R1 | 0.0864 – 0.1200 | **0.1032** |
| R2 | 0.0880 – 0.1100 | **0.0990** |
| S0 | 0.06（静态） | **0.06** |

- 符文那道「游走光」不再游走，但梯度仍在（`stroke-opacity` 是静态属性）→ **保留「某一侧稍亮」的明暗暗示**，不至于退化成完全均匀的环。

### 5.2 具体 CSS（参考实现，交 BG-02）

```css
/* 默认档 —— 动效 */
.af-array--runes{
  animation: af-spin-cw 300s linear infinite,
             af-breathe-r1 49s var(--af-breath) infinite;
  transform-origin: 50% 50%;
}
.af-array--ticks{
  animation: af-spin-ccw 420s linear infinite,
             af-breathe-r2 67s var(--af-breath) infinite;
  transform-origin: 50% 50%;
}

@keyframes af-spin-cw  { from{ transform: rotate(0deg);} to{ transform: rotate(360deg);} }
@keyframes af-spin-ccw { from{ transform: rotate(0deg);} to{ transform: rotate(-360deg);} }
@keyframes af-breathe-r1 { 0%,100%{ opacity: calc(var(--af-op-r1) * 0.72);} 50%{ opacity: var(--af-op-r1);} }
@keyframes af-breathe-r2 { 0%,100%{ opacity: calc(var(--af-op-r2) * 0.80);} 50%{ opacity: var(--af-op-r2);} }

/* reduce 档 —— 静态 */
@media (prefers-reduced-motion: reduce){
  .af-array--runes,
  .af-array--ticks{ animation: none; }
  .af-array--runes{ opacity: calc(var(--af-op-r1) * 0.86); }  /* = 0.1032 */
  .af-array--ticks{ opacity: calc(var(--af-op-r2) * 0.90); }  /* = 0.0990 */
}

/* 与 BG-02 §3.1 的 paused 单并列，互不冲突 */
```

> 注：BG-02 §3.1 已规划 `animation-play-state: paused`（`document.hidden`）。**reduce 用 `animation: none` 而非 paused**——paused 会冻在任意中间相位（可能是歪的），`none` 才确保回到 θ₀=−90° 的正位。两者是不同场景，不要合并。

|---|---|---|---|---|---|

| **L0 静态** | BG-02 判 low / reduce | 隐藏 | 静态 §5 | 静态 §5 | §5.1 中值 |

断点逻辑：

- **为什么第一个砍 S0**：`--af-size` 在 1440×900 下算出 936px → S0 半径 **221px**，而菜单内容列半宽是 **254px**（`.menu` max-width 460 ÷ 2 + 24 padding）。**整个九芒星完全落在文字列之内**，是三层里唯一 100% 压字的，性价比最低，先砍。
  （1440×900 时 R1 符文 r=333px、R2 r=440px，均在 y=0 处位于内容列之外 ✓，只有弧段会掠过。）
- **为什么手机保留 R1**：它是唯一有叙事内容的层（7 枚符文），砍掉就只剩一圈刻度，毫无辨识度。宁可把它压到 ×0.65 并关掉明灭（少一层 opacity 动画）。
- **为什么手机关 R1 明灭而不是砍掉 R1**：把 opacity 动画对象从 2 个减到 1 个，边际收益有限，却能保留 R1 的符文叙事；反过来若把 2 个全关，「呼吸感」就彻底没了。故选出版社：留 R2 明灭作为唯一的动态节奏。

## 8. 验收标准（客观判据）

「克制且不抢内容」必须可证伪。以下每条给出**可执行的测法与阈值**。

1. **对比度判据** —— 在菜单内容列（宽 460px 居中）内取**动态层最亮像素**，反推有效 alpha ≤ **0.12**；`#9aa1ad` 在那里实测对比度 **≥ 4.5:1**（预测 4.59–5.15）。
   测法：关闭动效（reduce 档）→ 截图 → 与本层 `display:none` 的截图逐像素反算 alpha。

2. **频闪判据** —— 内容列内任一固定像素，5 秒窗口内的 sRGB 通道漂移 **≤ 3/255**；变化重复频率 **≤ 0.05 Hz**（远低于 WCAG 2.3.1 的 3 Hz）。
   测法：同一坐标连续采样 60s，做差分。

3. **注意力判据（「不抢」的可量化定义）** —— 首页静态截图做**视觉显著性**抽查：标题区与按钮柱区域内的最高局部对比梯度必须落在**文字/按钮自身**上，不得落在背景线稿上。
   简易替代测法：只渲染背景层的截图，用任何显著图工具，确保内容列内的显著峰面积占比 **< 3%**。

4. **互动判据** —— 自动化断言 6 个按钮中心 `elementFromPoint()` 返回 `.cg-btn--block` 或其后代；根层 `pointer-events:none`、 `aria-hidden=true`；Tab 序不含新节点。

5. **性能判据** —— 沿用 BG-02 §3.4 全表；附加两条本规格专属：
   - 稳态 30s Performance 录制中，** Layout 记录数 = 0，Paint 记录仅出现在首帧**；
   - DevTools Layers 面板新增持续合成层 **≤ 2**（= R1 + R2）。

6. **减动效判据** —— DevTools 强制 reduce 后，相隔 3s 的两张首页截图 **PNG diff = 0**；且 `#/settings`、`#/cards` 等非首页路由下本层 `display:none`。

7. **共存判据** —— 仅切换本层的 CSS 开关（`display:none` ↔ 开），`#/settings` 页与首页无内容区域的像素应完全一致；不得出现暗角变浅、暗雾被冲淡、八芒 tile 消失。

8. **资产判据** —— 本次改动后 `git status --porcelain assets/` 输出为空；新建/修改文件仅限 BG-02 §5.1 列出的清单。
